# 자동화 공장 (프로토타입)

탑다운 2D 그리드 생산 체인 자동화 게임. 지금 게임은 [docs/기획서-버전2.md](docs/기획서-버전2.md), 앞으로 할 일은 [docs/계획서.md](docs/계획서.md), 만든 기록은 [docs/기획.md](docs/기획.md), 버전별 바뀐 점은 [docs/바뀐점.md](docs/바뀐점.md), 시장 조사는 [docs/리서치.md](docs/리서치.md).

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run host       # dev와 같음 (같은 공유기의 다른 PC에서도 들어올 수 있게 늘 열려 있다)
npm test           # 시뮬레이션 테스트
npm run build      # 타입 검사 + 배포용 빌드 (dist/)
npm run app        # 빌드한 다음 exe와 같은 창으로 바로 켜 보기 (설치 파일은 안 만든다)
npm run exe        # PC용 설치 파일 만들기 → release/AutomationFactory-Setup-<버전>.exe
npm run release    # 설치 파일을 만들어 깃허브 릴리스에 올리기 (아래 "새 버전 올리기")
```

## PC용 프로그램 (설치 파일 + 게임 안 업데이트)

Electron으로 게임 화면을 창에 담고, 같이 하기 서버와 방 찾기를 프로그램 안에 넣었다. 친구는 **처음 한 번만 설치**하고, 그다음부터는 게임 안 **[업데이트]** 버튼으로 새 버전을 받는다.

- 결과: **`release/AutomationFactory-Setup-0.1.0.exe`** (약 96MB). 같은 폴더의 다른 파일(`win-unpacked/`, `latest.yml`, `.blockmap`)은 릴리스용이라 친구에게 보낼 필요 없다.
- 파일 이름이 영어인 이유: 깃허브가 한글 파일 이름을 바꿔 버려서 자동 업데이트가 파일을 못 찾는다. 설치하면 바탕화면·시작 메뉴 바로가기 이름은 "자동화 공장".
- 설치: 더블클릭하면 묻지 않고 설치하고(약 20~40초) 게임을 켠다. 관리자 권한은 필요 없다. 설치 위치 `%LOCALAPPDATA%\Programs\automation-game`.
- 저장: `%APPDATA%\자동화 공장` 에 남는다 (업데이트하거나 지웠다 다시 깔아도 그대로). 브라우저 버전의 저장과는 따로다.
- 지우기: Windows 설정 → 앱 → 설치된 앱 → "자동화 공장" → 제거 (저장은 남는다).
- 처음 켤 때 **Windows 방화벽 창이 뜨면 "개인"과 "공용" 둘 다 체크하고 "액세스 허용"**. 와이파이가 "공용 네트워크"로 잡힌 PC가 많아서, "공용"을 안 켜면 다른 PC가 내 방에 못 들어온다. 설치 위치가 늘 같아서 업데이트해도 다시 묻지 않는다.
- 서명 안 된 프로그램이라 설치 파일을 처음 열 때 **"Windows의 PC 보호" 파란 창**이 뜰 수 있다 → **"추가 정보" → "실행"**.
- 창 제목에 버전이 보인다 ("자동화 공장 0.1.0"). 방 창 맨 아래에도 "게임 버전 0.1.0".
- 키: F5 새로고침, F12 개발자 도구 (메뉴 막대는 없앰).
- 같은 PC에서 두 번 켜면 두 번째 창은 제목 끝에 "(2)"가 붙고 저장도 따로다 (같이 하기 시험용).
- 빌드 설정은 `package.json`의 `build` (설치 방식 `nsis`, 업데이트 주소 `publish`), 아이콘은 `build/icon.ico`(창 아이콘은 `electron/icon.ico`).

### 게임 안 업데이트

- 게임을 켤 때 깃허브 릴리스에 새 버전이 있으면 **오른쪽 위에 "새 버전이 있어요 (0.1.0 → 0.1.1) [업데이트] [나중에]"** 가 뜬다.
- [업데이트]를 누르면 받은 다음 저절로 설치하고 다시 켠다 (게임은 닫힐 때 저장된다). 같이 하는 중이면 한 번 묻는다.
- 설치 파일 전체가 아니라 **바뀐 조각만** 받는다 (시험: 93MB 중 1.8MB). 그래서 **옛 릴리스는 지우지 않는다** (옛 버전의 `.blockmap`이 있어야 조각을 비교한다).
- 인터넷이 없거나 깃허브에 닿지 못하면 알림 없이 그냥 켜진다. 기록: `%APPDATA%\자동화 공장\update.log`.
- 브라우저 버전(`npm run dev`)에는 업데이트 알림이 없다.

### 처음 한 번: 깃허브 준비 (직접 해야 하는 것)

1. **저장소 만들기**: github.com 로그인 → 오른쪽 위 **+** → **New repository** → Repository name에 `automation-factory` → **Public** 선택 → **Create repository**.
   - 공개(Public)여야 친구 게임이 로그인 없이 업데이트를 받는다. 코드는 안 올려도 된다 (릴리스에 설치 파일만 올라간다).
   - 다른 계정·이름을 쓰면 `package.json` → `build` → `publish`의 `owner`(깃허브 아이디)와 `repo`(저장소 이름)를 바꾼다. 지금은 `ilyoon98` / `automation-factory`.
2. **토큰 만들기** (내 PC가 릴리스에 파일을 올릴 수 있게 하는 비밀번호 같은 것):
   github.com 오른쪽 위 프로필 사진 → **Settings** → 왼쪽 맨 아래 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
   - Token name: 아무거나 (예: `automation-factory release`), Expiration: 원하는 기간 (끝나면 새로 만든다)
   - Repository access: **Only select repositories** → `automation-factory`
   - Permissions → Repository permissions → **Contents** 를 **Read and write**
   - **Generate token** → 나온 `github_pat_…` 글자를 복사한다. 이 화면을 벗어나면 다시 볼 수 없고, **남에게 보여 주면 안 된다**.
3. **토큰을 이 PC에 넣기**: PowerShell에서 한 번만 실행하고, 터미널(또는 VS Code)을 껐다 켠다.
   ```powershell
   setx GH_TOKEN "github_pat_여기에_붙여넣기"
   ```

### 새 버전 올리기

1. 버전 올리기 (아래 중 하나):
   ```bash
   npm version patch --no-git-tag-version   # 작은 수정: 0.1.0 → 0.1.1
   npm version minor --no-git-tag-version   # 큰 변경: 0.1.x → 0.2.0
   ```
   또는 `package.json`의 `"version"`을 직접 고친다.
2. 바뀐 점 적기: `docs/바뀐점.md`에 `## 0.1.1` 절을 만들어 적는다. 올릴 때 그 절이 릴리스 설명에 들어간다 (없으면 설명 없이 올라간다).
3. 올리기:
   ```bash
   npm run release
   ```
   빌드한 다음 숨김 릴리스 `v0.1.1`을 만들어 설치 파일 → `.blockmap` → `latest.yml` 차례로 올리고, 다 올라가면 공개한다. 끝나면 `https://github.com/ilyoon98/automation-factory/releases` 에 보인다.
   - 올리기는 electron-builder가 아니라 `scripts/build-exe.mjs`가 직접 한다. electron-builder에게 맡겼더니 0.2.0 때 같은 태그로 릴리스가 둘 생겨 파일이 나뉘어 올라갔다.
   - 중간에 끊기면 `npm run release`를 다시 하면 된다. 올리다 만 숨김 릴리스나 방금(2시간 안) 공개한 릴리스를 찾아 파일을 새 빌드로 바꿔 올린다.
4. 친구들은 다음에 게임을 켤 때 업데이트 알림을 본다.

- **같은 버전 번호로 두 번 올리지 않는다.** 이미 그 버전을 받은 사람에게는 업데이트가 안 뜬다. 고쳤으면 버전을 올려서 다시 올린다.
- 버전이 다른 사람끼리는 같이 하기가 안 된다 (아래 "버전 확인"). 새 버전을 올리면 모두 업데이트하라고 알린다.
- 깃허브 없이 업데이트를 시험하려면: 버전마다 `npm run build && node scripts/build-exe.mjs --feed http://127.0.0.1:8765/` 로 빌드하고, 그 주소에서 `release/`의 `latest.yml`·설치 파일·`.blockmap`(옛 버전 것도)을 내려 주는 서버를 띄운다.

## 같이 하기 (LAN)

### exe로 (주소 복사 없이)

1. 같은 와이파이(공유기)에 붙은 PC들에서 "자동화 공장"을 켠다. 켜면 방 창이 먼저 뜬다: **같은 와이파이에서 열린 방 목록 · 방 만들기 · 혼자 하기**.
2. 한 사람이 **방 만들기**. 1~2초 안에 다른 PC들의 방 목록에 "○○의 방"이 저절로 뜬다 (위쪽 버튼에도 "🚪 ○○의 방 · 참가").
3. 다른 사람은 목록에서 **참가**. 방장 공장에 들어가 같이 짓는다.

- 방 알리기: 방이 열린 exe는 1초마다 같은 와이파이에 신호(UDP 47819번 포트, 브로드캐스트+멀티캐스트)를 보낸다. 게임 서버는 47820번 포트 (같은 PC에서 하나 더 켜면 47821, 47822…).
- **버전 확인**: 락스텝이라 방장과 손님의 게임 버전이 같아야 한다.
  - 방 목록에서 버전이 다른 방은 흐리게 "옛 버전" / "새 버전이라 업데이트 필요"로 뜨고 참가 버튼이 막힌다.
  - 서버도 참가할 때 한 번 더 비교한다. 다르면 "방장이 새 버전이에요 (방장 0.3, 나 0.2). 업데이트하고 들어오세요"처럼 알려 주고 내 공장으로 돌아온다 (브라우저 초대 주소로 들어와도 마찬가지).
  - 버전 번호가 같아도 따로 빌드한 파일이면 "파일이 달라요"로 막는다. 친구들과는 같은 릴리스를 쓴다.
- 참가가 안 되고 "방장 PC에 붙지 못했어요"가 뜨면 방장 PC의 방화벽에서 "자동화 공장"이 허용됐는지 본다.
- exe 방장의 방에 브라우저로도 들어올 수 있다: 방 창의 주소(`http://192.168.x.x:47820/?join`)를 보낸다.

### 브라우저로

1. 한 PC에서 `npm run dev`(또는 `npm run host`)를 실행하고 브라우저로 `http://localhost:5173` 을 연다. 서버는 늘 같은 공유기 안에 열려 있다.
2. 위쪽 **👥 같이 하기 → 방 만들기**. 지금 내 공장으로 방이 열리고 내가 방장이 된다.
3. **주소 복사**로 초대 주소(`http://192.168.x.x:5173/?join`)를 복사해 메신저로 보낸다. 같은 와이파이·랜선의 PC에서 열면 바로 참가한다.
4. 처음 실행할 때 Windows 방화벽 창이 뜨면 "개인 네트워크"를 허용한다.

### 규칙 (exe·브라우저 같음)

- 서버 하나에 방 하나. 주소만 열고 들어온 사람은 위쪽 **🚪 ○○의 방 · 참가**를 누르면 들어간다.
- 손님은 방장 공장에서 같이 짓고, **나가기**를 누르면 자기 공장(자기 저장)으로 돌아간다. 방장이 **방 닫기**를 해도 마찬가지.
- 방장이 새로고침하거나 잠깐 끊기면 방이 저절로 다시 열리고 손님도 저절로 다시 들어온다 (그동안 손님 화면은 멈춤).
- 공동 공장: 허브 재고와 연구를 모두 함께 쓴다. 되돌리기(Ctrl+Z)는 각자 자기가 한 것만.
- 다른 사람의 커서·이름표, 들고 있는 건물(점선 고스트), 드래그 중인 복사·철거 영역이 보인다. 지도에도 점으로.
- 핑: F 키 또는 Alt + 클릭. 화면 밖이면 가장자리에 화살표.
- 방 창에서 접속자 목록 (보기 = 그 사람 커서로 이동), 내 이름 바꾸기.
- 저장·새 게임·게임 속도는 방장 기준 (손님이 속도를 바꾸면 방장에게 부탁한다).
- 락스텝: 월드는 주고받지 않고 명령만 주고받는다. 호스트가 틱 번호를 찍어 모두에게 돌리고, 모두 같은 틱에 같은 순서로 적용한다. 2초마다 체크섬을 비교해 어긋나면 손님이 호스트 월드를 다시 받는다.
- **월드를 바꾸는 코드는 반드시 `sim/commands.ts`의 명령으로**. 입력·UI에서 `world.place()` 같은 걸 직접 부르면 그 PC에서만 바뀌어 어긋난다. 저장 파일에 없는 시뮬레이션 상태를 새로 만들면 `World.snapshot()`에도 넣는다 (`sim/lockstep.test.ts`가 확인).

## 구조

```
src/
  data/      아이템, 레시피, 건물, 연구 정의 (밸런스 숫자는 전부 여기)
  sim/       시뮬레이션 (DOM 없음, 테스트 가능)
    world.ts       맵, 건물 배치/철거, 틱(채굴·제작·전력·컨베이어), 저장, 같이 하기 스냅샷·체크섬
    commands.ts    플레이어가 월드를 바꾸는 명령 전부 (같이 하기에서 주고받는 단위)
    building.ts    건물 상태
    blueprint.ts   복사/붙여넣기
    mapgen.ts      맵 생성 (시드 고정)
  render/    Canvas 그리기, 카메라
  input/     마우스·키보드
  ui/        툴바, 허브 재고, 전력, 정보창, 연구, 목표 가이드
  net/       같이 하기 (락스텝 세션, exe에서 다른 PC 서버로 옮겨 붙기)
  main.ts    게임 루프 (초당 60틱 고정), 자동 저장
  version.ts 게임 버전 (package.json의 version) · 빌드 번호
server/
  relay.mjs  같이 하기 중계 서버 (개발 서버 vite.config.ts와 exe가 같이 쓴다). 참가할 때 버전 확인
electron/
  main.mjs     exe 본체: 창, 내장 서버(게임 파일 + 중계), 같은 와이파이 방 알리기·찾기, 업데이트
  preload.cjs  게임 화면에 방 목록·업데이트 소식을 넘겨 주는 다리 (window.desktop)
scripts/
  build-exe.mjs  설치 파일 만들기·깃허브에 올리기 (npm run exe / npm run release)
build/           exe 아이콘
```

## 시뮬레이션 규칙 요약

- **컨베이어**: 한 칸에 아이템 최대 4개 (간격 0.25칸), 기본 1.5칸/초 → 최대 초당 6개. 하류부터 갱신해서 줄 선 아이템 사이에 빈틈이 없다.
- **입출력**: 기계는 앞면(노란 화살표)으로만 내보내고 나머지 면에서 받는다. 분배기는 뒤가 입구, 앞·양옆이 출구. 출구가 컨베이어·허브·다른 기계에 닿으면 거기로 들어간다.
- **제작**: 재료가 다 있고 출력 칸이 남으면 시작 (재료는 시작할 때 소모). 남은 진행도를 이어받아 생산 속도가 정확하다.
- **전력**: 맵 전체가 한 전력망. 공급/수요 비율만큼 모든 기계가 느려진다. 허브 기본 400kW, 그다음 발전기가 나눠서 석탄을 태운다.
- **철거**: 건설 비용 + 안에 든 아이템 100% 허브로 환급.
