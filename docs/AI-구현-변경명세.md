# AI 구현 요청용 변경 명세

2026-10-27 · 기존 게임에서 추가·수정할 사항만 분리 · [전체 기획](기획-통합정리-검토.md)

**이 문서는 기존 게임을 유지하면서 지역 생산망 확장을 구현하기 위한 작업 명세다.** 기획 논의·폐기한 대안·이전 문서의 기능 후보를 구현 목록으로 사용하지 않는다. 현재 구현 기준점은 main `3301dcf`, 패키지 버전 0.4.2다. AI가 착수할 때 실제 현재 코드와 작업 중 변경을 다시 확인하고 이미 구현된 부분을 중복 작성하지 않는다. 기획 문서가 아직 미커밋 상태여도 삭제·초기화하지 않는다.

## 1. 전달할 범위

- **전체 확장 변경분**: 이 문서의 D01~D12와 연결된 최신 상세 문서를 사용한다. 현재 코드 대비 추가·수정 목록이며 실행 가능한 패치 파일은 아니다.
- **완제품 사용의 확정 사항**: [모듈 설치·분리와 고급 트럭 생성 계약](모듈-장착-트럭생성-상세기획.md)이다. 모듈 인접 창고 설치를 채택했고, 작업 중 효과·분리·실패·중복 명령·차량 현지 생성까지 구체화했다.
- **기록 업적 30종의 이번 보완**: [record-v1 항목·기준표](업적-기록30종-구현기준.md)의 REC01~30·120메달을 사용한다. 각 행의 저장 ID·4단계 값·계측·지원별 활성 목록이 있으며 이전 구현 복구를 기다리는 범위가 아니다. 과거 수치 복원으로 오인하지 않는다.
- **최신 UI 방향**: [운영 UI](지역-운영-UI-상세기획.md)의 정보 표시 원칙·§6.1 차량 조작·§9.1 연구 완료 카드다. 사람의 생산 계획을 자동 계산/추천하는 기능은 추가하지 않고 실제 상태 표시와 작은 차량 조작 개선·연구 축하 연출에 집중한다.
- **기존 기능의 연출 개선**: [공장·운송·완료 연출](공장-가동-운송-완료-연출-상세기획.md). 실제 작업 속도와 상태, 실제 화물 이동·차량별 용량에 맞춰 표현하고 기존 설치/철거/연구 효과를 재사용한다. 전선/공급 면의 표시·기존 날씨·허브 완료 카드·효과 줄이기를 포함한다. 전력 반경 축소 후보는 이번 적용 대상이 아니다.
- **운송 사용성 보완**: [운영 UI §6.2](지역-운영-UI-상세기획.md)의 도달 가능한 정류장 선택·단절된 기존 선택 보존·상태/화물/배터리 중심 요약·상세 설정/설명 접기를 적용한다. regional-d09에는 연출 개선 후 추가 구현했으며 [운송 검증 기록](../.claude/worktrees/regional-d09/docs/운송-선택-정보정리-구현-2026-10-30.md)을 확인한다. 현재 미커밋 구현을 보존하고 중복 작성하지 않는다.
- **첫 목표·운송의 후속 적용**: 사용자 결정으로 MG01은 철판 실제 반입도 인정한다. 각 정류장의 지도 보기와 출발지 보관 품목 우선 표시도 regional-d09에 추가 구현했다. [목표](목표-진행-상세기획.md)의 MG01과 [운영 UI §6.2](지역-운영-UI-상세기획.md)를 따르며 기존 완료 ID·전체 품목·작성 중 계획·실제 운송 규칙은 유지한다. 컴퓨터 유즈 없이 빌드/325개 단위 테스트와 시뮬레이션으로 검증했다.
- **정류장 배치와 입출고 표시 적용**: 실제 접도/정차 칸의 `P` 미리보기, 성공한 상하차/벨트 입출고의 아이콘 이동과 표지 표시를 regional-d09에 추가했다. 4배속에서도 읽히도록 완료 잔상은 실제 시간 0.55초로 유지한다. [구현 기록](../.claude/worktrees/regional-d09/docs/정류장-배치-입출고-연출-구현-2026-10-30.md)에 테스트 335개와 코드 자동 진행 결과를 적었으며 실제 화면 재생 검증으로 보고하지 않는다. 현재 구현을 보존하고 중복 작성하지 않는다.
- 전체 기획을 설명하는 [버전 4](기획서-버전4.md)와 [통합 정리](기획-통합정리-검토.md)는 맥락 확인용이다. 수량·예외 처리는 아래 담당 상세 문서를 우선한다.
- 상세 문서는 같은 저장소에 있다. 이 파일만 저장소 밖으로 복사할 경우 상대 링크의 문서도 함께 전달한다. 수치 표를 이 문서에 중복 복사해 다른 가격표를 만들지 않는다.

전력의 이번 변경은 [연결·독립 시작 개정](전력망-연결-독립시작-개정.md)을 우선한다. 신규 설비는 11종(생산 6+전력 5), 경제의 터미널 비용/수량 삭제·전봇대 74대·원료 재검산을 함께 적용한다. F30/D07/D08/D09/D12/H09·CG03의 판정은 거점과 전력망을 분리한 최신 업적/목표 문서를 따른다. 이전 전력 업적이 실제 출시된 저장은 달성을 보존하고 조건 버전을 분리한다.

지도 공개는 [목표별 지역 공개](지도-목표별-공개-상세기획.md)를 적용한다. 전체 공개 시제품안을 대체하고, RV00~07·접근 마스크·첫 트럭의 초원 내 배송·시작 나무로 MG08·MG28 전 조립 부지 보장을 포함한다. 지도 공개는 D24 조사 보고서가 아니다. 기존 전체 공개 저장을 다시 가리지 않는다.

[통합 진행 검토](지도-연구-생산-진행-통합검토.md)에 7가지 진행 순서·연구/목표 선행 분리·시작 재료/첫 광맥 수지와 구현 차이를 정리했다. MG28 수신지는 공개 부지의 창고/정류장이면 되고 T07/조립소/수신지 생산을 요구하지 않는다. MG29는 이미 해금된 P22/P23의 첫 제작 시작이며 T08 연구를 MG32 완료 뒤로 잠그지 않는다. 건설 반복으로 지도를 추가 공개하지 않는다.

모듈 51개는 장착 1개를 유지하는 경제 사례다. MG34 완료 후 정상 분리·실물 회수·운송한 모듈은 프로젝트 납품에 사용할 수 있어 총 50개 제작으로도 가능하다. 동시 사용/중복 소비는 차단하되 정상 순차 재사용을 금지하거나 기존 MG34 완료를 취소하지 않는다.

현재 main 이외에 .claude/worktrees/regional-d09의 확장 구현도 확인했다(검토 시점 HEAD 988730a). 이 작업본의 초기 반경 40·숲 MG11·전체 MG32·건설 주변 공개는 최신 RV 계약과 다르다. 기능이 없다고 전제해 중복 구현하지 말고 실제 작업 폴더/브랜치·현재 변경을 확인한 뒤 초기 마스크/공개 테이블/건설 공개/저장/테스트를 함께 맞춘다. 기획 파일만 복사해 실제 구현과 맞았다고 보고하지 않는다.

확장 후보인 업적 116종·290기록을 전부 필수 구현 목록으로 해석하지 않는다. 이번 기록 30종은 [record-v1](업적-기록30종-구현기준.md)의 개별 기준과 지원별 활성 목록을 적용한다. 기본 사건 집계 지원 시 26종·104메달, 금속 3종 추가 시 29종·116메달, 폭풍까지 지원 시 30종·120메달이다. 나머지 최초·심화·숨은 86종의 출시 활성 ID·추가 보상 외형은 별도 선정 사항이다. 미지원 계열은 표시·완료율에서 제외하며 미연구 상태를 미지원으로 처리하지 않는다. CG06은 양방향 실제 배송이 가능한 빌드에서만 활성화한다.

UI는 레시피·명목 속도·실제 수치·재료/전력/운송의 관측 상태를 보여 준다. 플레이어가 정한 계획값·차량 수·목표 재고·노선은 유지하며 자동으로 최적값을 입력하지 않는다. 차량 목록 묶음은 표시 기능이고 계획을 자동 합치지 않는다. 현재 연구 성공 토스트·효과음·허브 반짝임을 확인한 뒤 완료 카드로 연결해 중복 효과를 피한다. 상세 동작은 운영 UI §6.1·9.1을 따른다.

되돌리기·다시 실행 버튼은 상단에 이름과 함께 유지한다. 이력이 없으면 비활성 표시하고 숨기지 않는다. Ctrl+Z/Ctrl+Y도 유지하며, 공간 정리를 이유로 두 기능을 단축키 전용이나 메뉴 전용으로 바꾸지 않는다. 버튼 표시가 모듈 설치·고급 차량 생성 등 원래 되돌릴 수 없는 작업의 범위를 확장하지는 않는다.

D11의 상단 배치는 [상단 UI 줄·앵커 상세](상단-UI-배치-앵커-상세기획.md)를 따른다. 논리 폭 900 이상은 2줄, 640~899는 3줄, 그 미만은 기능 묶음을 유지한 세로 배치다. 좌우 8px 정렬·줄 사이 1px 선·상단 아래 8px 팝오버·중앙 연구 완료 카드·겹침 순서를 구현한다. `#topbar`의 실제 `offsetHeight`를 `ResizeObserver`로 측정해 `--top-h`에 반영하고 기존 `top:46px/52px` 상수를 대체한다. `--uiz` 적용 전 논리 좌표와 DOMRect 화면 좌표를 한 번만 변환한다. 메뉴 정리는 기존 새 게임·도움말·소리 기능을 유지하는 위치 변경이다.

하단은 비용 상시 표시형을 사용하며 실제 자원 아이콘+개수를 넣는다. 운영 UI §2.1에 따라 건설 가능/연구 잠김/재료 부족의 상태 띠·아이콘·배경을 구분하고, 차단 항목을 눌러 정보를 확인한 것을 건설 선택으로 처리하지 않는다. ‘드래그로 연속 배치’ 같은 반복 조작 안내는 하단 상세 줄에서 제외한다. `src/ui/toolbar.ts`의 현재 무조건 `setTool(type)`하는 클릭과 숫자키 경로를 함께 검사해 건설 불가 상태의 진입을 막는다. 실제 구현은 기존 `src/ui/icons.ts`의 자원/설비 아이콘과 실제 세계 상태를 사용하며 설계 예시의 화면 조각·샘플 재고를 게임 데이터로 복사하지 않는다.

2026-10-30 최신 사용자 요청과 운영 UI §2.3에 따라 발전 C와 전력 U를 분리한다. 발전은 풍력(C1)·석탄·태양광·수력·연료·지열, 전력은 전봇대·변전소·축전기 순서다. 모든 건설 목록을 초기 설비 → 목표·연구 단계 순의 고정 순서로 바꾸고 카드·숫자키·도감에 공통 적용한다. 연구할 때마다 가변 정렬하지 않는다. 이전의 전력 단일 탭·발전 4종 번호 보존 규칙은 폐기한다. 기존 세계에서 빈 전력·산업 탭은 표시·Tab 순회·도감에서 제외한다. 변전소는 넓은 주변 공급, 전봇대는 연결된 작은 공급 범위 확장 역할을 유지한다. 처리 용량 승격은 삭제한다.

### D02의 새 재료 범위

원자원 6종은 주석광석·보크사이트·수액·원유·황·리튬 함유 염수다. 주석·보크사이트·황은 기존 채굴기, 수액은 새 채취기, 원유·염수는 새 시추기를 사용한다. 천연 모래는 기존 모래 아이템의 새 채취 입지다.

새 가공품/부품 22종은 주석판·청동·청동 구동부·고무·절연 전선·절연 모터·플라스틱·고급 회로·산업 제어기·알루미늄판·경량 프레임·강화 고무·강화 타이어·황산·리튬·배터리 팩·고용량 케이블·윤활유·정유 연료·고급 윤활제·고급 트럭 조립품·자동화 설비 모듈이다. P15는 기존 광물 가루·진흙을 만드는 대체 경로여서 신규 아이템을 더하지 않는다.

### D09 완제품 사용의 세부 변경

1. 모듈은 T08 이후 지원하는 레시피 기계 11종에 1개만 설치한다. 실제로 몸체에 붙은 창고군의 예약되지 않은 모듈 1개를 슬롯으로 이동한다. 기계 일반 재료 포트를 모듈 투입구로 바꾸지 않는다.
2. 배치 시작 시 모듈 사용 여부를 기록한다. 속도 ×1.20·작업 전력 ×1.25이며 작업 중 첫 설치는 다음 배치부터 적용한다.
3. 사용 중 모듈의 기본 분리는 현재 제작 완료 후 실행한다. 기다릴 수 없으면 작업 취소·실제 투입 원료 현지 반환과 함께 즉시 분리한다. 현재 배치에 묶인 모듈을 다른 기계에 중복 사용하지 않는다.
4. 고급 트럭은 T07 이후 정류장 자체/직접 연결 창고군의 조립품 1개로 새 차량 1대를 만든다. 기본 트럭 원가 추가 차감·자동 교체·원격 허브 차감 없음.
5. 새 고급 트럭은 화물 0·노선 미지정·운행 정지·0kJ로 실제 접도 칸에 생성한다. 생성 정류장에서 노선 없이도 충전 예산을 사용해 충전 가능하며, 부족 전력은 생성 실패가 아닌 충전 대기다.
6. 설치·분리·고급 차량 생성/철거는 기본 차량 원가를 쓰는 기존 Ctrl+Z 경로로 재생성하지 않는다. 새 행동은 명시적인 분리·철거로 실제 회수한다. 기존 기본 차량·배치의 되돌리기는 유지한다.
7. 차감·결과 생성·명령 처리 기록을 한 번에 확정한다. 실패 전 차감 없음, 동일 명령 재전송은 재실행 없음. 자세한 상태와 20개 검증 시나리오는 사용 계약을 따른다.

## 7. 검증과 보고 기준

- 착수 때 `npm test`, `npm run typecheck`로 실제 기준선을 확인한다. 이전 기록의 테스트 개수를 현재 결과로 복사하지 않는다.
- 단계별로 바뀐 기능의 의미 있는 검증을 수행한다. 설치/분리/차량 생성은 [사용 계약](모듈-장착-트럭생성-상세기획.md) §12의 M01~M10·V01~V08·S01~S02를 기준으로 한다.
- 재고·슬롯·차량 원가·투입 중 원료·회수 더미의 보존, 예약의 비실물성, 동일 명령의 한 번 적용을 검사한다. 단순 UI 숫자 변경은 기능 완료가 아니다.
- 저장 전후·중간 참가·동일 명령 재생의 상태와 해시에 새 필드가 포함되는지 확인한다. 실제 사용 중인 저장을 덮어써 시험하지 않는다.
- 통합 완료 때 적절한 테스트·타입 검사·`npm run build`와 실제 조작을 확인한다. 4~5시간 목표는 실제 플레이 기록으로 검증하며 계산만으로 달성했다고 보고하지 않는다.
- 최종 보고는 구현한 단계·실행한 검증·실제 통과 범위·미구현/미정/기존 실패를 구분한다. 코드 구현과 문서 설계를 같은 완료로 세지 않는다.
