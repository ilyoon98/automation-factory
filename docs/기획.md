# 자동화 게임 기획서 (초안)

> 최종 수정: 2026-10-20

## 1. 한 줄 컨셉

**탑다운 2D 그리드에서 광물을 캐고, 레시피 체인을 따라 가공하고, 생산 비율이 맞지 않아 생기는 잉여를 이리저리 돌려 쓰며 공장을 키우는 힐링형 자동화 게임.**

- 장르: 생산 체인 자동화 (Factorio 계열을 작게)
- 테마: 산업/공장
- 시점: 탑다운 정사각 그리드
- 플랫폼: 웹 브라우저 (Vite + TypeScript + Canvas 2D)
- 목표 규모: 학습/프로토타입

## 2. 핵심 재미

1. **레시피 트리**: A로 B를, B로 C를, A와 B로 D를 만든다.
2. **비율 퍼즐**: 기계마다 생산 시간이 달라 개수가 딱 맞지 않는다. 남는 잉여를 다른 라인으로 돌리고, 부족한 곳을 채우는 설계가 핵심.
3. **공장이 공장을 짓는다**: 건물은 생산품으로만 짓는다.
4. **힐링형 압박**: 시간 제한이나 적은 없다. 대신 광맥이 유한해서 서서히 확장을 유도한다.

## 3. 핵심 루프

```
유한 광맥 채굴 → 컨베이어 운반 → 제련/조립 → 허브에 납품(창고)
→ 허브 재고로 새 건물 건설 / 연구 납품으로 해금 → 더 큰 공장
```

## 4. 조작 (마우스 중심)

| 입력 | 동작 |
|---|---|
| 좌클릭 | 선택한 건물 배치 / 빈손일 때 건물 클릭 시 정보창(레시피 선택, 상태) |
| 좌클릭 드래그 | 컨베이어 연속 배치 (드래그 방향으로 자동 회전) |
| 우클릭 (드래그) | 철거 (재료 100% 환급) |
| R | 회전 |
| 휠 | 줌 |
| 가운데 드래그 / 스페이스+드래그 | 맵 이동 |
| 1~9 | 건물 단축키 |
| Q / Esc | 선택 해제 |

## 5. 허브

허브는 **창고 + 건설 자재 공급원 + 연구 납품처**다. (Mindustry의 코어 방식)

- 벨트로 허브에 넣은 아이템이 허브 재고에 쌓인다.
- 건물을 놓으면 허브 재고에서 재료가 빠진다. 철거하면 돌려받는다.
- 연구: 특정 아이템을 정해진 수만큼 납품하면 새 건물/레시피 해금. 기한 없음.

## 6. 아이템과 레시피 (MVP)

| 아이템 | 재료 | 시간 | 건물 |
|---|---|---|---|
| 철광석 | – | 1초 | 채굴기 (철광맥) |
| 구리광석 | – | 1초 | 채굴기 (구리광맥) |
| 석탄 | – | 1초 | 채굴기 (석탄맥) |
| 돌 | – | 1초 | 채굴기 (돌, 무한) |
| 철판 | 철광석×1 | 2초 | 제련로 |
| 구리판 | 구리광석×1 | 2초 | 제련로 |
| 기어 | 철판×2 | 3초 | 조립기 |
| 구리선 | 구리판×1 → 2개 | 1.5초 | 조립기 |
| 강철 | 철판×2 + 석탄×1 | 5초 | 제련로 |
| 회로 | 철판×1 + 구리선×3 | 4초 | 조립기 |

석탄은 강철 재료이면서 발전기 연료 → 자원 경쟁.

## 7. 전력

- 석탄 발전기가 석탄을 태워 전력 생산.
- 프로토타입: 맵 전체가 하나의 전력망. 공급/수요 비율만큼 모든 기계 속도가 줄어든다 (공급 80% → 80% 속도).
- 나중: 전봇대와 연결 범위, 배터리.

## 8. 자원 진행 곡선

| 단계 | 자원 | 느낌 |
|---|---|---|
| 초반 | 풍부한 유한 광맥 (매장량 표시) | 빠르게 공장 세우기 |
| 중반 | 가까운 광맥 고갈 → 먼 광맥까지 확장 | 부드러운 확장 압박 |
| 후반 | 흙·돌(무한) → 다단계 공정 → 소량 금속 | "광맥 독립"이 장기 목표 |

후반 무한 자원 공정 예시:

```
돌 ─분쇄기→ 자갈 ─분쇄기→ 모래
모래 + 물 ─세척기→ 광물 슬러리 + 진흙(부산물)
슬러리 ─분리기(전력 많이)→ 철 정광 70% / 구리 정광 20% / 슬래그 10%
정광 ─제련로→ 철판·구리판
진흙 ─가마→ 벽돌 (건물 자재)
슬래그 → 콘크리트 원료 또는 소각
```

## 9. 리서치에서 확정한 원칙

- 드래그 배치, 복사·붙여넣기, 철거 100% 환급, 기계 상태 아이콘을 **처음부터** 넣는다.
- 규칙은 직관적으로, 툴팁과 상태 표시로 설명한다.
- 새 레시피/제약이 기존 설계를 흔들어야 한다 (반복 방지).
- 해금/비용 곡선은 미리 계산해서 중후반 정체를 막는다.

## 10. 기술 설계

- **시뮬레이션과 렌더링 분리**: 고정 틱(초당 60틱)으로 `World` 갱신, `requestAnimationFrame`으로 그리기. (처음엔 20틱으로 잡았지만 컨베이어 아이템이 끊겨 보여서 60으로 올림)
- `src/sim`: 순수 로직 (DOM 의존 없음, 테스트 가능)
- `src/render`: Canvas 그리기, 카메라
- `src/input`: 마우스/키보드
- `src/data`: 아이템, 레시피, 건물 정의
- `src/ui`: 툴바, 허브 재고, 정보창

### 기획과 달라진 점 / 결정이 필요한 점

- **건설비**: 결정대로 생산품만 사용. 시작 재고 철판 120, 기어 40, 돌 40.
- **허브 기본 전력 300kW**: 석탄 채굴기도 전기가 필요해서, 처음 발전기를 돌릴 전력이 없으면 시작이 막힌다. 그래서 허브가 기본 전력을 준다.
- **입출구 방향 (2026-10-21 변경)**: 처음엔 Mindustry처럼 아무 면으로나 내보냈는데, 제련로 옆 분배기로 결과물이 새어 라인이 막히는 문제가 생겼다. 그래서 방향을 정했다.
  - 채굴기·제련로·조립기: 노란 화살표(앞면)로만 출력, 나머지 면으로 입력. R로 회전.
  - 분배기·우선 분배기: 뒤 한 면이 입구, 앞·양옆이 출구.
  - 출구가 다른 기계·발전기·허브에 닿으면 컨베이어 없이 바로 넣는다.
  - 예전 저장(v1)은 불러올 때 이어진 컨베이어를 보고 방향을 자동으로 맞춘다.
- **컨베이어 드래그**: 이미 있는 컨베이어 위를 드래그하면 방향이 바뀐다 (shapez 방식). 교차로를 실수로 망가뜨릴 수 있다.
- **연구**: "납품"이 아니라 허브 재고에서 재료를 내고 즉시 해금. 시간이 걸리는 연구는 아직 없다.
- **컨베이어 위에 짓기 (2026-10-21)**: 기계·분배기를 컨베이어 위에 클릭하면 그 칸 컨베이어를 철거·환급하고, 흐름 방향으로 출구를 맞춰 라인에 끼워 넣는다. 드래그로는 덮어쓰지 않는다 (줄 전체가 지워지는 사고 방지).

- **지하 컨베이어 (2026-10-21)**: 입구를 놓고 같은 방향으로 최대 4칸 건너 놓으면 출구. 사이 칸은 무엇이 있어도 지나간다. 방향을 바꾸려면 철거 후 다시 놓기 (회전하면 짝이 깨지므로 막음). 드래그로는 깔지 않는다.

### 2026-10-21 추가 (요청 반영 완료)

1. **툴바 개편**: 하단을 크게. 카테고리 탭(물류 Z · 생산 X · 전력 C · 보관 V, Tab으로 돌리기) + 그 탭의 건물 목록. 숫자 1~9는 지금 탭의 N번째 건물. 처음엔 즐겨찾기 단축칸 10개를 따로 뒀다가, "탭 + 번호"가 더 낫다는 의견으로 단축칸을 없앴다. 탭 안 순서는 `CATEGORIES.items`가 정한다.
2. **스마트 분류기** ('물류' 연구): 고른 아이템은 앞으로, 나머지는 양옆에 번갈아. 고를 수 있는 목록은 그 줄을 거꾸로 따라가(컨베이어·지하·분배기·병합기 통과) 찾은 기계가 만들 수 있는 아이템과 지금 줄 위에 있는 아이템뿐이다. 정보창에 "이 줄로 들어오는 곳"을 보여 주고, 기계를 못 찾으면 전체 목록을 보여 준다.
3. **창고 + 하역기** ('보관' 연구): 창고는 최대 200개 보관. 하역기는 뒤에 붙은 허브·창고에서 고른 아이템을 초당 2개 꺼낸다 (너무 빠르면 "전부 허브에 넣었다 꺼내기"만 하게 되므로 제한).
4. **고속 컨베이어·고급 채굴기**: 전역 속도 업그레이드 연구를 없애고 따로 짓는 건물로. 연구는 해금만. 고속 컨베이어(1.5배)는 일반 컨베이어 위로 드래그하면 아이템을 유지한 채 교체. 고급 채굴기는 2배 속도·2배 전력.
- 레시피·분류기 아이템 기억이 "도구 설정 기억"으로 합쳐졌다 (조립기·제련로·분류기·하역기).
6. **기계별 생산 현황**: 기계마다 최근 가동 기록(15초 지수 평균)을 남긴다. 정보창 맨 위에 실제 분당 생산(크게)·최대·가동률·멈춘 이유(재료 부족/출력 막힘/전력 부족)와 해결 힌트, 실제 소비량. I 키(또는 위쪽 "생산량" 버튼)로 맵의 모든 기계 위에 "N/분"을 가동률 색(초록 ≥90%, 노랑 ≥50%, 빨강)으로 띄워 병목을 한눈에 찾는다.
5. **병합기** (처음부터 사용 가능, 물류 7번): 뒤·양옆으로 받아 앞으로. 컨베이어가 1차선이라 옆구리 합류는 본선이 꽉 차면 옆줄이 거의 못 들어간다 (측정: 본선 55 대 옆줄 5). 병합기는 기다리는 줄끼리 하나씩 번갈아 받아서 꽉 찬 두 줄을 반반 섞는다 (측정: 56 대 53). 한 줄만 있으면 기다리지 않고 통과.

### 도감 (2026-10-21)

마인크래프트 JEI(Create 모드 등)처럼, 아이템을 누르면 얻는 법(레시피 + 채굴·양수 같은 출처) · 쓰는 곳(레시피 + 발전기 연료) · 건설 재료 · 연구 재료를 표로 보여 준다. 표 안의 아이템을 누르면 그 아이템으로 넘어가고 "뒤로"로 돌아온다. 잠긴 레시피는 필요한 연구를 표시. G 키 / 위쪽 "도감" 버튼 / 허브 재고 줄·레시피 카드·연구 비용의 아이템을 누르면 열린다.

- 표 모양: **왼쪽 재료 ─ 가운데 기계(화살표 위에 시간) ─▶ 오른쪽 결과물**, 맨 오른쪽에 분당 개수나 잠김 표시. 건설·연구 재료도 `[철판 ×8] ─짓기─▶ [채굴기]` 같은 모양으로 맞췄다.
- **광맥·지형 페이지** (철광맥·구리광맥·석탄 광맥·돌 광맥·호수·빈 땅): 맵 모양 그대로의 타일 그림, 설명, 칸당 매장량, 지금 맵에 남은 총량, 캐는 법(채굴기 60 / 고급 채굴기 120 / 양수기 120).
- **건물 페이지**: 설명(입출구 포함) · 짓는 법(비용, 필요한 연구) · 넣을 수 있는 재료 · 하는 일(그 건물의 레시피 전부, 채굴기는 캐는 곳). 표 안의 기계 이름, 정보창의 "📖 도감" 버튼, 툴바 건물 우클릭으로 연다.

### M7 확정 내용 (2026-10-21)

| 기계 | 재료 | 결과 | 시간 |
|---|---|---|---|
| 채굴기 (빈 땅) | – | 흙 | 1초 |
| 양수기 (호수 위) | – | 물 ×2 | 1초 |
| 분쇄기 | 흙 2 | 자갈 1 + 모래 1 (한 줄에 섞임) | 2초 |
| 분쇄기 | 자갈 1 | 모래 1 | 1.5초 |
| 분쇄기 | 돌 1 | 자갈 2 | 2초 |
| 세척기 | 모래 3 + 물 2 | 광물 가루 1 + 진흙 1 | 3초 |
| 분리기 | 광물 가루 1 | 철 정광 / 구리 정광 / 슬래그 (10개마다 7·2·1, 고정 순서) | 4초 |
| 제련로 | 철 정광 / 구리 정광 | 철판 / 구리판 | 2초 |
| 제련로 | 진흙 2 | 벽돌 1 | 3초 |
| 조립기 | 슬래그 2 + 자갈 1 | 콘크리트 1 | 3초 |

- 결정: 흙은 빈 땅 어디서나 / 물 포함 (호수 + 양수기, 물은 아이템으로 컨베이어에) / 분리기는 고정 순서 / 슬래그는 콘크리트로.
- 호수 위에는 양수기만 지을 수 있다 (컨베이어는 지하 컨베이어로 건넌다). 예전 저장(v1·v2)은 불러올 때 빈 땅에 호수를 더한다.
- 광맥 위에 놓은 채굴기는 광맥이 바닥나면 멈춘다 (흙으로 바뀌지 않음). 흙은 광맥이 없는 땅에 놓은 채굴기만.
- 측정: 흙 채굴기 1대 → 분쇄기 1대 → 세척기 1대 → 분리기 1대 줄에서 철판 분당 약 7개 + 벽돌·구리 정광·슬래그·남는 자갈. 광맥 1대(분당 30)를 대신하려면 이 줄이 4개쯤 필요.

### 광맥 (2026-10-21 변경)

- **광맥 전체에서 캐기**: 이어진 같은 광석 칸들이 한 광맥. 채굴기는 광맥 어디에 놓든 그 광맥 전체에서 캐고, 바깥 칸(원래 모양 기준 가장자리)부터 옅어지다 사라진다. 채굴기가 깔고 있는 칸은 맨 나중. 다 캐서 옮길 필요가 없다. 같은 광맥의 채굴기들은 양을 나눠 쓴다.
- 칸마다 광맥 번호를 저장해서 (사라진 칸 포함), 불러온 뒤에도 같은 광맥에서 이어서 캔다.
- **먼 광맥 줄이기**: 예전엔 먼 광맥이 시작 광맥의 40배가 넘어 바닥날 일이 없었다. 개수 28 → 20, 칸당 800 + 거리×40 → 300 + 거리×8, 종류는 비율대로 고르게. 이제 종류별로 시작 광맥의 약 6~19배. 예전 저장은 불러올 때 먼 광맥(가운데서 20칸 밖)을 1/4로 (한 번만, 저장의 rev로 판단).

### 광맥 고갈 경고 (2026-10-21)

- 광맥마다 **바닥까지 남은 시간** = 남은 양 ÷ (그 광맥 위 채굴기 전부의 최근 15초 실제 생산 합). 막히거나 전력이 모자라 느려지면 그만큼 길어진다. 여러 광맥에 걸친 채굴기는 아직 남은 광맥끼리 속도를 나눈다.
- **곧 바닥** = 지금 속도로 10분 안 (`PATCH_LOW_MIN`). **바닥남** = 0개인데 위에 채굴기가 남아 있음.
- 알림은 광맥마다 단계별로 한 번씩 (5초). 새 게임·불러오기 직후에 이미 있던 경고는 알림 없이 목록에만.
- 왼쪽 맨 위 **"⚠ 광맥 경고"** 목록: 바닥남 먼저, 그다음 남은 시간 짧은 순. 누르면 그 광맥의 채굴기로 화면을 옮기고 정보창을 연다 (여러 대면 누를 때마다 다음 채굴기). 채굴기를 다 치우면 목록에서 빠진다.
- 맵: 곧 바닥날 광맥 위 채굴기에 노란 **!** (바닥나면 원래대로 빨간 ✕).
- 채굴기 정보창: 광맥 전체 남은 양(처음의 %)과 막대, 이 광맥 채굴기 수·분당 합계, 바닥까지 남은 시간. 바닥나면 "철거하고 옮기세요" 안내.
- 광석 칸 툴팁: 광맥 전체 남은 양(%)과, 캐는 중이면 채굴기 수와 바닥까지 남은 시간.
- 저장: 광맥마다 처음 매장량과 광석 종류(`patchMeta`). 다 캐서 칸이 전부 사라진 광맥도 불러온 뒤 "철광맥 바닥남"으로 알 수 있다. 이 기능 전 저장은 불러온 때의 양을 처음 양(100%)으로 본다.

### 재료 필요량 표시 (2026-10-21)

- 기계 정보창의 생산 칸 아래 **"재료 · 100%로 돌리려면 필요한 양"**: 재료마다 최대 속도일 때 분당 필요량(크게)과 지금 실제로 쓰는 양. 재료 줄을 몇 갈래로 나눌지 정할 때 보는 숫자라 측정 중에도 보인다.
- 재료 부족으로 멈추면 "철광석 분당 30개를 대 주면 100%로 돌아가요. 지금은 분당 10.7개만 들어와요."처럼 숫자로 안내.
- 기계 툴팁에도 "100%에 필요: 분당 N".

### 차량 운송 (2026-10-21)

결정: **도로 위를 달리는 트럭**, **두 정류장 왕복**, 연료는 **전기 충전** (2026-10-22, 아래 "트럭 충전").

- **연구 "차량 운송"** (강철 40 · 기어 40 · 회로 20, 선행: 강철 제련 + 전자 공학) → 운송 탭(B): 도로, 정류장.
- **도로** (돌 1): 드래그로 깐다. 방향 없음, 트럭만 다닌다. 컨베이어와 엇갈리면 지하 컨베이어로 밑을 지난다. 이웃한 도로·정류장 쪽으로 이어져 보이고 끊긴 쪽은 연석.
- **정류장** (2×2, 철판 20 · 기어 10 · 강철 5): 번호가 붙는다(정류장 1, 2…). 테두리에 닿은 도로 칸에 트럭이 선다.
  - **싣기**: 아무 면으로나 컨베이어로 받아 최대 200개 쌓아 둔다.
  - **내리기**: 트럭이 내린 짐(최대 200개)을 앞(노란 화살표)으로 내보낸다. 앞을 허브에 붙이면 바로 입고.
  - 싣기 정류장에 내리면 쌓여서 다른 트럭이 실어 간다 (갈아싣기).
  - 종류를 바꾸면 쌓인 짐은 허브로 돌려준다. 도구 설정 기억·Q·복사 붙여넣기에 종류가 따라간다.
- **트럭** (강철 10 · 기어 10 · 회로 5): 정류장 정보창의 "트럭 만들기". 건물이 아니라 칸을 차지하지 않고 트럭끼리 겹쳐 지나간다. 50개 실음, 초당 4칸, 싣고 내리기 초당 10개.
  - **줄 서기** (2026-10-23, 사용자가 "정류장 앞에서만"으로 정함): 같은 칸에 서 있는 트럭들(정류장에서 싣고 내리거나 차례를 기다림, 충전기 앞 충전)은 먼저 온 트럭만 제자리, 나머지는 도로를 따라 온 쪽(뒤)으로 한 칸씩 줄 서 그린다. 뒤쪽 도로가 모자라면 옆·앞쪽, 그래도 모자라면 마지막 칸에 겹친다. **화면만** 바꾸고 시뮬레이션 자리(모두 그 칸)는 그대로라 같이 하기에 영향이 없다 (`World.truckSpots`). 클릭도 보이는 자리로 고른다. 달리는 트럭은 지금처럼 겹쳐 지나간다.
  - 만들 때 짝: 도로로 갈 수 있는 가장 가까운 반대 종류 정류장 (없으면 한쪽만 정한 채 기다림).
  - 싣는 곳에서 가득 차거나, 덜 찼어도 5초 동안 새 짐이 없으면 출발. 내리는 곳에서 다 내리면 돌아간다.
  - 길: 도로 칸 너비 우선 탐색. 칸 가운데에 섰을 때, 목적지나 도로·정류장이 바뀌었을 때만 다시 찾는다. 밑의 도로가 사라져도 옆 도로로 빠져나간다.
  - 상태: 달리는 중 / 싣는 중 / 짐 기다리는 중 / 내리는 중 / 내릴 곳이 꽉 참 / 충전 중 / 배터리 없음 (천천히) / 길 없음 / 정류장을 골라 주세요. 멈춘 이유는 트럭 위 빨간·주황 !와 정보창 안내.
  - 클릭하면 정보창(싣는 곳·내리는 곳 고르기, 짐, 한 바퀴 기준 분당 운송량, 트럭으로 가기, 철거)과 맵에 두 정류장 점선 테두리 + 가는 길. 철거(Del)하면 재료와 짐을 돌려받는다.
- 저장: 정류장 번호·종류, 트럭 위치·짐·하던 일. 길은 저장하지 않고 다시 찾는다.

### 트럭 싣는 짐 고르기 (2026-10-22, 자율 작업)

- 트럭 정보창 "싣는 짐": 아무거나(기본) 또는 아이템 하나. 고르면 싣기 정류장에서 그 아이템만 싣는다. 이미 실은 짐은 그대로.
- 싣기 정류장의 차례: 서로 다른 아이템만 싣는 트럭끼리는 기다리지 않고 동시에 싣는다 (한 정류장에 철·구리를 섞어 넣고 트럭 둘로 나눠 나르기). 한쪽이라도 "아무거나"면 지금처럼 먼저 온 트럭부터.
  - 단, 먼저 온 트럭이 **지금 실을 게 없으면**(고른 짐이 정류장에 없음, 또는 가득 차서 충전 중) 뒤 트럭이 먼저 싣는다. 안 그러면 철만 싣는 트럭이 앞에서 기다리는 동안 구리가 쌓여 정류장이 막힌다 (리뷰에서 찾은 문제).
  - 한계: 되돌리기(Ctrl+Z)로 다시 만든 트럭은 싣는 짐이 "아무거나"로, 배터리는 가득으로 돌아온다.
- 그 짐이 없으면 "짐 기다리는 중" + "이 트럭이 실을 짐(철광석)이 싣는 정류장에 없어요" 안내.
- "같은 길로 한 대 더"는 싣는 짐도 따라간다. 저장·체크섬에 들어가고, 같이 하기 명령 `truck-filter`. 되돌리기(Ctrl+Z)에는 안 들어간다 (정류장 고르기처럼).

### 트럭 충전 (2026-10-22, 자율 작업)

사용자가 "연료가 있으면 좋겠다"고 했던 것. 석탄 연료와 전기 충전 중 **전기 충전**으로 정함 (판단):
석탄은 바닥나는 자원이고 최종 목표가 "석탄 독립"이라 트럭이 석탄을 먹으면 목표와 어긋난다.
또 정류장에 연료 칸을 따로 두면 "석탄을 실어 나르는 정류장"과 헷갈린다. 전기는 이미 있는 전력망을 그대로 쓰고, 태양광·수력으로 가면 석탄 없이 돈다.

- **배터리** 1,800kJ. 달리는 동안 60kW → 한 칸 15kJ, 가득 차면 **120칸**.
- **충전**: 정류장에 서 있는 동안(싣는 중·내리는 중·차례 기다림) 한 대 **200kW**를 공장 전력에서 가져온다. 빈 배터리 → 가득 9초. 싣고 내리는 데 5초쯤 걸려서, 보통 길(왕복 수십 칸)에서는 그사이에 거의 다 찬다.
  - 충전도 전력 수요에 들어간다. 모자라면 기계처럼 같은 비율로 느려진다 (허브 300kW에 트럭 둘이 충전하면 75%).
  - 전력 판에 "사용 중 N kW는 트럭 충전", 정류장 정보창에 "충전 중 트럭 N대 · 실제 충전 kW".
- **떠나기**: 떠날 때가 돼도(가득 참·5초 새 짐 없음·다 내림) 배터리가 다 찰 때까지 "충전 중"으로 기다린다. 그동안 짐은 계속 싣는다.
- **배터리가 떨어지면** 멈추지 않고 1/4 속도로 간다 ("배터리 없음 (천천히)", 트럭 위 주황 !). 힐링형이라 막히는 일은 없게. 정보창 안내: 120칸보다 먼 길은 중간에 싣기 정류장을 두고 트럭 두 대로 갈아싣기.
- 정보창: 배터리 %·남은 칸 수·충전 속도 막대. 도감 정류장 페이지에 "충전 한 번에 120칸".
- 정보창 "길 (한쪽)": 두 정류장 사이 도로 칸 수와 배터리 가득일 때 갈 수 있는 칸. 길이 더 길면 빨갛게 "배터리가 모자라요" (`World.routeLength`, 도로·정류장이 바뀔 때만 다시 잰다).
- 저장·체크섬에 배터리. 배터리가 없던 예전 저장은 가득 찬 채로.
- 값은 `TRUCK.battery / drive / charge / emptySpeed` (`src/data/buildings.ts`).

### 고용량 배터리 · 충전기 (2026-10-23)

계획서 2.2의 "배터리 연구"와 "충전소".

- **연구 "고용량 배터리"** (물류 탭, 선행 차량 운송, 구리판 300 · 회로 200 · 강철 100): 배터리 1.5배 (120 → 180칸), 정류장 충전 1.5배 (200 → 300kW), 충전기 해금. 연구 15 → 16개.
- **충전기** (운송 탭 3번, 1칸, 구리판 20 · 회로 10 · 강철 5): 도로 바로 옆에 놓는다.
  - 판단: 처음엔 "충전 도로"(도로의 한 종류)를 생각했지만, 도로를 특별 취급하는 곳(드래그·도로/컨베이어 겹침·연결 그림·지도·철거)이 많아 따로 건물로 했다.
  - 트럭이 충전기 옆 도로 칸 가운데에 닿았을 때, **남은 길(지금 가는 정류장까지 칸 수 × 15kJ)을 갈 배터리가 모자라면** 서서 400kW로 가득 채우고 다시 간다 ("충전 중"). 넉넉하면 그냥 지나간다. 배터리가 다 떨어져 천천히 오던 트럭도 선다.

### 숲·나무 1차 (2026-10-23)

계획서 2.4 "새 자원". 구상은 [숲-구상.md](숲-구상.md), 정한 것: 벌목기·식목기 따로, 2분, 숯은 약한 대신, 나무 위에 지으면 베어짐.

- **나무 층**: 칸마다 자람 정도(`World.tree`, 0 = 없음 ~ 1 = 다 자람). 자라는 나무는 심은 순서대로 `growing`에 들고 틱마다 키운다 (같이 하기에서 모두 똑같이). 광맥·건물·나무가 있는 칸에는 못 심는다. 다 캔 광맥 칸은 광맥 표시가 지워지니 심을 수 있다.
- **맵 숲** (`addForests`): 허브에서 12~16칸에 1곳, 멀리 6곳. 가장자리는 듬성듬성, 처음부터 다 자란 나무. 예전 저장(나무 정보 없음)을 불러오면 그때 더한다.
- **연구 "산림"** (자원 탭, 선행 강철 제련, 철판 300 · 기어 150): 숲 탭(N) 건물 3개 + 레시피 3개. 연구 17개.
- **벌목기** (2×2, 50kW, 회전): 둘레 3칸(8×8) 안의 다 자란 나무를 2초에 한 그루 베어 앞으로 통나무 2 + 묘목 1. 앞이 막혀 6개가 쌓이면 멈춘다. 끝없는 연구 "채굴"이 베는 속도도 올린다. 상태 "다 자란 나무 없음".
- **식목기** (2×2, 30kW, 회전 없음, 네 면으로 받음): 묘목을 5개까지 받아 범위 8×8 안 빈 땅에 1초에 하나 심는다 (위 줄 왼쪽부터). 상태 "심을 땅 없음". 가동률은 나무 자라는 속도에 묶여 의미가 없어서 생산 현황을 안 보여 준다.
  - 한 판: 범위 60칸쯤 = 2분마다 60그루 = 초당 0.5그루 → 벌목기 한 대(초당 0.5그루)와 딱 맞는다. → 고침 (밸런스 점검 2): 식목기 범위가 벌목기 범위와 일부만 겹쳐서 실제로는 분당 통나무 40개, 숲 가꾸기 뒤 58개.
- **제재소** (2×2, 90kW): 통나무 1 → 목재 2 + 톱밥 1 (2초). 목재·톱밥은 2차(종이·건물 비용)에서 쓴다.
- **숯**: 제련로에서 통나무 2 → 숯 1 (3초). 석탄 발전기 땔감(1개 2,500kJ, 석탄 4,000kJ의 2/3, 석탄보다 먼저 태움), 제련로 강철(철판 2 + 숯 1).
  - 제련로는 첫 재료로 레시피를 고르는데, 철판이 든 제련로에 숯이 오면 "숯 강철"로 바뀐다. 바꾸기는 **이미 재료가 들어 있을 때만** (빈 제련로가 이리저리 바뀌지 않게).
- **나무 위에 짓기**: 그 칸 나무가 사라지고, 다 자란 나무면 통나무 2를 허브로 돌려받는다.
- **화면**: 나무 3단계(새싹·어린 나무·나무, 다 자란 나무는 살랑임), 지도·미니맵에 초록, 멀리서 보면 초록 칸. 벌목기·식목기를 고르거나 들면 범위를 초록 점선으로. 정보창에 범위 안 나무(다 자람·자라는 중)·빈 땅·묘목. 그림은 그래픽 세션에서 다듬었다 (벌목기는 톱날 대신 도끼, 제재소와 헷갈리지 않게).
- **목표 3개** (트럭 다음): 연구 산림 → 나무 베기 → 나무 심기(심은 나무가 처음 다 자람). 목표 27개.
- **저장·체크섬**: 나무 목록 `[칸, 자람]`. "나무 심기" 목표용 다 자란 나무 수는 저장하지 않는다 (이룬 목표는 따로 저장됨).

### 숲·나무 2차 (2026-10-23)

목재·톱밥을 쓸 곳과 숲을 키우는 목표. 사용자: "2차도 이어서 진행해".

- **종이** (아이템 27개째): 세척기에서 톱밥 2 + 물 1 → 종이 1 (2초). 물은 양수기가 있어야 해서 연구 **"제지"**는 산림 + 흙 정제 뒤 (목재 200 · 회로 100, 자원 탭).
  - 세척기는 첫 재료로 레시피를 고른다. 물이 먼저 오면 "모래 세척"으로 정해지지만, 물을 든 채 톱밥이 오면 "종이"로 바뀐다 (숯 강철과 같은 규칙: 재료를 들고 있을 때만).
- **연구 "숲 가꾸기"** (제지 다음, 종이 100 · 목재 300): 나무가 1.5배 빨리 자란다 (2분 → 80초). 식목기 정보창의 "몇 분이면 다 자라요"도 따라 바뀐다.
  - 판단: 구상에는 "숲 연구들에 종이"만 있어서, 종이를 끝없는 연구 전에도 쓰도록 이 연구를 더했다. 범위 넓히기도 생각했지만, 지어 둔 벌목기·식목기의 칸을 다시 계산해야 해서 자라는 속도로 했다.
- **끝없는 연구 "나무 자라기"** (5번째 줄, 종이 100 · 목재 200 · 회로 100): 단계마다 나무가 10% 더 빨리 자란다. 숲 가꾸기와 곱해진다 (`World.treeGrowth()`).
- **숲 되살리기**: 광맥을 다 캐면 광맥 표시는 지워지고 광맥 번호(`patchOf`)는 남는다 → "다 캔 광맥 땅" = 광맥 번호가 있고 광맥이 없는 칸. 그 위의 다 자란 나무를 센다 (`World.revivedLand()`). 새 저장 칸은 필요 없다.
  - 목표 "숲 되살리기": 다 캔 광맥 땅에 다 자란 나무 50그루 (`FOREST.revive`). 광맥이 다 떨어지는 건 늦은 일이라 목표 맨 끝에 두었다 (목표는 순서와 상관없이 이루면 체크된다).
  - 공장 통계 맨 위에 "🌲 숲: 다 자란 나무 N그루 · 자라는 중 M · 다 캔 광맥 땅 S칸 중 R칸에 다 자란 나무 (숲 되살리기 R/50)".
  - 식목기 정보창: 범위 안 다 캔 광맥 땅이 있으면 "다 캔 광맥 땅 S칸 · 다 자란 나무 R".
- **목표 2개**: "종이 만들기"(콘크리트 다음, 부산물 쓰기끼리), "숲 되살리기"(맨 끝). 목표 29개.

- **나무 좌우 뒤집기**: 칸마다 정해진 쪽으로 뒤집어 그려서 숲이 과수원처럼 줄 맞춰 보이지 않게 (그래픽 세션 제안). 빛 방향이 바뀌는 나무도 있지만 16px에서는 거의 티가 안 난다.
- 종이 아이콘(귀퉁이 접힌 종이)은 임시 그림.

### 끝없는 연구 (2026-10-22, 자율 작업)

최종 목표(광맥 독립)를 마치면 더 할 게 없던 문제. 공장을 계속 키울 이유를 주려고 단계형 연구를 붙임 (판단).

- 연구 창에 다섯 번째 탭 **"끝없는"** (탭에 단계 합계). 광맥 독립 전에는 잠겨 있다. 다른 연구를 다 마쳤으면 연구 창을 열 때 이 탭이 먼저 열린다.
- **채굴 속도**: 모든 채굴기·고급 채굴기·양수기가 단계마다 +10%. 1단계 강철 100 · 회로 100 · 콘크리트 20.
- **기계 속도**: 모든 기계(제련로·조립기·분쇄기 등)가 단계마다 +10%, 전력은 그대로. 1단계 벽돌 100 · 회로 150 · 콘크리트 20.
- **컨베이어 속도**: 모든 컨베이어(고속·지하 포함) 위 아이템이 단계마다 +10% 빨리 간다 → 한 줄 처리량도 그만큼. 1단계 강철 100 · 기어 200 · 회로 100. 컨베이어 무늬 움직임도 같이 빨라진다. 도감의 컨베이어 속도는 기본값.
- **트럭 성능**: 트럭 속도와 배터리 크기가 단계마다 +10%. 칸당 드는 전기(15kJ)와 충전 속도(200kW)는 그대로라, 배터리가 커진 만큼 더 멀리 가고 충전은 조금 더 오래 걸린다. 1단계 강철 150 · 기어 100 · 회로 100. 새 트럭은 커진 배터리가 가득 찬 채로, 먼저 있던 트럭은 다음 정류장에서 마저 채운다.
- 다음 단계 비용은 1.5배 (올림). 단계는 끝이 없다.
- 효과는 `World.craftTime`에 곱해지고, 기계별 생산 현황·공장 통계의 "최대" 값에도 들어간다. 도감의 레시피 시간은 기본값 그대로 보여 준다.
- 저장(`levels`)·체크섬에 단계. 같이 하기에서는 기존 연구 명령 그대로 쓴다.
- 값: `ENDLESS_TECHS`, `ENDLESS_GROWTH` (`src/data/tech.ts`).
- 나중에: 필요하면 줄을 더하기 (예: 발전량, 정류장 싣고 내리기 속도).

### 공장 파일 내보내기·불러오기 (2026-10-22, 자율 작업)

exe로 바뀌면서 저장이 그 PC 안(앱 저장 공간)에만 있어서, 다른 PC로 옮기거나 친구가 이어서 방장을 하거나 백업할 방법이 없었다 (판단).

- 도움말(H) 맨 아래 **"📤 공장 파일로 내보내기"**: 지금 공장을 `자동화공장-날짜-시각.json`으로 내려받는다 (저장 파일과 같은 내용).
- **"📥 공장 파일 불러오기"**: 파일을 고르면 확인 후 지금 공장 대신 불러온다. 바로 저장하고, 방장이면 손님들에게도 새 공장을 보낸다 (새 게임과 같은 흐름). 손님일 때는 꺼짐.
- 공장 파일이 아니면 "공장 파일이 아니에요". 호수가 없던 예전 맵이면 불러올 때 호수를 더한다 (평소 불러오기와 같음).
- **"↩ 바로 전 공장으로"**: 새 게임·파일 불러오기로 공장이 통째로 바뀌기 바로 전 공장을 한 칸 보관해 둔다 (`automation-game/save-backup`). 누르면 지금 공장과 맞바꿔서, 한 번 더 누르면 다시 돌아온다. 실수로 새 게임을 눌렀을 때를 위한 것 (판단). 아주 큰 공장이라 저장 공간이 모자라면 보관만 건너뛴다.

### 효과음 (2026-10-22 밤, 자율 작업)

- 소리 파일 없이 Web Audio로 그 자리에서 만든다 (`src/ui/sound.ts`). 나무 공방 느낌의 짧고 부드러운 소리.

### 트럭 노선: 여러 정류장 (2026-10-22 밤, 요청)

두 정류장 왕복만 있어서, 광맥 여러 곳에서 모으려면 트럭을 따로따로 만들어야 했다.

- 트럭마다 **노선** = 정류장 2~8곳, 곳마다 **싣기·내리기**. 위에서 아래로 돌고 끝나면 처음으로. 같은 정류장을 여러 번 넣어도 되지만 바로 다음 정류장은 달라야 한다.
- 처음 만들면 예전처럼 "싣는 곳 → 가장 가까운 내리는 곳" 두 곳 노선. 예전 저장의 트럭도 두 곳 노선으로 읽는다 (`load`·`unload`도 계속 저장해서 예전 버전도 읽을 수 있음).
- 정류장에서 하는 일 (판단):
  - 싣는 곳: 가득 차거나 5초 동안 새 짐이 없으면 출발 (예전과 같음). 이미 가득이면 들르기만. **빈 채로는 기다리되, 노선의 다른 싣는 곳에 이 트럭이 실을 짐이 있으면 빈 채로 넘어간다** — 처음엔 무조건 넘어가게 했다가, 모든 싣는 곳이 비면 빈 바퀴를 끝없이 돌며 충전 전력만 쓰는 걸 테스트에서 보고 바꿈.
  - 내리는 곳: 다 내리면 다음으로. 꽉 차면 기다리되, **노선에 다른 내리는 곳이 있으면 남은 짐을 싣고 넘어간다** (넘치는 짐을 다른 곳으로).
  - **싣는 곳마다 실을 짐**을 따로 고른다 (기본 아무거나). 예: A에서는 철광석, C에서는 돌. 예전 트럭마다 하나였던 "싣는 짐"은 모든 싣는 곳에 들어가고, 저장의 `filter`에는 첫 싣는 곳의 것을 계속 써서 예전 버전도 읽을 수 있다.
- 한 바퀴 = 노선 마지막 정류장을 떠날 때까지. 운송량은 그동안 내린 개수 / 걸린 시간 (두 곳 노선이면 예전과 같은 값).
- 트럭 정보창: 노선 줄마다 두 줄 — 차례 · 정류장 · ▲(한 칸 앞으로) · ×(빼기) / 싣기·내리기 · (싣는 곳이면) 실을 짐. "+ 정류장 더하기". 트럭 전체 "싣는 짐" 칸은 없앰. 정류장을 고르면 싣기·내리기는 그 정류장 종류로 맞추고 옆에서 바꿀 수 있다. 지금 가는 정류장은 놋쇠색 테두리. 아직 안 고른 정류장이 있으면 "정류장을 골라 주세요"로 멈춘다.
  - 길: 두 곳이면 "N칸 (한쪽)", 여러 곳이면 "한 바퀴 N칸 · 가장 긴 구간 M칸". 정류장마다 충전하므로 배터리는 가장 긴 구간으로 본다.
  - "같은 노선으로 한 대 더": 노선에서 처음 들르는, 트럭을 만들 수 있는 정류장 옆에서 그 차례부터.
- 맵: 고른 트럭의 정류장마다 "1 싣기 철광석 · 3 내리기"처럼 차례와 할 일(고른 짐), 지금 가는 곳은 ▶.
- 정류장 정보창 트럭 목록: "여기서 싣기 / 여기에 내리기 / 여기서 싣고 내리기".
- 같이 하기: 노선 명령 `{ t: 'route', id, stops }` (모양이 틀리면 무시). 체크섬에 노선과 지금 정류장 번호를 넣었다. 정류장을 철거했다가 되돌리면 노선이 새 정류장에 다시 이어진다.

  - 기록은 트럭 id와 바꾸기 전·후 노선. 트럭이 철거됐다 되돌리기로 다시 생기면 새 id로 찾아간다.
  - 정류장을 철거했다 되돌려 새 id로 다시 지으면, 움직이는 트럭뿐 아니라 **되돌리기 기록 속 노선**(노선 바꾸기, 트럭 만들기·철거)의 정류장 번호도 고친다. 전에는 기록 속 노선이 없어진 정류장을 가리켜, 다시 하기로 되살린 노선이 "정류장을 골라 주세요"가 될 수 있었다.

### 석탄 독립 (2026-10-22)

문제: 철·구리는 흙에서 무한으로 얻지만 석탄은 광맥뿐이라, 석탄이 바닥나면 강철(철판 2 + 석탄 1)과 석탄 발전기가 멈춘다.
결정 (사용자 선택): **전기로 + 무한 발전**, 무한 발전은 **태양광과 수력 둘 다**. 새 아이템은 만들지 않았다.

| 건물 | 크기 | 비용 | 하는 일 |
|---|---|---|---|
| 태양광 패널 | 2×2 | 철판 10 · 회로 5 · 벽돌 5 | 넣는 것 없이 늘 100kW |
| 수력 발전기 | 2×2 | 철판 15 · 기어 10 · 벽돌 10 | 물 1개 = 300kJ, 최대 600kW (초당 물 2개 = 양수기 1대). 물 10개까지 쌓아 둠 |
| 전기로 | 2×2 | 철판 20 · 회로 10 · 벽돌 20 | 철판 2 → 강철 1 (5초), 전력 450kW. 철판이 들어오면 레시피를 스스로 고름 |

- 세 건물 모두 강철·석탄 없이 지을 수 있다 (석탄이 이미 바닥났어도 시작할 수 있게).
- 연구: **재생 에너지** (벽돌 30 · 회로 30, 선행 흙 정제) → 태양광·수력. **전기 제강** (벽돌 40 · 회로 40, 선행 흙 정제) → 전기로.
- **광맥 독립**(최종 목표)은 이제 광물 분리 + 재생 에너지 + 전기 제강을 모두 마쳐야 열린다.
- 전력 쓰는 순서: 허브 기본 300 + 태양광 (공짜) → 수력 (물) → 석탄 발전기 (석탄은 마지막까지 아낀다).
- 왼쪽 전력 칸에 "허브 300 · 태양광 N · 수력 N · 석탄 N kW" (지금 돌 수 있는 최대치).
- 수력 발전기에 물이 없으면 "물 없음". 철거하면 쌓인 물은 물로 돌려준다.
- 공장 통계에서 수력 발전기가 쓰는 물도 소비로 친다. 도감에 물 → 수력 발전기 쓰임새.
- 목표 2개 추가 ("석탄 없이 전기 만들기", "석탄 없이 강철 만들기", 최종 목표 앞).
- 툴바: 전력 탭(C) 2·3번 = 태양광·수력, 생산 탭(X) 9번 = 전기로.

### 밸런스 점검 2: 숲 들어간 뒤 (2026-10-23)

요청: "숲 들어간 뒤 처음부터 끝까지 밸런스 점검". 연구 19개의 비용을 원료·기계 시간으로 풀고 (부산물은 공짜로 치지 않고 주 결과물에 전부), 숲은 시뮬레이션으로 30분 돌려 마지막 15분을 쟀다. 숫자만 보고 아직 아무것도 바꾸지 않았다.

**연구 비용 (원료, 기계 시간)**

- 새 연구 넷은 앞뒤 연구 사이에 맞게 들어가 있다. 산림은 강철 제련(13분)과 전자 공학(17분) 사이, 고용량 배터리는 차량 운송과 비슷하다.
- 제지·숲 가꾸기는 숲 한 판(벌목기+식목기)으로 5~10분이면 모인다. 흙 정제 뒤 단계(연구마다 기계 50분 안팎)에 비하면 가볍다. 숲은 곁가지라 이 정도가 맞다고 봄.
- 연구 전부의 철광석 7,040개는 허브 근처 철광맥(약 25,000)보다 한참 적다. 지난 점검(5,900개쯤)보다 산림·배터리만큼 늘었다. 광맥이 바닥나는 압박은 연구가 아니라 공장을 키우는 데서 온다 (지난 점검과 같음).

**숲 생산 (시뮬레이션, 식목기에 묘목을 늘 채워 둠)**

| 배치 | 통나무/분 |
| --- | --- |
| 벌목기 1 + 식목기 1 (붙여 놓음) | **40** |
| 〃 + 숲 가꾸기 | 58 |
| 〃 + 숲 가꾸기 + 나무 자라기 5단계 | 60 (벌목기가 2초에 한 그루라 여기서 막힘) |
| 벌목기 2 + 식목기 1 | 50 → 숲 가꾸기 76 → 나무 자라기 5단계 111 |

- **숲-구상·숲 1차에 적은 "한 판 = 벌목기 한 대와 딱 맞는다(분당 60)"는 틀렸다.** 식목기 범위가 벌목기 범위와 일부만 겹쳐서, 숲 가꾸기 전에는 분당 40개다. 숲 가꾸기가 이 차이를 메운다 (+45%).
- **나무 자라기(끝없는)는 1:1 배치에서는 숲 가꾸기 뒤로 효과가 거의 없다** (60에서 막힘). 식목기 하나에 벌목기를 둘 붙이거나, 끝없는 "채굴 속도"로 벌목기를 빠르게 해야 효과가 난다.
- **숯 발전**: 벌목기+식목기 한 판이 분당 숯 20개(숲 가꾸기 뒤 30개) → 석탄 발전기에서 약 830kW(1,250kW). 벌목기·식목기·숯 제련로 전력을 빼면 **약 660kW(1,000kW)**. 석탄 채굴기 한 대(약 4,000kW)보다 훨씬 약하지만 끝이 없고, 강철 제련 바로 뒤부터 된다. 그래서 석탄이 바닥나는 압박은 예전보다 약하다. 최종 목표는 여전히 재생 에너지·전기 제강 연구가 있어야 열린다.
- **목재가 남는다**: 제재소는 통나무 하나에 목재 2 + 톱밥 1을 낸다. 종이 하나(톱밥 2)를 만들면 목재 4개가 남는데, 목재를 쓰는 곳은 연구 셋(제지 200, 숲 가꾸기 300, 나무 자라기 단계마다 200×1.5배)뿐이고 건물 비용에는 없다. 숲-구상의 "목재 → 다음 단계 건물 비용"은 아직 안 했다.

**그대로인 것**: 시작 재고로 첫 연구까지, 단계마다 기계 수, 흙 사슬 비용(지난 점검의 결론)은 숲과 무관해서 바뀌지 않았다.

정할 것·고칠 것은 [계획서](계획서.md) "3. 밸런스 점검 2에서 나온 것".

**고친 것: 목재 쓰는 곳** (요청 "목재가 남는 거 고쳐 줘")

| 어디 | 전 | 후 | 이유 |
| --- | --- | --- | --- |
| 식목기 | 철판 15 · 기어 10 | 철판 10 · 기어 10 · 목재 10 | 숲을 넓힐수록 목재가 든다. 제재소가 같은 연구라 처음 숲 통나무로 바로 만든다 |
| 수력 발전기 | 철판 15 · 기어 10 · 벽돌 10 | 철판 10 · 기어 10 · 벽돌 10 · 목재 20 | 그림이 나무 물레방아 |
| 연구 재생 에너지 선행 | 흙 정제 | 흙 정제 + 산림 | 목재 없이 수력을 못 짓는 일이 없게. 목표 순서도 산림이 먼저라 맞는다 |
| 끝없는 기계 속도·컨베이어 속도 1단계 | (목재 없음) | + 목재 100 (단계마다 1.5배) | 종이를 만들수록 쌓이는 목재를 끝없이 쓰는 곳 |

- 건물 둘은 한 번 쓰고 끝나는 곳, 끝없는 연구 둘은 계속 쓰는 곳. 끝없는 숲 한 단계(종이 100 → 목재 400 남음, 목재 200 씀)에서 남는 목재 200개쯤을 기계·컨베이어 속도가 한 단계씩 쓴다.

- 예전 저장: 이미 지은 건물·한 연구는 그대로. 아직 재생 에너지를 안 했으면 산림을 먼저 해야 한다 (산림은 철판 300 · 기어 150).
- 테스트 1개 추가 (목재 쓰는 곳, 목재 없으면 수력을 못 지음).

### 밸런스 점검 (2026-10-22)

**찾은 것**: 연구 비용이 너무 싸서, 공장을 거의 키우지 않아도 1시간쯤에 최종 목표까지 간다.

### 쌓기 · 창고 합치기 · 하역기 전부 (2026-10-22)

- **컨베이어 한 칸에 쌓기**: 일반 컨베이어·지하 컨베이어 2개, 고속 컨베이어 4개까지 (`BuildingDef.stack`).
  - 기계·하역기·정류장은 쌓인 결과물을 한 칸만큼 한 번에 내보낸다 (밀려 있을 때만 쌓이고, 술술 흐를 땐 하나씩).
  - 분배기·병합기·분류기는 한 칸을 통째로 들고 넘긴다. 받는 쪽이 덜 받으면 (고속 → 일반, 칸이 모자란 기계) 남은 건 그 자리에서 기다린다. 개수는 늘 그대로.
  - 쌓인 칸은 아이콘 두 개를 겹쳐 그리고, 3개부터 숫자도. 저장에는 쌓인 칸만 개수를 붙인다 (예전 저장과 같은 모양).
- **창고 합치기**: 빈틈없는 직사각형으로 붙은 창고끼리 한 창고. 가로·세로 최대 3×4 (어느 방향이든, 12개 = 2,400개, 6×8칸).
  - 위·왼쪽 창고부터 그 창고를 왼쪽 위로 하는 가장 큰 직사각형을 하나씩 묶는다 → 2+3처럼 튀어나오면 2×2만 합쳐지고 하나는 따로. 칸이 어긋나게 붙으면 안 합쳐짐.
  - 아무 칸에 넣고 아무 칸에서 꺼낸다 (넣은 칸에 쌓이고, 하역기는 묶음 앞쪽 칸부터 꺼냄). 철거하면 그 칸에 든 것만 허브로.
  - 바깥 테두리만 그려서 큰 창고 하나처럼 보이고, 가운데에 "494 / 800".
- **하역기 아이템을 안 고르면 전부**: 든 것을 종류별로 번갈아 꺼낸다 (가운데에 "전부"). 0.5초마다 앞 컨베이어 한 칸만큼 (일반 2개, 고속 4개) → 예전보다 2~4배 빠르다.

### 채팅 (2026-10-22)

- **Enter**(또는 위쪽 "채팅" 버튼)로 입력창을 열고, Enter로 보내면 메시지가 화면 아무 높이에서 **오른쪽 → 왼쪽으로 흘러가다 사라진다**. Esc는 취소, 다른 곳을 누르면 닫힌다 (쓰던 글은 남음).
- 보낸 사람 이름은 그 사람 색(커서·핑과 같은 색). 내가 보낸 건 노란 테두리.
- 위쪽 바 아래 ~ 툴바 위를 32px 줄로 나누고 (화면 높이에 따라 줄 수가 달라짐), 비어 있는 줄 중 **아무 줄(랜덤)**에 띄운다. 앞 메시지 꼬리가 화면에 다 들어온 줄이 빈 줄. 다 차 있으면 가장 먼저 비는 줄 (메시지를 미루지는 않는다). 속도는 모두 같아서(170px/초) 같은 줄에서 따라잡지 않는다.
- 같이 하면 방 안의 모두에게 (커서·핑처럼 중계 서버가 방장을 거치지 않고 바로 뿌림, 게임 진행·체크섬과 무관). 혼자면 내 화면에만.
- 한 줄 60자 (서버도 80자에서 자름). 0.4초 안에 연달아 보내기는 막음. 한글 조합 중 Enter로는 보내지 않는다.
- 지난 채팅: 입력창을 열면 위에 최근 6줄이 보인다 (30개까지 기억, 새로고침하면 사라짐). 흘러가는 걸 놓쳤을 때 다시 보려고 (2026-10-22 자율 작업에서 더함).

## 13. 성능 메모: 컨베이어

참고: [팩토리오 벨트는 아이템 자리 대신 간격을 적는다](https://ch5saeng.tistory.com/132) (FFF #82, #148, #176 정리)

- 지금 구현은 팩토리오 0.12~0.15 방식이다: 칸마다 아이템 절대 위치를 들고, 매 틱 아이템마다 앞 아이템만 보고 옮긴다. 비용은 아이템 수에 비례 (O(아이템)).
- 측정 (2026-10-21, 브라우저, 고리 모양 벨트에 계속 흐르는 상태):

  | 벨트 | 아이템 | 틱당 | 1초(60틱) |
  |---|---|---|---|
  | 2,000칸 | 4,000개 | 0.16ms | 9.6ms |
  | 10,000칸 | 20,000개 | 0.75ms | 45ms |
  | 20,000칸 | 40,000개 | 1.72ms | 103ms |

- 지금 맵(128×128)을 컨베이어로 꽉 채워도 6만 개 수준이라 틱당 3ms 안팎이다. **당장은 필요 없다.**
- 바꿀 때 (맵을 크게/무한으로 늘리거나, 2차선·지하 컨베이어를 넣을 때):
  1. 이어진 같은 종류 컨베이어를 **트랜스포트 라인** 하나로 묶는다 (기계·분배기·합류 지점에서 끊는다).
  2. 라인은 아이템 위치 대신 **간격**을 저장한다. 흐를 때는 앞 빈칸과 뒤 빈칸 두 숫자만 바꾼다 (O(1)).
  3. 출구가 막히면 붙어 선 아이템 무리 바로 뒤 간격 하나만 줄인다. 그 위치를 기억해 두고 따라간다.
  4. 그릴 때는 보이는 라인만 앞에서부터 간격을 더해 위치를 구한다.
- 현재 시뮬레이션 테스트(간격 유지, 개수 보존, 저장 후 같은 결과)를 그대로 두고 구현만 바꾸면, 두 방식이 같은 결과를 내는지 확인할 수 있다.

## 14. 픽셀아트 전환 (2026-10-22)

### 정한 것 (사용자)

- 그림은 **Claude가 전부 코드로** 그린다. 나중에 마음에 안 드는 것만 직접 그린 PNG로 하나씩 바꿔 끼운다.
- **1칸 = 16픽셀**. 팔레트는 **따뜻한 공방**: 크림색 땅, 나무·놋쇠·벽돌 기계.
- **UI도 전부 픽셀**: 갈무리 픽셀 글꼴(OFL, npm `galmuri` — 인터넷 없이 LAN에서도 됨) + 픽셀 테두리.
- 있던 애니메이션(드릴 회전, 제련로 불꽃, 물레방아, 컨베이어 흐름 등)은 그대로 둔다.

### 구조

| 파일 | 하는 일 |
|---|---|
| `src/render/pixel.ts` | 팔레트, 붓(Pen), 그림 등록·굽기(`define`/`sprite`), PNG 바꿔 끼우기. 아이템·땅·광맥·물·컨베이어·지하·도로·화살표·상태 표시·숫자 |
| `src/render/pixel-buildings.ts` | 건물(허브, 기계, 발전), 창고 조각, 정류장, 1칸 물류 상자, 트럭 |
| `src/render/renderer.ts` | 맵 그리기 (그림을 찍고 진행 막대·이름표 같은 덧그림) |
| `src/render/camera.ts` | 줌 단계 |
| `src/ui/icons.ts` | UI 아이콘도 같은 그림에서 |
| `src/style.css` | 픽셀 UI |

- **몸체는 돌리지 않는다**: 빛은 늘 왼쪽 위. 방향은 입출구 화살표(노랑 = 출구, 흰색 = 입구)로만 보인다. 컨베이어·지하 컨베이어·트럭만 방향대로 돌려 그린다.
- 2×2 기계는 **3/4 시점**: 위쪽이 윗면, 아래 10줄이 앞면. 앞면 왼쪽 크림색 **이름표**에 만드는 아이템(채굴기는 캐는 광석), 오른쪽 아래에 **진행 막대**.
- 프레임 0 = 멈춤, 1~4 = 일할 때 (전력 부족이면 반 속도). 허브는 늘 연기가 나는 4프레임.
- 창고는 묶음 가장자리 모양(위·오른쪽·아래·왼쪽) 16가지 조각을 골라 붙여서 큰 상자 하나처럼 보인다. 이름표·채운 정도는 묶음마다 한 번.
- 컨베이어 위 아이템: 2개부터 뒤에 하나 더 겹치고, 3개부터 픽셀 숫자.

### 또렷하게 보이게

- 줌은 **단계로만**: 그림 1픽셀 = 화면 0.5·1·2·3·4·5·6…픽셀 (줌 = n × 16 / 화면 배율). 휠 한 칸 = 한 단계.
- 광맥 칸은 광물마다 다른 흙색 위에 돌 (철 `#a9b3bb`, 구리 `#d6a27a`, 석탄 `#8a847b`, 돌 `#cdc6b6`, `ORE_GROUND`). 돌 개수는 칸에 남은 양 (600 이상 3개, 250 이상 2개, 그 밑 1개, 0이면 땅).
- **LOD**: 그림 1픽셀이 화면 1픽셀보다 작아지면(0.5 단계) 바닥은 칸마다 단색만 칠한다 (돌·물결 없음). 매장량이 많은 칸일수록 진하게. 지도(미니맵)도 같은 색.
  - 건물·컨베이어·트럭은 **절반 크기로 줄인 그림**(`spriteHalf`: 2×2픽셀마다 가장 많은 색, 같으면 진한 색이라 잉크 테두리가 남는다)을 첫 프레임으로 멈춘 채 그린다.
  - 컨베이어 위 아이템, 이름표 아이템, 진행 막대, 입출구 화살표, 정류장 번호, 창고 이름표·막대, 상태 표시는 그리지 않는다. PNG로 바꿔 끼운 그림도 같은 방식으로 자동으로 줄인다.
- 월드 원점을 기기 픽셀에 맞추고(`setTransform`), 아이템·트럭 위치도 그림 픽셀 단위로 맞춰 찍는다. `imageSmoothingEnabled = false`.
- 땅·광맥은 16×16칸 묶음으로 한 장씩 구워 둔다 (광맥이 줄어 돌 크기가 바뀌면 그 묶음만 다시 굽는다). 물은 물결이 움직여서 칸마다 매 프레임.
- 격자는 도구를 들고 있을 때만 옅게.

### 직접 그린 그림으로 바꿔 끼우기

1. 위 표에서 바꿀 그림의 이름과 크기를 확인한다. 개발 서버에서 `/sprites.html`을 열면 모든 그림이 움직이는 채로 나온다 (`?q=miner,belt`로 거르기, `?scale=6`으로 확대).
2. 같은 크기로 PNG를 그린다. 프레임이 여러 장이면 **가로로 이어 붙인다** (예: `miner`는 32×32 다섯 장 = 160×32).
3. `public/sprites/`에 넣는다. 파일 이름은 그림 이름에서 `:`를 `_`로 바꾼 것 (`item:coal` → `item_coal.png`, `ore:iron-ore:3:0` → `ore_iron-ore_3_0.png`).
4. `public/sprites/manifest.json`에 이름을 적는다 (그림 이름이나 파일 이름 어느 쪽이든):

   ```json
   ["miner", "item:coal", "ore_iron-ore_3_0"]
   ```

5. 새로고침. `/sprites.html` 위쪽에 "바꿔 끼운 그림: …"으로 확인할 수 있다. 목록에 없는 이름은 무시하고 코드 그림을 쓴다.

### 확인용 페이지 (개발 서버에서만)

- `/sprites.html`: 그림 목록.
- `/scene.html`: 모든 건물·컨베이어·창고 묶음·정류장·트럭을 늘어놓은 따로 만든 월드를 진짜 렌더러로 그린다. `?scale=4`, `?ghost=smelter`(미리보기), `?rates=1`, `?select=1`. 게임 저장과 상관없다.

### UI

- 글꼴: Galmuri11 12px(기본), Galmuri9 10px(작은 글씨), Galmuri14 15px(제목), 24px(도감 이름). 이 크기들의 정수 배에서만 또렷하다.
- 판: 크림색 + 3px 잉크 테두리 + 안쪽 빛·그늘 줄 + 흐림 없는 그림자. 단추는 2px, 누르면 안쪽 줄이 뒤집힌다. 둥근 모서리 없음.
