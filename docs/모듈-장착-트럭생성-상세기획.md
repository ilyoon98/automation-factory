# 모듈 설치와 분리 및 고급 트럭 생성

2026-10-27 · regional-v1 확장 설계 · [전체 검토](기획-통합정리-검토.md) · [AI 변경 명세](AI-구현-변경명세.md)

**모듈은 기계에 직접 맞닿은 창고의 실물 1개를 설치 버튼으로 장착한다.** 이 공급 방식은 사용자 채택 기준이다. 아래 설치·분리·차량 생성·실패 처리는 이번에 구체화한 첫 구현 기준이다. 연구비·설비비·제품 레시피는 [경제 기획](진행시간-경제-상세기획.md)과 [생산 기획](생산체인-상세기획.md)을 유지한다. 게임 코드 구현은 별도다.

## 1. 두 완제품의 사용과 비용

| 행동 | 실제 지불·이동 | 추가 비용·시간 | 성공 결과 |
| --- | --- | --- | --- |
| 모듈 설치 | 인접 창고군의 자동화 설비 모듈 1개 → 기계 장착 슬롯 | 없음, 명령 적용 시 설치 | 기계에 최대 1개 보관 |
| 모듈 분리 | 장착 슬롯의 모듈 1개 → 기계 위치의 현지 회수 더미 | 없음 | 실제 모듈을 다시 운송해 사용 가능 |
| 고급 트럭 조립 | 해당 정류장 내부 또는 직접 연결 창고군의 고급 트럭 조립품 1개 | 금속·회로 추가 차감 없음, 별도 조립 타이머 없음 | 새 고급 트럭 1대 |
| 고급 트럭 철거 | 차량에 포함된 조립품 1개와 실제 화물 → 현재 차량 위치의 회수 더미 | 저장 전기는 아이템으로 반환하지 않음 | 기존 기본 트럭 비용은 반환하지 않음 |

모듈 설치는 아이템을 소멸시키는 일이 아니라 창고에서 장착 슬롯으로 옮기는 일이다. 고급 트럭 생성도 조립품을 차량에 포함된 원가로 기록한다. 슬롯·차량에 포함된 원가를 창고 재고로 동시에 세지 않는다. 연구·허브 프로젝트로 이미 소비한 모듈을 다시 장착할 수 없다.

## 2. 공통 재고와 명령 원칙

1. 화면에 보였던 수량을 믿고 차감하지 않는다. 공용 시뮬레이션 명령을 적용하는 순간 대상·연구·연결·실물·출고 예약을 다시 확인한다.
2. 사용 가능량은 각 실제 보관물의 수량에서 그 보관물에 배정된 출고 예약을 뺀 값이다. 운송 중·입고 예정·기계 버퍼·회수 더미·허브 원격 재고는 공급 가능량이 아니다.
3. 예약은 실제 창고/정류장 ID와 품목별 할당 수량을 식별할 수 있어야 한다. 공유 물류 풀의 예약 총량을 보관물마다 반복 차감하지 않고, 다른 정류장의 재고를 가까운 재고로 바꿔 세지도 않는다. 창고 구조 변경 때의 예약 재계산은 [물류 규칙](물류-회수-운영규칙.md)을 따른다.
4. 입력 검사·실제 재고 차감·슬롯/차량 생성·소비 사건 기록을 한 번의 상태 변경으로 확정한다. 하나라도 실패하면 이 명령의 차감·생성·임시 예약을 모두 남기지 않는다. 다른 명령이 먼저 성공한 결과는 취소하지 않는다.
5. 같은 재료 1개를 두 사람이 동시에 요청하면 공용 명령 순서상 먼저 유효한 한 건만 성공한다. 재료가 더 있으면 서로 다른 기계/차량에 각각 성공할 수 있다.
6. 명령에 고유 ID를 두고 중복 수신은 기존 결과만 반환한다. 성공 후 같은 ID의 재전송으로 다시 차감·생성하지 않는다. 실패 뒤 다시 시도하려면 최신 상태로 새 명령을 보낸다. 자동 재시도나 재료 대기 중 선차감은 없다.
7. 화면에서는 명령 처리 중 같은 버튼의 중복 입력을 막고, 응답 뒤 실제 수량·대상을 다시 보여 준다. UI가 먼저 재고를 차감하거나 슬롯/차량을 생성하지 않는다.

명령 순서는 기존 함께 하기의 공용 틱·순서를 따른다. 벽시계·화면 프레임·클라이언트별 배열 순서를 판정에 사용하지 않는다. 동률은 저장된 ID 순으로 정한다. 내부 명령·예약 ID는 일반 화면에 노출하지 않는다.

## 3. 모듈 설치 대상과 창고 선택

- T08 통합 자동화 연구 이후, 선택 레시피를 사용하는 생산 기계만 지원한다. 기존 제련로·조립기·분쇄기·세척기·분리기·전기로·제재소 7종과 새 화학 반응기·정유소·전해로·대형 조립소 4종이다.
- 채굴기·양수기·벌목기·식목기·수액 채취기·시추기·발전기·운송/보관/배전 설비에는 설치하지 않는다. 첫 범위는 생산 기계 11종이며 대상 확대는 별도 변경이다.
- 기계 몸체와 창고 몸체가 상하좌우 테두리에서 한 칸 이상 맞닿아야 한다. 대각선·한 칸 간격·같은 전력망이라는 이유만으로 연결되지 않는다.
- 맞닿은 창고가 직사각형 창고군의 일부면 그 실제 창고군 재고를 쓸 수 있다. 같은 군의 여러 동이 닿아도 선택 목록에 한 번만 표시한다. 창고군의 크기·합치기 제한은 기존 규칙 그대로다.
- 공급은 **선택한 창고군의 실제 창고들**로 제한한다. 그 군에 연결된 다른 정류장의 내부 재고까지 사용하지 않는다. 서로 떨어진 군의 수량을 합치지 않는다.
- 여러 창고군이 닿으면 선택창에서 공급 군을 지정한다. 최초 기본값은 대표 창고 ID가 가장 작은 유효 군이며, 이후 마지막으로 선택한 유효 군을 유지한다. 전송한 명령이 실패했다고 다른 군에서 몰래 차감하지 않는다.
- 명령에는 대상 기계 ID, 접촉 창고 ID, 창고군의 구조 개정을 담는다. 구조가 바뀌었으면 최신 연결을 확인하도록 실패 처리한다. 단순 재고 증감은 실행 시 재검사한다.
- 연구·실물·연결이 유효하면 전력 부족·정지·레시피 미선택 상태에서도 설치할 수 있다. 설치 자체에는 작업 전기를 요구하지 않는다. 슬롯이 이미 차 있거나 분리 대기 중이면 추가 설치하지 않는다.

기계 일반 입출구와 독립된 정비 조작이므로 창고를 특정 소켓에 맞출 필요는 없다. 대신 몸체의 실제 인접은 필요하다. 일반 재료 입력구에 모듈을 흘려보내면 기존의 레시피 외 재료 거부 규칙을 유지한다.

대형 조립소의 여섯 입력을 모두 연결해도 장착 창고를 둘 수 있다. 몸체가 `(0,0)~(2,2)`이고 남향 출력이 `(1,3)`이면 창고 좌상단을 `(-1,3)` 또는 `(2,3)`에 두면 된다. 창고는 앞면 모서리 한 칸에 닿고 기존 여섯 입력·중앙 출력을 가리지 않는다. 첫 장착을 위해 반드시 모든 기계 옆에 창고를 지을 필요는 없으며, 경제 예시처럼 기존 인접 창고를 활용한 한 기계에서 시작한다.

## 4. 설치 성공과 현재 제작

설치 명령이 성공하면 선택 창고의 사용 가능 모듈 1개를 차감하고 슬롯에 같은 출처의 모듈 1개를 기록한다. 창고 출처는 기록용이며 설치 뒤 창고가 사라져도 장착 모듈이 사라지지 않는다.

| 설치 시 기계 상태 | 현재 제작 | 다음 제작 |
| --- | --- | --- |
| 유휴·재료 대기·레시피 미선택 | 진행 중 배치 없음 | 시작할 때 모듈 효과 적용 |
| 모듈 없이 이미 제작 중 | 기존 속도·전력으로 완료 | 시작할 때 모듈 효과 적용 |
| 슬롯에 이미 모듈 있음 | 변경 없음, 추가 설치 실패 | 기존 장착 유지 |

각 제작 배치 시작 시 그 배치가 장착 모듈을 사용하는지 기록한다. 모듈을 사용하는 배치의 제작 속도는 기존 연구 적용값 ×1.20, 작업 전력은 기존 연구 적용값 ×1.25다. 재료·산출 개수·버퍼 상한은 바꾸지 않는다. 예를 들어 기본 30초·300kW 레시피는 모듈 사용 시 25초·375kW다. 전력 부족에 따른 진행 감속은 기존 구역 규칙을 따른다.

모듈 배율은 해당 배치 동안 유지한다. 작업 중 설치했다고 진행도를 소급해 올리거나 현재 배치의 전력만 먼저 올리지 않는다. 유휴 소비도 새로 만들지 않는다. MG34는 **모듈을 사용한다고 기록한 배치의 실제 완료**로 판정한다. 슬롯만 채우거나 모듈 없이 시작한 배치가 끝난 것은 완료 조건이 아니다.

## 5. 분리와 작업 취소

| 상태 | 기본 ‘분리’ 동작 | 모듈의 실제 위치 |
| --- | --- | --- |
| 배치 없음 | 즉시 분리 | 슬롯에서 기계 좌상단 칸의 회수 더미로 이동 |
| 현재 배치가 모듈을 사용하지 않음 | 즉시 분리, 현재 제작은 계속 | 같은 현지 회수 더미 |
| 현재 배치가 모듈 사용 중 | ‘현재 제작 완료 후 분리’ 예약 | 완료까지 슬롯에 남아 해당 배치에 묶임 |
| 이미 분리 예약됨 | 추가 예약·반환 없음 | 기존 슬롯에 한 개 유지 |

분리 예약은 별도 모듈 아이템이 아니다. 완료 전 다른 기계로 옮길 수 없으며 같은 모듈을 여러 제작에 중복 적용하지 않는다. 제작 완료 때 산출과 완료 실적을 확정한 다음 슬롯의 모듈을 한 번 회수하고, 다음 배치부터는 효과 없이 시작한다. 완료·분리·다음 시작 순서를 고정한다.

분리 예약 중에는 ‘분리 요청 취소’를 제공한다. 슬롯을 그대로 유지하고 재료를 이동시키지 않는다. 전력 부족·일시 정지에서는 분리 예약과 제작 진행을 보존한다.

기다리지 않으려면 **‘작업 취소 후 즉시 분리’**를 선택한다. 현재 배치에 실제 투입한 원료와 장착 모듈만 현지 회수하고, 진행도와 출력 예약을 해제한다. 아직 투입하지 않은 입력 버퍼와 이미 완성된 출력 버퍼는 기계에 남긴다. 완제품·완료 실적을 생성하지 않으며, 이미 완료한 과거 실적을 되돌리지 않는다. 버튼에 현재 작업 취소와 원료 현지 반환을 함께 표시해 별도 추측이 필요 없게 한다.

분리기처럼 산출 순서가 있는 레시피는 완료하지 않은 배치의 취소만으로 순번을 진행하거나 다시 추첨하지 않는다. 이미 완료해 확정한 순번을 과거로 되돌리지도 않는다.

분리한 모듈은 원래 창고·허브로 원격 반환하지 않는다. 회수 더미의 모듈을 다시 설치하려면 하역기로 꺼내 인접 창고에 실제 공급해야 한다. 설치/분리용 창고 자동 입고나 플레이어 개인 인벤토리는 추가하지 않는다.

## 6. 다른 편집과의 결합

| 조작 | 처리 |
| --- | --- |
| 레시피 변경 | 기존 현지 회수 규칙으로 현재 배치와 버퍼 정리. 모듈은 슬롯 유지. 분리 예약이 있으면 작업 취소로 잠금이 풀린 뒤 모듈도 한 번 회수 |
| 기계 철거 | 실제 버퍼·투입 중 원료·슬롯 모듈을 각각 한 번 현지 회수. 분리 예약 종료. 별도 분리 사건을 뒤에 다시 실행하지 않음 |
| 공급 창고 철거·군 분리 | 설치 전 명령은 연결·실물을 재검사. 설치가 끝났으면 장착 상태 유지 |
| 회전 | 크기·슬롯·현재 모듈 배율·분리 예약 유지. 일반 입출구 방향만 기존 회전 규칙으로 변경 |
| 청사진·복사 | 건물·레시피 설정만 복사. 슬롯 아이템·제작 중 모듈 사용 표시·분리 예약을 복제하지 않음 |
| 건물 철거 되돌리기 | 동일 회수 사건에 남은 모듈이 실제로 있을 때만 기존 회수 규칙으로 복원. 이미 옮겨 쓴 모듈을 채우지 않음 |

새 설치·분리·작업 취소 명령은 첫 범위에서 일반 Ctrl+Z/다시 실행 대상에 넣지 않는다. 설치의 반대 조작은 ‘분리’, 분리 이후 재사용은 현지 배송이다. 기존 건설·설정·기본 트럭의 되돌리기는 유지한다.

## 7. 고급 트럭의 조립 장소와 재료

- T07 상위 차량 조립 이후 정류장 상세의 ‘고급 트럭 조립’으로 한 번에 한 대 만든다. 싣기/내리기 어느 모드든 가능하며 모드를 자동으로 바꾸거나 화물을 비우지 않는다.
- 공급 후보는 **선택한 정류장 자체의 내부 재고**, 그 정류장에 직접 연결한 **한 창고군의 실제 창고 재고**다. 다른 정류장의 내부·먼 창고·허브·기계·더미·입고 예정은 제외한다.
- 재료 1개를 한 실제 보관물에서 가져온다. 기본 순서는 해당 정류장 내부, 연결 창고의 ID 순이며 예약하지 않은 수량만 사용한다. 다른 정류장의 예약분은 침범하지 않는다.
- 생성 명령은 선택한 정류장 ID와 연결 설정/창고군의 구조 개정을 함께 식별한다. 화면을 본 뒤 다른 창고군으로 연결이 바뀌었으면 자동으로 새 공급원에서 차감하지 않고 최신 연결 확인 후 다시 요청하게 한다.
- 정류장 몸체에 실제 도로 칸이 한 칸 이상 붙어 있어야 한다. 현재 코드의 `stationStops`/`isRoad`와 같은 접도 기준을 쓴다. 건설 불가 지면·임의 창고 칸·충전기 몸체를 도로로 간주하지 않는다.
- 가능한 접도 칸 중 칸 번호 `y×지도폭+x`가 가장 작은 곳에 생성한다. 현재 첫 범위에는 트럭끼리 도로 충돌을 추가하지 않으므로 다른 차량이 같은 칸에 있다는 이유로 생성 실패하지 않는다.
- 도로가 인접해 있으면 목적지·노선·장거리 경로가 아직 없어도 만들 수 있다. 출발은 노선을 지정한 뒤 판단한다. 전력 부족도 조립 실패 조건은 아니다.

고급 트럭 조립품 1개 외에 기존 기본 트럭의 강철 10·기어 10·회로 5를 다시 차감하지 않는다. 기본 트럭을 업그레이드하거나 자동으로 철거하지 않는다. 기본 트럭 생성·복제는 기존 비용·기능을 유지한다.

## 8. 차량 생성의 원자적 처리와 초기 상태

1. 규칙 프로필·T07·정류장 존재·현재 창고 연결·접도·사용 가능 조립품을 다시 검사한다.
2. 차감할 실제 보관물 한 곳과 출처, 생성 도로 칸, 새 차량 데이터를 임시로 준비한다. 아직 실물·예약·차량 목록을 바꾸지 않는다.
3. 조립품 1개 차감, 고급 종류·현지 지불 원가 기록, 차량 등록, 명령 성공 결과를 함께 확정한다. 실패하면 모두 적용하지 않는다. 실패로 차량 ID 발급 순서도 진행시키지 않는다.
4. 결과에 생성된 차량 ID와 실제 차감 위치를 내부적으로 연결한다. 화면에는 새 차량 선택과 ‘노선 지정 / 충전’ 상태를 보여 준다.

새 고급 트럭의 초기 상태는 화물 0, 노선 미지정·운행 정지, 저장 전기 **0kJ**다. 기본 용량 3,600kJ·충전 400kW이며 기존 연구 배율은 차량 종류 기본값 위에 적용한다. 기본 트럭의 기존 초기 충전 규칙은 바꾸지 않는다.

새 고급 트럭은 조립한 정류장의 실제 접도 칸에 정차한 동안 노선이 없어도 그 정류장의 충전 대기열에 들어갈 수 있다. 같은 구역의 충전 예산·도착 순서/ID 배분을 사용하고, 무전력에서는 0kJ로 대기한다. 정격 400kW를 혼자 받으면 기본 완충 시간은 9초이며 경쟁·전력 부족·연구에 따라 달라진다. 노선 지정 후의 출발 에너지·20% 여유는 기존 물류 규칙을 따른다.

조립 후 정류장이 삭제돼도 차량은 현재 도로 칸에 남는다. 삭제된 정류장에서 충전하지 않으며, 노선 재지정·실제 충전 지점 이동을 제공한다. 배터리가 빈 경우의 25% 비상 주행은 유지한다. 생성 명령의 성공을 나중에 취소해 조립품과 차량을 함께 남기지 않는다.

‘고급 트럭 조립’은 일반 Ctrl+Z 대상에서 제외하고 실제 차량 철거로 현지 조립품을 회수한다. 첫 범위의 고급 트럭 생성·철거를 기본 차량 원가로 재생성하는 기존 undo 경로에 넣지 않는다. 고급 차량의 ‘노선 복제’는 설정만 복사한다. 차량을 추가로 만드는 ‘같은 노선 고급 트럭 추가’는 이 조립 명령을 다시 적용해 유효 정류장의 실제 조립품 1개를 별도 지불해야 한다. 한 조립품으로 여러 대를 복제하지 않는다.

## 9. 실패와 재시도

| 상황 | 자원·기계·차량 결과 | 화면 안내·후속 |
| --- | --- | --- |
| 연구 미완료·지원하지 않는 기계/세계 | 변경 없음 | 필요한 연구/지원 대상 표시 |
| 모듈 슬롯이 이미 참 | 창고 차감 없음 | ‘이미 설치됨’ 또는 ‘분리 대기’ |
| 창고가 닿지 않음·군 구조 변경 | 다른 창고에서 차감하지 않음 | ‘공급 창고를 다시 선택’ |
| 실물 1개 부족·다른 출고 예약 중 | 선차감·대기 예약 없음 | 실제/예약/사용 가능 수량 표시 |
| 같은 재료에 설치·적재·조립 동시 요청 | 먼저 확정한 유효 명령만 차감 | 나머지는 최신 상태로 실패 |
| 정류장 삭제·접도 없음 | 조립품 유지, 새 차량 없음 | ‘정류장이 없어요 / 정류장 옆에 도로가 필요해요’ |
| 차량 데이터 준비·등록 검사 실패 | 재고·예약·차량·ID 순서 모두 이 명령 전 상태 | 실패 사유 표시, 새 명령으로 재시도 |
| 같은 명령 재전송·연결 복구 후 중복 | 기존 결과만 응답 | 추가 설치·생성·차감 없음 |
| 원래 공급원은 삭제됐지만 이미 설치/생성 성공 | 장착 모듈·차량 유지 | 현재 대상 기준으로 관리 |
| 저장 파일 쓰기 실패 | 메모리에서 성공한 조작을 다시 실행하거나 보상 차감하지 않음 | 현재 세계를 다시 저장. 마지막 정상 저장은 전체 일관 상태로 보존 |

재고 검사 후 다른 명령이 끼어들어 차감하는 분리된 UI/API 단계로 구현하지 않는다. 확정 전 실패는 실제 재고를 건드리지 않으며, 확정 후 UI 응답이 늦어진 것은 재료 실패가 아니라 같은 결과를 다시 받는 상황이다.

## 10. 저장·함께 하기·사건 판정

- 기계의 실제 슬롯 모듈과 출처, 현재 배치의 모듈 사용 여부/배율, 분리 예약과 투입 원료를 저장한다. 슬롯과 배치의 잠금 참조를 두 아이템으로 세지 않는다.
- 차량 종류, 실제 차감한 조립품 원가·출처, 생성 정류장, 현재 도로 칸·충전 상태·노선을 저장한다. 저장에 종류가 없는 기존 차량은 기존 기본 트럭으로 읽는다.
- 공용 명령의 처리 번호와 중복 방지 상태를 저장한다. 과거 모든 명령 로그를 무한히 보관하는 대신, 처리한 번호의 재적용을 막는 기준과 필요한 최근 결과를 보관한다. 중간 참가도 이미 확정된 슬롯·차량·소비를 복원할 뿐 생성 명령을 다시 실행하지 않는다.
- 명령을 먼저 적용하고 제작을 진행한다. 분리 예약의 완료 처리는 그 배치 완료 사건 안에서 한 번 수행한다. 같은 틱의 철거·레시피 변경은 실제 적용 순서대로 현재 상태를 검사한다.
- 모듈 설치/분리·회수·차량 생성은 새 제품의 제작 실적이 아니다. MG30은 실제 P22 완료, MG31은 생성된 고급 트럭의 실제 배송 20개, MG34는 모듈을 사용하는 배치 완료, MG36은 허브 프로젝트의 실제 모듈 소비로 판정한다.
- 슬롯·현재 배치·회수 사건이 모순되는 손상 저장을 발견하면 자동으로 아이템을 추가해 맞추지 않는다. 불일치 진단과 정상 백업 복구 경로를 제공한다. 기존 세계의 규칙을 자동으로 확장 모드로 바꾸지 않는다.

## 11. UI의 최소 구성

기계 상세의 ‘설비 모듈’에는 `미설치 / 설치됨 / 다음 제작부터 적용 / 제작 완료 후 분리`를 표시한다. 공급 창고 선택, 실물·출고 예약·사용 가능 수량, 속도/작업 전력 배율과 현재 배치 적용 여부를 보여 준다. 가능한 상태에 맞춰 `설치 / 분리 / 분리 요청 취소 / 작업 취소 후 즉시 분리`를 제공한다. 현재 배치 진행과 원료 반환 여부를 버튼 옆에서 확인할 수 있게 한다.

정류장 상세는 기본 트럭 구매와 고급 트럭 조립을 구분한다. 고급에는 `현지 조립품 1개`, 실제 사용 가능한 수량, 접도 상태와 `고급 트럭 조립`을 표시한다. 성공 후 생성 차량을 선택하고 노선과 충전 상태를 보여 준다. 연구·자원 부족·연결 실패를 전부 ‘재료 부족’으로 뭉뚱그리지 않는다. 버튼 처리 자체에 추가 승인창을 붙이지 않는다.
