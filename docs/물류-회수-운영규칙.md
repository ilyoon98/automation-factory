# 현지 화물 회수와 다품목 운송 운영 규칙

2026-10-27 · [통합 기획](기획-통합정리-검토.md) · [지역 인프라](지형-운송-전력-상세기획.md) · 미구현 상세 설계

**건설 원가는 허브로 환급하되, 실제 화물은 있던 장소에 남긴다. 트럭은 필요한 품목과 받을 공간을 예약하고, 부족한 품목 때문에 다른 배송까지 무한정 기다리지 않는다.** 아래는 첫 구현을 위한 규칙안이며 수량·처리 시간은 시제품에서 검증한다.

## 1. 서로 다른 세 종류의 반환

| 대상 | 돌아가는 곳 | 실적 처리 |
| --- | --- | --- |
| 건설 때 지불한 원가 | 기존처럼 공용 허브 재고 | 생산·배송·프로젝트 납품으로 세지 않음 |
| 기계·벨트·창고·정류장·차량 안의 실물 | 실제 있던 위치의 현지 회수 더미 | 원래 생산 출처 보존, 새 생산·배송으로 세지 않음 |
| 설치한 설비 모듈 | 설비가 있던 위치의 현지 회수 더미 | 제작 실적 추가 없음. 다시 실제 운송해 사용·납품 가능 |

건설 원가 환급은 건물을 지을 때 실제 차감한 원가만 반환한다. 기본 트럭처럼 허브에서 지불한 원가는 허브로 돌려주고, 고급 트럭처럼 현지에서 조립품을 소비한 경우 그 조립품은 현재 차량 위치의 현지 회수 대상으로 돌린다. 고급 트럭에서 기본 트럭 비용까지 함께 반환하지 않는다. 원가 반환은 새 생산 사건이 아니다.

모듈 설치·분리와 고급 차량 생성은 [사용 계약](모듈-장착-트럭생성-상세기획.md)을 따른다. 설치는 실제 인접 창고군의 모듈 1개를 슬롯으로 옮기며, 생성은 해당 정류장 내부/직접 연결 창고의 조립품 1개만 사용한다. 두 조작도 실제 보관물에 배정된 출고 예약을 침범하지 않는다. 공유 풀의 예약을 실제 창고/정류장별 할당으로 추적해 가까운 대상의 사용 가능량을 계산하고 같은 예약을 여러 군에 중복 차감하지 않는다.

2026-10-30 실제 작업본의 수동 회수는 클릭한 칸의 더미를 가까운 창고·정류장의 남은 공간으로 옮기고, 대상이 없거나 공간이 모자라면 나머지를 허브에 넣는다. 이전의 ‘클릭으로 허브 재고를 늘리지 않음’ 규칙을 현재 구현에 맞춰 대체한다. 회수 자체를 새 생산·정상 배송·프로젝트 납품 실적으로 더하지 않는다.

## 2. 현지 회수 더미

### 위치와 용량

- 빈손 클릭은 같은 칸의 회수 더미를 설비보다 먼저 고른다. 컨베이어와 겹친 바닥 물건도 회수하며, 그 컨베이어에서 운반 중인 화물은 그대로 둔다. 마우스에는 회수 손·더미 상자의 초록 테두리·실제 품목과 수량을 표시한다. 화면 이동 드래그나 다른 편집 조작을 하면 수거하지 않는다.
- 건물은 원래 좌상단 칸, 벨트는 해당 칸, 차량은 명령을 처리하는 틱의 실제 도로 칸에 생성한다. 차량의 출발지나 마지막 정류장으로 원격 이동시키지 않는다.
- 더미는 충돌 없는 지면 표식이다. 건설·도로·벨트를 막지 않고, 같은 칸의 더미는 목록을 합쳐 보인다. 새 건물 아래에 가려져도 물류 보기의 회수 표식으로 선택할 수 있다.
- 편집으로 생긴 전량을 받아야 하므로 첫 범위에서는 강제 생성량을 잘라 버리는 용량 제한·소멸 시간을 두지 않는다. 같은 칸은 품목·출처별 합계로 저장한다.
- 더미에는 벨트·트럭·수동 명령으로 새 물건을 입고할 수 없다. 회수·반송 처리로 생긴 화물만 들어가며 빈 더미는 제거한다. 정상 운송의 목적지나 일반 창고로 지정할 수 없다. 표시와 재고 합계는 합치되 되돌리기용 사건별 잔량은 별도로 유지하고, 꺼낼 때 먼저 생긴 회수분부터 감소시킨다.
- 더미를 옮기거나 ‘모두 허브로 회수’하는 기능은 없다. 물건을 빼는 동안에도 그 칸의 보관량에서 실제로 감소한다.

강제 회수물의 손실 방지를 우선한 결정이다. 장기 방치량과 성능은 시제품에서 점검하되 저장 용량 제한으로 물건을 삭제하지 않는다.

### 다시 꺼내는 방법

기존 하역기를 인접한 칸에 놓고 입력 대상을 ‘현지 회수 더미’로 선택한다. 기본 2개/초, 소비 전력 0으로 기존 하역 속도를 따른다. 반대쪽 벨트·창고·정류장으로 실제 출력한다. 한 칸에 건물과 더미가 함께 있으면 입력 대상 선택에 둘을 구분한다. 출력이 막히면 그 더미에 그대로 보관한다.

품목 필터를 설정할 수 있고, 필터가 없으면 품목을 순환해 꺼낸다. 필요한 물건이 적게 남은 품목 뒤에서 영원히 대기하지 않게 한다. 더미가 비면 하역기는 ‘회수 완료’ 상태가 되며 같은 위치의 다른 건물 재고를 임의로 꺼내기 시작하지 않는다.

물류 보기에는 `회수 대기 3곳 · 74개`처럼 표시한다. 선택하면 품목별 수량·발생 이유·위치·연결 가능한 출구를 보여 준다. 더미의 화물은 현지 물류 풀의 재고나 배송 가능량에 자동 합산하지 않는다.

## 3. 조작별 회수 결과

| 조작·상황 | 처리 |
| --- | --- |
| 기계 철거 | 건설 원가만 허브 환급. 입출력 버퍼·설치 모듈·아직 소비하지 않은 연료는 현지 회수 |
| 제작 중 철거·레시피 변경 | 제작 시작 때 실제 차감했던 입력을 한 번 반환. 작업 진행률은 취소하고 완제품을 생성하지 않음 |
| 레시피 변경 | 기존 입출력 재고와 취소한 투입물을 현지 회수한 뒤 새 레시피를 선택. 건설 원가는 반환하지 않음 |
| 정류장 싣기/내리기 변경 | 해당 정류장의 내부 화물만 현지 회수. 연결 창고까지 비우지 않음. 진행 중 예약은 아래 운송 규칙으로 정리 |
| 정류장·창고 철거 | 철거한 실물 안의 수량만 회수. 다른 창고의 물건을 복제하거나 원격 합산하지 않음 |
| 벨트·분배기·하역기 철거 | 실제 들고 있던 아이템과 개수만 해당 위치에 회수 |
| 차량 철거·화물 내려놓기 | 화물은 현재 차량 칸에 회수하고 해당 운송 예약을 종료. 화물을 하역해도 차량 자체는 남기는 조작 제공 |
| 발전기·축전기 철거 | 미사용 실물 연료·건설 원가만 반환. 이미 전기로 전환한 연료나 저장 에너지를 새 아이템으로 만들지 않음 |
| 회수 더미 위에 재건설 | 새 건물은 빈 버퍼로 시작. 더미를 자동 흡수하지 않으며 하역기로 다시 공급 |
| 영역 철거 | 각 위치에서 회수. 구역 중심 한 곳이나 허브에 몰아 놓지 않음 |

같은 틱에는 공용 편집 명령을 먼저 처리한 후 제작을 진행한다. 명령을 처리할 때 이미 완료된 작업이면 출력만 회수하고 입력은 다시 반환하지 않는다. 아직 제작 중이면 저장된 시작 투입물만 반환한다. 적용된 회수 사건을 저장·재접속·중간 참가에서 다시 실행하지 않는다.

### 되돌리기

되돌리기는 배치·설정을 되돌리는 기능이며 이미 일어난 생산·배송·연구·허브 납품을 과거로 돌리지 않는다.

철거 되돌리기는 필요한 원가를 다시 지불하고 원래 자리에 건물을 복원한다. 같은 회수 사건으로 남은 물건이 그 자리에 그대로 있으면 버퍼 한도 안에서 재입고할 수 있다. 이미 하역기로 꺼낸 물건은 복제해 채우지 않으며 부족한 상태로 복원한다. 제작 진행률은 0부터 시작한다. 설치 모듈도 해당 회수분이 남아 있을 때만 재설치한다.

현재 장소가 막혔거나 건설 원가가 부족하면 이유를 보여 주고 그 되돌리기를 적용하지 않는다. 영역 편집 되돌리기는 필요한 위치·원가를 먼저 검사해 편집 한 단위로 적용한다. 이 과정에서 다른 플레이어가 이미 운송한 수량·달성 기록을 취소하지 않는다.

## 4. 다품목 운송의 첫 범위

새 혼합 화물 노선은 기본적으로 싣기 정류장 1곳과 내리기 정류장 1곳을 연결한다. 돌아올 때는 빈 차다. 기존 2~8정류장 노선은 보존하지만, 첫 혼합 화물 노선에서 다중 목적지·회송 합승까지 함께 자동 계획하지 않는다. 반송은 아래의 예외 처리로만 제공한다.

정류장에는 `연결 창고`를 하나 지정할 수 있다. 직접 맞닿은 기존 창고 그룹만 선택하며, 멀리 있는 창고나 같은 전력망 전체의 재고를 공유하지 않는다. 이 직접 접속·예약 조회는 **새 확장 기능**이며 현재 코드가 이미 지원한다는 뜻이 아니다.

연결 창고가 없으면 정류장 단독 재고를 사용한다. 연결한 경우 창고 그룹과 그 그룹에 직접 연결한 정류장들을 하나의 ‘물류 보관 풀’로 집계한다. 같은 창고를 정류장 둘이 참조해도 재고와 빈 공간은 한 번만 센다. 입력/출력 화물은 실물 위치에 남고 정류장 접속으로 실제 이동해야 한다. 차량 작업은 정류장당 합계 10개/초, 창고 접속을 포함해 그 작업량을 중복 사용하지 않는다.

트럭의 작업은 인접 연결 창고에서 차량으로, 또는 차량에서 인접 연결 창고로 이어지는 **한 번의 도킹 이동**이다. 같은 화물이 반드시 정류장 버퍼를 거쳐 두 번 이동해야 하는 설계는 아니다. 도킹이 10개/초인 동안 별도 창고 이동을 같은 설비의 추가 10개/초로 더하지 않는다. 연결된 정류장마다 실제 작업 자리·10개/초 한도는 따로 있지만 같은 원천 재고·빈 공간의 예약은 공유한다.

연결 창고는 기존 직사각형 그룹·칸당 용량 규칙을 따른다. 다른 그룹으로 연결을 바꾸거나 그룹을 분리·병합하면 관련 미적재 예약을 취소하고 다시 계산한다. 적재된 화물의 예약도 새 보관 구조에 유효한지 확인하고, 수용할 수 없으면 반송 처리한다.

## 5. 플레이어가 설정하는 값

| 설정 | 의미와 기본값 |
| --- | --- |
| 적재 품목 | 허용할 여러 품목. 아무 품목이나 무제한으로 싣는 설정은 혼합 계획과 구분 |
| 품목별 1회 상한 | 차량 한 대가 한 편에 싣는 최대량. 모든 상한의 합은 차량 적재량 이하 |
| 목적지 목표 재고 | 그 물류 풀에 보관하고 싶은 품목별 수량. 정상 요청은 목표에 부족한 만큼 |
| 운행 방식 | 정기편 120초 기본, 기존 방식인 새 짐 없이 5초 후 출발도 선택 가능 |
| 조기 출발 | 기본 끔. 켜면 할당 화물과 주행 전기가 준비된 경우 먼저 출발 |
| 차량 수·간격 | 같은 노선의 차량은 주기/대수로 분산. 배터리 준비 지연 시 지연 이유 표시 |

상한 20·20·10으로 설정한 기본 트럭은 한 품목이 부족해도 다른 품목의 상한을 임의로 늘리지 않는다. 빈자리를 항상 채우려다 중요한 품목이 밀려나는 일을 피한다. 합계가 50을 넘는 설정은 부족량을 표시하고 적용 전에 조정하게 한다. 자동 비율 축소·자동 품목 삭제는 하지 않는다.

목적지 품목별 목표 재고 합계가 물류 보관 풀 용량보다 크면 ‘목표 재고가 현지 용량보다 큼’을 표시한다. 운영 자체를 금지하지 않지만 모든 목표를 동시에 보관할 수 있다고 보장하지 않는다. 실제 예약은 언제나 남은 물리 용량 안에서 하며, 품목별 공정성을 위해 예약 요청의 품목 순서도 순환한다.

차량 연구나 종류 변경으로 실제 적재량이 줄면 기존 화물은 보존하고 추가 적재를 막는다. 다음 편 계획을 실제 용량에 맞추기 전에는 새 운행을 시작하지 않는다.

## 6. 요청과 예약

품목별 새 요청량은 다음과 같다.

`부족량 = max(0, 목표 재고 - 실제 보관량 - 입고 예약 잔량)`

입고 예약 잔량에는 적재 중 배정분과 실제 운송 중 화물을 모두 포함하되 같은 화물을 두 번 더하지 않는다. 회수 더미·기계 내부·먼 창고·생산할 예정인 물량은 실제 보관량에 넣지 않는다. UI는 ‘현재 20 · 입고 예정 10 · 목표 40 · 추가 요청 10’으로 나눈다.

### 예약 절차

1. 차량이 실제 적재 차례가 됐을 때 출발지의 예약하지 않은 재고, 목적지 부족량과 빈 공간을 조회한다. 경로와 목적지의 유효성도 검사한다.
2. `이번 편 상한·출발지 가용량·목적지 부족량·목적지 예약 가능 공간·차량 여유` 중 작은 만큼만 양쪽에 함께 예약한다. 아직 생산하지 않은 물건을 먼저 잠그지 않는다.
3. 같은 품목의 경쟁 요청은 먼저 요청한 차량부터 처리하되, 한 개 단위로 순환 배분해 한 차량이 전부 선점하지 않게 한다. 동률은 공용 명령의 고정 순서를 사용한다. 예약이 없던 새 생산분도 같은 대기 순서를 따른다.
4. 적재할 때 출발지 실물·출발지 예약을 줄이고 차량 실물을 늘린다. 목적지 예약은 그대로 둔다. 적재 종료 때 싣지 못한 예약은 즉시 해제한다.
5. 하역할 때 차량 실물·목적지 예약을 줄이고 목적지 실물을 늘린다. 예약에서 실물로 전환되는 것이므로 추가 요청량이 순간적으로 튀지 않는다.

목적지의 빈 공간은 모든 입고 예약 수량을 뺀 뒤 계산한다. 벨트·다른 하역기 등 외부 입고도 예약한 공간을 침범하지 않는다. 출발지의 다른 출고·하역기도 예약된 수량을 꺼내지 않는다. 두 장소의 조회·예약은 같은 시뮬레이션 명령 안에서 함께 적용하고, 한쪽만 실패한 예약은 남기지 않는다.

예약은 화물이 아닌 권리 표시다. 재고·화물·회수·소비의 합계에 예약 수량을 다시 더하지 않는다. 실제 싣기 전의 물건은 출발지에, 실은 뒤에는 차량에 한 번만 존재한다.

### 예시

모터 목표 40개, 실제 20개, 다른 차량의 입고 예정 10개면 새 요청은 10개다. 이번 차량 상한이 20개라도 10개만 예약한다. 다른 노선도 같은 목적지 풀을 보므로 동시에 20개씩 추가 발송하지 않는다.

기본 트럭의 상한을 모터 20·케이블 20·배터리 10으로 정했고 모터 재고가 6개라면 나머지 조건이 충족될 때 `6+20+10=36개`를 실어 출발한다. 모터를 기다리느라 케이블·배터리까지 멈추지 않는다.

## 7. 적재·출발·하역 시간

정기편은 출발 예정 10초 전부터 적재 차례를 받을 수 있다. 일찍 도착한 차량은 정류장 밖 논리 대기열에서 기다리며 작업 자리를 점유하거나 화물을 미리 예약하지 않는다. 충전 예산의 대기는 적재 차례와 구분한다. 정류장별 화물 작업 자리는 한 대가 사용하고 기다리는 차량은 도로를 막지 않는다.

화물 적재 작업은 한 번에 최대 10초다. 계획량을 다 싣거나 한계에 도달하면 미적재 예약을 해제한다. 정기편은 예정 시각에 준비된 화물로 출발하고, 늦게 적재 차례를 받은 차량은 끝나는 대로 출발한다. 기존 방식은 새 짐 없이 5초 또는 최대 적재 작업 10초에 출발 준비로 넘어간다. 적재 중 뒤늦게 생긴 재고를 더 받을 때도 품목 상한·수요·공간 예약을 다시 확인한다.

차량은 다음 충전 지점까지의 실제 거리 전기와 배터리 용량 20% 여유를 확보해 출발한다. 충전 준비가 늦으면 적재가 끝나도 ‘충전 대기’이며 화물과 목적지 예약을 유지한다. 차량은 화물 작업 자리에서 빠져 다른 차량이 적재할 수 있게 한다. 첫 범위에서 트럭끼리의 도로 충돌은 새로 만들지 않는다.

수요가 없어 빈 편이면 주기만 넘기고 출발하지 않는다. 요청은 있지만 재료가 없어 빈 편인 경우에도 ‘출발지 재료 부족’으로 남기고 빈 왕복을 하지 않는다. 소수 분배 잔여는 0 이상 1 미만만 이월한다. 놓친 편의 정수 물량을 무한 부채로 쌓거나 재개 직후 한꺼번에 예약하지 않는다.

도착하면 품목을 순환 하역한다. 한 품목이 막혀도 수용 가능한 다른 품목은 먼저 내린다. 작업 시작 뒤 최대 10초 또는 모든 잔여 품목에서 5초간 하역이 없으면 남은 화물은 반송으로 바꾸고 작업 자리를 비운다. 대기열에서 기다리는 시간은 이 하역 제한 시간에 포함하지 않는다. 정상 예약 공간이 유지됐다면 포화 없이 내릴 수 있어야 한다.

## 8. 예외와 반송

| 상황 | 현재 화물·예약·다음 행동 |
| --- | --- |
| 한 품목만 부족 | 확보한 품목만 배송. 없는 품목의 공간을 다른 품목이 임의로 차지하지 않음 |
| 모든 재료 부족 | 새 예약 없이 출발지 대기. 다음 편/기존 대기 규칙에 맞춰 다시 요청 |
| 목적지 목표 재고를 이미 충족 | 새 요청 0. 빈 편은 생략하고 기존 적재분의 계약은 유지 |
| 다른 차량·벨트가 먼저 입고 | 예약 공간을 침범하지 않으므로 새 요청만 감소. 예약하지 않은 물량의 입고는 남은 공간까지만 |
| 목적지에 일부만 하역 가능 | 가능한 품목·수량만 실제 배송 처리. 나머지 예약을 해제하고 원래 출발지로 반송 |
| 목표 재고·허용 품목 변경 | 미적재 예약은 재계산. 이미 실은 기존 계약은 한 번 완료한 뒤 새 설정 적용. 기존 입고 예정량을 UI에 남김 |
| 노선 끝점 변경 | 이미 실은 화물은 기존 목적지까지 한 번 배송. 빈 차가 된 뒤 새 끝점 적용 |
| 출발 정류장 삭제 | 아직 안 실은 예약 해제. 이미 출발한 차량은 유효한 목적지까지 기존 배송 가능 |
| 목적지 삭제·모드 변경 | 해당 목적지 계약 종료, 예약 해제. 남은 실물은 출발지로 반송하고 삭제된 곳에 배송 실적을 만들지 않음 |
| 연결 창고 변경·용량 감소 | 미적재 예약 재계산. 기존 적재분의 공간을 유지할 수 없으면 반송으로 전환 |
| 도로 단절 | 대체 경로를 고정 순서로 재탐색. 없으면 현재 칸에서 화물을 보존하되 해당 입고 예약은 해제해 먼 목적지 공간을 영구 잠그지 않음. 복구 후 실제 잔여 화물을 기준으로 다시 예약 |
| 배터리 소진 | 기존 25% 비상 주행. 화물을 없애거나 허브로 반환하지 않음 |
| 차량·노선 삭제 | 차량 삭제는 현지 회수. 노선만 삭제하면 새 편은 멈추고 실은 화물은 기존 배송 또는 반송까지 정리 |
| 노선 일시정지 | 새 적재·새 편을 중지하고 아직 안 실은 예약을 해제. 이미 실은 화물은 한 번 배송/반송한 뒤 빈 차로 대기 |
| 출발지와 목적지 모두 삭제 | 현재 위치 대기. 새 유효 목적지로 실제 운송하거나 ‘화물 내려놓기’로 현지 회수 선택 |
| 저장·중간 참가 | 현재 실물과 예약·개정·대기 순서를 함께 복원. 접속이 새 요청·새 하역 사건이 되지 않음 |

반송은 실물 차량이 출발 정류장으로 돌아와 실제로 내리는 동작이다. 정상 혼합 노선은 싣기/내리기 정류장을 구분하되, **자신이 보낸 화물의 반송에 한해 싣기 정류장도 반환을 받는 예외**를 둔다. 새 확장 기능이며 일반 회송 합승과 다르다.

출발 보관 풀에 공간이 있으면 반환하고, 남은 반송분은 그 정류장 위치의 회수 더미에 작업 속도 안에서 내린다. 공간 부족 때문에 차량이 영구적으로 정류장을 점유하지 않게 한다. 반송은 정상 배송·새 생산·새 수요 이행 실적이 아니다. 반송할 출발 정류장도 없어졌지만 이전 도로 칸까지 갈 수 있으면 그 자리의 회수 더미에 내린다. 경로까지 없으면 현재 칸에 대기하고 재지정·현지 회수를 제공한다.

잔여 화물은 비울 때까지 새 화물과 섞어 싣지 않는다. 반송 도중 새 목적지를 선택하면 기존 예약을 종료한 뒤 새 목적지의 품목 수요와 공간을 예약하고 실제로 운송한다. 새 목적지 입고는 유효 실수요를 충족한 양만 배송으로 기록한다. 같은 화물의 반복 왕복은 신규 실적으로 부풀리지 않는다.

경로 복구 후 원래 목적지에 전량을 다시 예약할 수 있으면 배송을 이어 간다. 일부만 예약되면 그 양을 배송하고 잔여는 반송한다. 요청 자체가 사라졌다면 바로 반송한다. 재연결 대기 중의 기존 화물은 새 편의 적재로 세지 않으며, 취소·해제된 예약을 복원했다고 가정하지 않는다.

## 9. 설정 변경과 UI

설정 화면에는 출발지 재고·다른 출고 예약·이번 편 예정량·운송 중·목적지 현재량·입고 예정·목표를 구분한다. 플레이어가 조작하는 것은 품목·상한·목표·주기이며 예약은 자동이다. 내부 예약 ID나 판정 버전을 일반 화면에 노출하지 않는다.

계획 변경 시 ‘운송 중인 모터 10개는 기존 목적지에 배송 후 적용’처럼 실제 영향을 표시한다. 목표·필터 변경과 정류장 모드 변경의 차이도 구분한다. 여러 필드를 고친 뒤 ‘계획 적용’ 한 번으로 검증해 합계 초과·없는 정류장·같은 끝점·접근 불가능한 경로를 표시한다. 정상 완료 누적과 과거 메달은 지우지 않는다.

대표 상태 문구는 `수요 충족 / 출발지 재료 부족 / 적재 차례 대기 / 충전 대기 / 하역 공간 부족 / 반송 중 / 경로 단절 / 현지 회수 대기`다. 원인이 다를 때 모두 ‘물류 부족’으로 뭉뚱그리지 않는다.

## 10. 저장과 구현 검증

실물 수량, 생산 출처, 회수 발생 사건, 실제 예약 수량, 차량의 현재 계약·새 계획, 소수 잔여, 게임 시간 기준 작업 경과, 대기 순서를 저장·동기화한다. 예약은 취소·하역·반송·편집에서 한 번만 해제한다. 구조 변경 후 예약 합계가 실제 수량과 공간을 넘지 않는지 검사한다.

검증 시나리오는 다음과 같다.

- 제작 직전·직후 철거, 입력 없는 레시피 변경, 회수 뒤 되돌리기에서 원료와 출력이 중복 생성되지 않는다.
- 이미 회수한 모듈을 실제 허브에 납품하면 한 번만 차감·기록하고, 더미 생성 자체는 납품이 아니다.
- 서로 다른 차량·노선이 같은 풀의 마지막 모터와 마지막 빈 공간을 동시에 예약해도 각각 실제 수량 이하이다.
- 한 품목의 재고 부족·목적지 포화가 다른 품목을 영구 정지시키지 않는다.
- 적재 10초, 하역 10초, 정기편 시각 경계에서 최종 한 개의 이동을 먼저 확정하고 종료를 판정한다.
- 29.6개 같은 소수 계획은 장기 배분이 맞고, 누락된 편이 재개 후 무제한 적재 요구가 되지 않는다.
- 정류장 삭제·모드 변경·창고 분리·차량 삭제·도로 단절·반송 중 저장 후에도 화물과 예약이 일치한다.
- 두 플레이어의 같은 틱 편집·되돌리기와 중간 참가가 물건 복제·삭제·실적 중복을 만들지 않는다.

이 문서는 동작 규칙을 구체화한 단계다. 실제 연결 칸·회수 하역기 선택 조작·예약 공정성·물류 처리량·멀티플레이 성능은 시제품 검증이 필요하다.
