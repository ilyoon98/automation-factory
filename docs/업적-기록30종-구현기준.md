# 기록 업적 30종의 항목·수치·구현 기준

2026-10-27 · [업적 전체](업적-확장기획서.md) · [AI 작업 명세](AI-구현-변경명세.md)

**누락됐던 기록 30종을 구현할 수 있도록 정한 첫 기준안이다. 이전 구현의 ID·수치를 복원한 표가 아니다.** 기존의 ‘누적 17·속도 6·공장 7’ 구성을 채우며, 별도 30종을 추가해 전체 업적 수를 늘리지 않는다. 총 후보는 계속 116계열·290기록이고 이 문서가 담당하는 부분은 30계열·120메달이다. 수치는 플레이 테스트 전 초기값이며 게임 코드 적용과 달성 기록 생성은 별도다.

구현 AI는 아래 값을 첫 적용값으로 사용한다. ‘항목별 기준값이 없어서 기록 30종 전체를 보류’하지 않는다. 필요한 생산·전력·식재 사건을 연결하면서 기능별 활성 규칙을 적용한다. 최초·심화·숨은 업적의 조건은 [전체 업적 기획](업적-확장기획서.md)을 따른다.

## 1. ID와 메달

- REC01~REC30은 문서 식별자다. 저장 ID는 아래 표의 `record-v1/…` 문자열을 사용한다. 레시피·노선의 R01 같은 ID와 섞지 않는다.
- 모든 행은 동·은·금·다이아의 4단계다. 표의 네 수치는 각각 해당 메달의 `이상(>=)` 기준이다. 한 사건으로 여러 기준을 넘으면 모두 지급하고 알림은 한 번으로 묶는다.
- 지급한 메달과 최고 기록은 감소하지 않는다. 업적은 허브 최종 납품의 선행 조건이 아니며, 일정 효율을 연속 유지할 필요가 없다.
- 메달은 기록·완료 도장만 제공한다. 재료·속도·전력 보너스와 신규 보상 외형은 추가하지 않는다.

## 3. 생산 속도 6종

### 측정 창과 저장

1. 게임 시간의 정수 초마다 완료된 1초 버킷을 닫는다. 시각 t의 Q60은 `[t−60,t)`에 포함된 60개 버킷의 합이다. 정확히 t에 발생한 완료 사건은 다음 버킷에 넣는다. 실제 산출 사건은 한 버킷에만 더한다.
2. 집계를 처음 시작한 뒤 60초가 지나야 판정한다. 10초 생산량을 6배 해 분당 속도로 표시하거나 지급하지 않는다. 준비 중에는 ‘측정 중 10/60초’로 표시한다.
3. 품목별 60개 정수 버킷·현재 버킷·시각·측정 시작 시각·최고 Q60을 저장/스냅샷/체크섬에 포함한다. 1배·2배·4배속 모두 같은 게임 시간 창이다. 일시정지 중 창은 진행하지 않는다.
4. v1 저장의 창은 불러오기와 중간 참가에서 그대로 이어 간다. 최고 기록도 보존한다. 창이 없는 이전 저장은 집계 시작 후 60초를 새로 측정하며, 재고에서 과거 속도를 추정하지 않는다.
5. Q60이 60→59로 내려가도 얻은 메달·최고 Q60은 유지한다. UI에는 ‘현재 최근 60초 / 최고 / 다음 기준’을 구분한다. 레시피·기계 교체가 공장 전체의 정상 생산 이력을 지우지 않는다.

### REC24~26 전력

- 이 세 기록의 ‘작업’은 실제로 소비한 생산·채취·가공·식목 등 설비 작업이다. 허브 무료 전력, 발전기 명목 출력, 미사용 출력, 차량/기계/축전기의 충전, 송전 손실, 축전기 방전은 제외한다. 저장 후 방전한 에너지는 이 세 기록에 다시 더하지 않는다. 축전 활용은 기존 D09·H07 등 별도 업적에서 다룬다.
- [전력망 개정](전력망-연결-독립시작-개정.md)에 따라 발전원별 **실제 출력**을 기준으로 연결 망의 전원 비율을 구하고 최종 작업 소비량에 배분한다. 허브·축전기 기여도 비율의 분모에는 남겨 둔 뒤 비대상 기여만 빼야 한다. 허브가 300kW, 풍력이 100kW를 실제 공급하고 작업 소비가 200kW라면 풍력 작업 기여는 50kW다. 허브가 있다는 이유로 풍력 기여를 0으로 만들거나 작업 200kW를 전부 풍력으로 세지 않는다.
- 공통 망의 발전원 구성으로 최종 소비처에서 한 번 센다. 중간 전봇대·발전기 출력·소비처에 각각 더하지 않는다. 선로 방향/손실은 없으며 축전 충전 손실은 유지한다. 공급원 기여를 알 수 없는 값으로 추정 지급하지 말고 공통 전력 계측을 먼저 연결한다. 별도 업적용 공급 우선순위를 만들어 실제 전력 운영을 바꾸지 않는다.
- REC24는 완료된 게임 시간 1초에 공급한 대상 에너지 J를 1,000으로 나눈 평균 kW다. 한 번 기준을 넘으면 지급하고 별도 유지 타이머는 없다. 예: 1초에 500,000J이면 동메달이다. 그 1초의 전반에 1,000kW·후반에 0kW여도 평균 500kW로 인정한다.
- REC25는 소비 시점의 하루 위상 `0.7 <= phase < 0.9`를 사용한다. 하루 720초에서 각 날짜의 `[504,648)`초다. 여러 날의 실적을 합산하며 해가 뜨거나 전력이 끊겨도 초기화하지 않는다. 밤 한 번에 전부 달성할 필요가 없다.
- REC26은 **발전기 중심 칸**의 폭풍 전환 20초가 끝난 구간에 발생한 직접 풍력 기여를 센다. 카메라가 폭풍 지역을 보고 있다는 이유로 다른 곳의 풍력을 세지 않는다. 이 행은 별도 조건이므로 업적 공통 규칙의 날씨별 60초 확인을 추가로 요구하지 않는다. 서로 다른 폭풍·풍력 발전기의 실적을 합산하며 폭풍 종료 후에도 보존한다.
- 시뮬레이션 틱에 적용된 실제 날씨·낮밤 상태로 사건을 태깅한다. UI 보간 날씨는 사용하지 않는다. 누적 에너지는 정수 J와 남은 소수 J를 저장해 합산 오차를 누락하지 않으며, MJ는 표시/기준 변환 단위다. 발전원·소비처는 고정 ID 순서로 집계해 함께 하기에서 같은 결과를 만든다.

### REC27~30 규모·식재·연구

- REC27은 현재 세계의 독립 건물 엔티티를 센다. `hub`, `belt`, `fast-belt`, `underground`, `splitter`, `overflow`, `sorter`, `merger`, `road`, `pole`은 제외한다. 나머지 등록 설비는 1대씩 센다. 창고·정류장·발전기·변전소·신규 생산 설비는 포함하고 트럭·회수 더미·장착 모듈·지형은 제외한다. 해당 빌드에 없는 종류 이름을 새로 추가하지 않는다. 3×3 조립소도 1대다. 확장 시 건물 데이터의 `countsAsRecordFacility` 같은 명시적 분류로 이 목록과 맞춘다.
- REC27·28은 ‘동시에 존재하는 수’를 판정한다. 9대 설치·철거를 반복해서 누적 10대로 만들 수 없다. 달성 후 철거하면 현재 수는 낮아져도 메달·최고 수는 남는다. 정지·노선 미지정·배터리 0인 트럭도 실물 1대로 센다. 실제 운행은 별도 배송 업적에서 평가한다. 기본·고급 차량 모두 포함하며 고급 차량으로 교체했다고 추가 두 대로 세지 않는다.
- REC29는 식목기가 묘목 1개를 소비하고 실제 나무 1그루를 생성한 성공 사건만 센다. 자연 생성·기존 나무 불러오기·빈 땅 없는 실패·명령 재전송은 제외한다. 벌목 후 같은 칸에 다시 식재한 **새 나무 세대**는 1회 더 센다. 새싹이 성숙할 때 다시 세지 않는다. 성숙 기록 D19와 구분한다.
- REC30의 대상은 기존 `endless-mining`, `endless-crafting`, `endless-belt`, `endless-truck`, `endless-forest` 5종이다. 업적 집계를 시작한 이후 재료를 지불하고 실제 완료한 추가 단계 수를 합산한다. 서로 다른 연구를 1단계씩 하면 합계 5다. 일반 연구·무료 해금·관리자 조작·연구 완료 연출 재생은 제외한다. 새 산업 반복 연구는 상한/효과가 미정인 후속 범위이므로 이 버전의 대상에 포함하지 않는다.
- 비용 증가가 1.5배인 반복 연구를 한 줄 20단계까지 강제하지 않도록 합계 20으로 정했다. 연구 5줄을 골고루 진행할 수 있고 최종 납품 전후 어느 때든 인정한다.

## 5. 활성 범위와 완료율

의존 표기 K/B/R/W의 뜻은 전체 업적 기획과 같다. **K는 구현 완료 표시가 아니라 기존 기능에 사건 계측을 연결하면 지원할 수 있다는 표시다.** 연구 전 잠금과 목표에 따른 지역 미공개는 업적 비활성 사유가 아니다. 해당 세계에서 나중에 해금할 수 있으면 처음부터 활성 목록에 남기고 다음 기준을 보여 준다.

| 지원 세계/빌드 | 활성 기록 | 계열 수 | 메달 분모 |
| --- | --- | ---: | ---: |
| 기본 품목·숲·기본 발전·반복 연구와 해당 사건 집계 지원 | REC01~14, REC18~25, REC27~30 | 26 | 104 |
| 위 기능에 주석·청동·알루미늄 생산까지 지원 | 위 목록 + REC15~17 | 29 | 116 |
| 위 기능에 확장 폭풍·현지 기여 집계까지 지원 | REC01~30 | 30 | 120 |

미지원 행은 비활성화하고 공개 완료율에서 제외한다. ‘연구를 아직 안 함’과 ‘이 세계에는 해당 시스템 자체가 없음’을 구분한다. 과거 세계를 새 지형/가격/날씨 규칙으로 변환해서 업적을 활성화하지 않는다. 필요한 계측이 아직 연결되지 않은 행은 개발 중 미지원으로 명시하고 완료로 보고하지 않는다.

전체 업적 116종 중 나머지 86종의 출시 활성 목록은 기존 문서대로 기능별로 선정한다. 기록 30종의 기준값·ID는 이 문서로 채웠으며 해당 부분을 다시 미정 목록에 넣지 않는다. 숨은 업적 16종은 공개 완료율 분모에서 계속 제외한다.

## 6. 이전 저장·이전 업적 복구

1. 현재 main처럼 기록 시스템이 없는 세계에는 v1 집계 시작 시각을 한 번 저장한다. 생산·야간/폭풍 에너지·식재·추가 연구는 그 시점부터 세며 시작 재고나 현재 연구 레벨을 과거 사건으로 바꾸지 않는다. Q60은 새 60초를 측정한다.
2. 현재 건물/트럭 수는 그 자체가 현재 상태이므로 REC27·28에 바로 반영할 수 있다. 반대로 누적 생산을 현재 건물 수나 재고에서 추정하지 않는다.
3. 나중에 이전 업적 구현이 발견되면 원래 ID·메달·조건 버전을 보존한다. 정확한 항목·단위·판정·기준의 동등성이 입증될 때만 v1과 명시적으로 대응한다. 숫자가 비슷하다는 이유로 같은 ID로 덮어쓰지 않는다.
4. 동등하지 않은 옛 메달은 보존 기록으로 표시하되 v1의 120개 분모에 추가하지 않는다. 같은 메달을 두 번 집계하거나 옛 달성 기록을 취소하지 않는다. 기존 수치가 남은 진짜 누적 카운터도 정의가 같고 집계 시작 범위가 입증될 때만 가져온다.
5. v1의 계열별 메달 비트·최고 기록, 누적값, 60초 창, 전력 1초 창/소수 잔량, 집계 시작 시각, 대상 연구 추가 완료 수를 공장 저장·네트워크 스냅샷·체크섬에 포함한다. 개인 UI 필터/추적은 공장 판정과 분리한다.
6. 사건은 공용 시뮬레이션의 실제 성공 지점에서 한 번만 센다. UI·효과음·재고 차이·전체 목록 재렌더링에서 증가시키지 않는다. 이미 적용한 명령의 재전송은 기존 공용 중복 방지로 차단하고 무한한 사건 로그를 새로 저장하지 않는다. 메달 비트는 같은 틱 재판정에도 다시 알리지 않는다.

## 7. 난이도와 자원 검토

- 동메달은 해당 공정을 막 시작한 플레이, 은은 첫 지역 연결, 금은 확장 공장, 다이아는 선택적인 대량 생산을 목표로 한다. 모든 계열의 다이아를 4~5시간 안에 얻는 것이 메인 완료 조건은 아니다. 이 시간 배치는 아직 실측하지 않았다.
- 철·구리 원광 25,000개는 각각 최소 매장량 56,000개보다 낮고, 석탄 20,000개는 최소 42,000개보다 낮다. 주석판 5,000개는 최소 주석광석 24,000개 중 일부이며 청동 20,000개에는 P02 기준 주석판 5,000·구리판 15,000개가 필요하다. 알루미늄판 5,000개에는 보크사이트 10,000개가 필요해 최소 36,000개보다 낮다.
- 위 비교는 개별 기준의 1차 상한 검사다. **모든 다이아 동시 달성의 원료 총량·작업 공간·예전 저장의 남은 자원까지 보장한 검산은 아니다.** 물류·메인 생산 소비와 함께 실제 플레이로 확인한다. 완전히 고갈된 옛 세계의 과거 미측정 광석 실적을 임의로 생성하지 않는다.
- 후반 제품은 실제 설비 모듈·고급 트럭의 최초/심화 업적으로 이미 다루므로 이번 누적 17종을 55품목 전체로 늘리지 않는다. 레시피·비용·광맥량·연구 상한도 업적을 맞추기 위해 변경하지 않는다.
