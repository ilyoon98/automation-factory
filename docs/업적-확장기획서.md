# 업적 확장 기획서

2026-10-27 · [확장 기획서 버전 3](기획서-버전3.md)의 업적 상세 설계

**설계 문서이며 게임 구현 완료 목록이 아니다.** 특히 아래 숨은 업적 표에는 이름·정답·판정 조건이 모두 있다. 플레이어용 도움말이나 배포 설명에 이 표를 그대로 노출하지 않는다.

2026-10-27 보완: 현재 Windows main에는 이 문서의 ‘기존 업적 30종’ 구현도 확인되지 않는다. 기존 기록 보존은 원래 구현본을 찾았을 때의 호환 조건이다. 후속 [목표·진행 기획](목표-진행-상세기획.md)에 맞춰 F31~F42·D25~D28을 추가했다. 기존 100종·262기록 후보에서 16종·28기록을 더해 총 116종·290기록의 설계 후보가 됐다. 실제 게임 완료율의 분모는 해당 버전에서 활성화한 공개 기록만 사용한다.

같은 날 후속 보완: 빠져 있던 기록 30종의 항목·저장 ID·동/은/금/다이아 수치·집계·활성 목록을 [기록 30종 구현 기준](업적-기록30종-구현기준.md)에 작성했다. 이는 과거 수치 복원이 아닌 `record-v1` 첫 기준안이다. 아래 ‘기존 기록’은 구성의 유래를 뜻하며, 현재 구현의 기준값은 연결한 v1 문서를 우선한다. 이전 구현을 찾기 전에도 해당 표로 진행할 수 있다.

## 1. 구성과 목표

기존 업적은 생산량과 공장 규모의 기록으로 남긴다. 신규 업적은 처음 배운 행동, 운영 숙련도, 우연히 발견하는 재미를 채운다.

| 구분 | 계열 수 | 계열당 단계 | 획득 기록 수 |
| --- | --- | --- | --- |
| 기록: 누적·속도·공장, record-v1 | 30 | 4 | 120 |
| 신규 최초 달성 | 42 | 1 | 42 |
| 신규 심화 | 28 | 4 | 112 |
| 신규 숨은 업적 | 16 | 1 | 16 |
| 합계 | **116** | — | **290** |

기존 30종 외의 신규 후보는 **86종**이다. 이전 최초 30·심화 24·숨은 16의 70종을 유지하고, 지역 중간재·후반 조립에 맞는 최초 12·심화 4를 추가했다. 기존 30종을 다시 신규로 세지 않는다. 심화의 네 기준은 동·은·금·다이아 순서이며, 위 단계를 한 번에 만족하면 아래 단계도 함께 달성한다. 모든 조건은 플레이 테스트 전 판정 초안이다. 2026-10-27 완화안은 신규 후보의 연속 실패 초기화를 없애며, 이미 출시·획득한 ID와 기록은 그대로 보존한다.

`K`도 **업적 자체가 구현돼 있다는 뜻이 아니다**. 현재 기능에서 판정 사건과 집계를 보강하면 만들 수 있다는 의미다. 여러 표기가 있으면 모두 필요하다. 해당 기능이 없는 버전에서는 업적을 비활성화하고 완료율의 분모에서도 제외한다.

## 2. 공통 판정 규칙

### 2.1 시간·수량·실제 행동

1. 모든 시간은 게임 시뮬레이션 시간이다. 일시정지는 진행 시간에 들어가지 않고, 2배·4배속에서는 게임 시간만큼 진행한다. PC 시각·프레임 수·창을 연 시간은 쓰지 않는다.
2. 생산량은 제작 완료·실제 채굴·실제 벌목 사건으로 센다. 시작 재고·파일 불러오기·철거 환급·나무 위 건설 환급·창고 이동은 새 생산이 아니다.
3. 기본 단위는 아이템 개수, 거리 칸, 전력 kW, 에너지 MJ다. 에너지는 실제 kW × 경과 초를 적분해 환산한다. 발전기 명목 출력이나 유휴 설비의 표시 용량은 공급 실적이 아니다.
4. 실제 공급은 기계 가동·유효 차량 충전 등 수요에 전달된 전력이다. 거점 간 전력 조건은 [전력망 개정](전력망-연결-독립시작-개정.md) §6에 따라 서로 다른 생산 거점의 최종 작업에 발전원 출처가 기여한 양을 센다. 전선·고리·충전 반복을 중복 합산하지 않는다.
5. 유효 배송은 트럭이 출발지와 다른 정류장에 실제로 화물을 내린 사건이다. 빈 운행·배터리 충전·정류장 배치·노선 설정만으로 배송 업적을 주지 않는다. 동일 배송 사건을 재접속·재동기화로 다시 세지 않는다.
6. 업적은 한 번 완료하면 조건이 낮아져도 취소되지 않는다. 건물 수·지역 수처럼 현재 상태를 재는 조건은 계속 지었다 철거하는 누적 횟수로 대체하지 않는다.

### 2.2 생산 속도와 지속 가동

- `Q60`은 최근 게임 시간 60초의 **실제 완료 생산량**이다. 충분한 60초 기록이 없으면 속도 조건을 판정하지 않는다.
- 기록 속도 REC18~23은 Q60 한 번 충족으로 판정한다. "1분 내내 일정 속도"를 요구하는 것으로 설명을 바꾸지 않는다. 복구된 옛 속도 업적은 원래 ID·조건을 보존한다.
- 시간·비율 조건은 메인 진행과 분리한 선택 심화다. `조건 충족 누적 180초`는 해당 조건을 만족한 게임 시간만 합산한다. 미달이면 누적을 잠시 멈추며, 회복하면 남은 시간부터 이어 간다. 179초에서 멈춰도 다음 충족 1초로 완료한다. 이미 얻은 기록·메달을 취소하지 않는다.
- 표의 `가동률`은 그 기계가 온전히 존재한 최근 60초 중 실제 작업한 시간 비율이다. 재료 부족·출력 막힘·전력 부족 시간도 분모에 포함한다. 레시피 변경·건물 교체로 불리한 구간을 지우지 못하게 새 60초 기록을 다시 모은다.
- 선택 심화의 `가동 구역`은 최근 60초에 실제 제작 완료가 있는 생산 기계를 포함하고, 기계·차량의 배터리 충전 외 소비 수요가 최소 100kW인 구역이다. 축전기를 충방전만 하는 빈 구역은 포함하지 않는다.
- `전력 충족 95%`는 실제 공급/작업 수요가 0.95 이상이라는 뜻이다. 수요 0인 순간은 지속 가동 시간으로 인정하지 않는다.

여기서 가동 구역은 운영 거점(siteId)을 뜻하며 전력망과 구분한다. 독립 망 수를 요구하는 D07만 실제 서로 다른 연결 성분을 센다. 전력 관련 조건은 사용자 채택 [전력망 개정](전력망-연결-독립시작-개정.md)의 판정 버전을 적용한다. 실제 출시된 이전 조건/달성은 보존하고 미출시 후보만 갱신한다.

### 2.3 지역·날씨·전기 출처

- 건물의 지형은 중심 칸으로 정한다. 도로·컨베이어·창고·빈 정류장으로 생산 거점의 수를 채우지 않는다.
- 거점은 보존된 운영 기준 칸의 지형으로 분류하고 연결 망과 구분한다. 개별 건물의 발전 배율과 현지 날씨는 각 건물의 중심 칸을 따른다.
- 날씨 조건은 **20초 전환이 끝난 현지 날씨**에서 센다. 별도 조건이 없다면 같은 날씨 종류에서 조건 충족 시간을 누적 60초 확인한다. 날씨가 바뀌어도 종류별 누적은 남는다.
- 한밤은 하루 길이 D의 위상 0.7 이상·0.9 미만인 구간이다. D는 기존 지도와 새 지도 모두 720초·12분이다. 게임 날짜는 `floor(게임 시간 / D)`로 구분하고 한밤 조건은 같은 세계의 확정된 하루 설정을 따른다. 일반 누적 180초 같은 업적 시간을 하루 길이에 비례해 임의로 바꾸지는 않는다.
- 폭풍·안개 등 확률형 현상은 후속 날씨에서 반복 도전할 수 있다. 특정 첫날·첫 폭풍·세이브 생성 직후만 가능한 업적은 만들지 않는다.
- 태양광·풍력·수력·지열·연료·허브·축전기 방전의 기여를 구분한다. 축전기는 에너지를 만드는 설비가 아니며, 친환경 조건에는 충전 당시의 발전원 비율도 반영한다.
- 전력망 병합/분리는 실제 노드 연결에 따라 판정한다. 거점 ID·누적 소비·메달·최고 기록은 유지하며 거점별 생산 창을 초기화하지 않는다. 독립 망 같은 순간 조건이 미달하면 해당 조건의 누적만 멈춘다.

D28의 유효 연결은 최근 300초에 실제 제작 재료 배송이 있는 출처→목적지 간선이다. 한 조립 거점으로 이어지는 공급 경로의 가동 생산 거점을 세며 조립 거점도 포함한다. 중계 창고만으로 가동 생산 거점 수를 늘리지 않는다. 이 단기 연결 창은 선택 심화 전용이며 메인 누적 실적을 지우지 않는다. 이전 D07·D18의 가동 구역·규모 조건을 소급 변경하지 않는다.

D06의 산출물 정정 등 이번 조건 보완은 미출시 후보의 개정이다. 복구된 실제 구현에 같은 ID의 다른 조건이 있으면 기존 획득 기록을 보존하고 새 판정 버전이나 새 ID로 분리한다. 확인하지 못한 기존 기록의 의미를 같은 ID로 덮어쓰지 않는다.

D27은 현재 소비·건설·목표 재고의 실제 요청을 이행한 배송을 기준으로 한다. 목적지에서 생산·사용 없이 같은 화물을 반복 왕복시킨 횟수는 새 실수요로 세지 않는다. 성공 회차는 실제 요청 재료를 합계 2개 이상 유효 배송해야 한다. 요청 0인 품목은 제외하고 요청이 모두 0인 빈 편은 성공·실패로 세지 않는다. 정시는 예정 시각 +15초 이내다. 성공 수는 생산 출처·목적지 조합에 저장해 같은 구간의 노선을 나눠도 중복되지 않으며, 주기·요청·노선 변경 후에도 보존한다. 동시에 여러 노선이 성공하거나 연속 성공할 필요는 없다.

최초 업적은 제품을 처음 배운 순간, 심화는 공급과 운영 숙련을 기록한다. UI의 추천 순서는 D25~D28과 지역 중간재를 우선하고, D20 원료 교역·F20 광맥 독립·D24 탐사는 선택 경로로 둔다. 탐사를 구현하지 않은 버전에서는 D24를 비활성화한다.

각 행의 정확한 수치·영구 저장 키·예외·지원별 26/29/30종 활성 목록은 [record-v1 기준표](업적-기록30종-구현기준.md)를 따른다. 옛 30종의 개별 조건이 확인되지 않아 ‘기존 기준 유지’만으로 작업할 수 없던 부분을 이 표로 대체했다. 원래 구현이 발견되면 옛 ID/메달을 보존하고 검증된 동등 항목만 명시적으로 대응한다. 같은 ID에 새 의미를 덮어쓰지 않는다.

단순 건물 수·트럭 수 업적을 실제 가동 업적으로 이름만 바꾸지 않는다. 기존 기록은 규모, 신규 심화는 실제 운영을 평가한다.

## 7. UI와 알림

- 업적 창은 `최초 / 기록 / 심화 / 숨은` 탭으로 나눈다. 각 탭에 생산·물류·전력·지역·숲·탐사 필터를 제공한다.
- 이름 검색, 미달성만 보기, 다음 단계가 가까운 순 정렬을 제공한다. 검색 결과나 정렬 정보로 숨은 이름·조건을 미리 노출하지 않는다.
- 최초는 완료 표시, 기록·심화는 네 메달과 다음 기준, 숨은 업적은 달성 전 힌트·달성 후 이름과 설명을 표시한다.
- 신규 최초·심화는 한 개를 추적할 수 있다. 숨은 업적은 달성 전 정확한 진행도 추적을 제공하지 않는다.
- 선택 심화는 ‘조건 충족 누적 92/180초’로 표시한다. 미달이면 ‘잠시 멈춤 · 재료 부족’처럼 이유와 보존된 시간을 보여 주며 0으로 되돌리지 않는다. 메인 목표에는 유지 타이머를 표시하지 않는다.
- 한꺼번에 여러 업적을 달성하면 한 알림으로 묶고 상세 내역을 업적 창에서 확인한다. 저장 로드·중간 참가의 일괄 소급은 소리를 반복하지 않는다.
- 공개 완료율은 활성화된 최초·기록·심화의 획득 기록 수 기준이다. 비활성 계열과 숨은 업적은 공개 완료율의 분모에서 제외한다. 숨은 업적은 별도의 발견 수로 보여 준다. 표의 290개는 모든 후보를 활성화했을 때 숨은 기록까지 합친 설계 총수다. record-v1의 기록 분모는 기능 지원에 따라 104/116/120이며 과거 구현 복구를 기다릴 필요가 없다. 조건이 확인되지 않은 옛 메달은 보존하되 v1 분모에 별도 중복 추가하지 않는다.
- UI 배율·키보드 포커스·목록 스크롤·애니메이션 줄이기를 기존 창과 동일하게 지원한다.

### 보상

첫 구현의 보상은 업적 기록·알림·완료 도장이다. 후속 보상은 칭호·허브 장식 등 외형으로 한정한다. 생산 속도·전력·자원 보상을 업적에 붙여 숨은 조건을 공략해야 효율이 좋아지는 구조를 만들지 않는다.

## 8. 저장·멀티플레이·측정 설계

구현 시 필요한 데이터 설계이며 이번 문서 작성에서 해당 코드를 추가하지 않는다.

| 측정 대상 | 필요한 정보 |
| --- | --- |
| 최초·누적 생산 | 실제 채굴·벌목·레시피 완료량, 일반 제련/정광 제련/황산 정제의 레시피 구분 |
| 지속 가동 | 초 단위 실제 생산 창, 기계 생존 기간·작업 시간, 조건별 충족 누적 초 |
| 숲 | 식재 여부·세대, 성숙 사건, 마지막 고갈 칸, 같은 칸의 식재 순환 상태 |
| 운송 | 적재·하역 정류장 ID와 지형, 품목·수량, 유효 배송 사건, 노선 개정과 한 바퀴 ID |
| 전력 | 거점 siteId·계산용 망 ID, 발전원 출처·최종 기계/차량 기여, 축전 출처 잔량 |
| 날씨 | 씨앗·게임 시각·현지 지형, 전환 완료 여부, 날씨별 성공 기록 |
| 탐사 | 안정적인 자원지·분출구 ID와 조사 완료 기록 |
| UI | 개인별 필터·추적 선택. 공장 업적의 판정 상태와 분리 |

- 업적은 시뮬레이션에서 판정한다. UI는 결과를 읽고 알린다. 화면을 열지 않았거나 탭이 가려져도 같은 틱에 같은 결과가 나와야 한다.
- 최초·숨은 완료 기록, 심화 메달, 누적값, 조건 충족 누적 시간과 이를 판단하는 데 필요한 최근 창·출처 집계를 저장과 네트워크 스냅샷에 포함한다. 불러오기나 중간 참가가 진척을 임의로 초기화하지 않게 한다.
- 복구된 옛 속도 업적의 디스크 불러오기 후 1분 재측정은 원래 동작으로 남길 수 있다. 새 record-v1은 60초 창을 저장해 이어 가며 창이 없는 옛 저장만 새로 측정한다. 신규 심화도 충족 누적 시간과 대응하는 최근 창을 보존한다. 창을 복구할 수 없으면 측정 준비 중 누적만 멈추고 저장된 시간을 지우지 않는다.
- 완료 후 재접속·재동기화·되돌리기로 누적값과 알림을 중복 생성하지 않는다. 설비 되돌리기는 이미 실제 발생한 생산·소비 사건을 재발생시키지 않는다.
- 업적은 공장 저장 단위의 공동 기록이다. 혼자 새 공장을 만들면 별도 기록으로 시작한다. PC 계정 단위 최고 기록 통합은 후속 범위다.
- 원래 존재하던 공장의 사건을 확인할 수 없으면 추정 달성하지 않는다. 과거 기록이 없어도 이후 플레이로 모든 신규 업적에 다시 도전할 수 있게 한다.
- 오래된 저장의 원래 메달 ID를 삭제하거나 다른 조건으로 재사용하지 않는다. 표시 제목은 바꿀 수 있어도 저장 ID는 고정한다.
- 필요한 사건·집계를 보존하되 모든 아이템의 무한한 이동 이력을 쌓지 않는다. 출처가 필요한 전력·물 반입 등은 한정된 집계로 설계하고 저장 크기·틱 비용을 측정한다.

## 9. 구현 순서

1. [record-v1](업적-기록30종-구현기준.md)의 30행 데이터·지원별 활성 목록·공통 사건 집계, 업적 탭·숨김·알림·옛 기록 보존을 구현한다. 기준값 미정으로 30종 전체를 보류하지 않는다.
2. 현재 기능 기반 최초·심화·숨은 업적부터 연결한다. `K`만 있는 계열이 첫 대상이다.
3. 7종 지형·신규 자원·지역 전력망을 만들 때 관련 계열을 함께 활성화한다.
4. 전력 출처·유효 배송·숲 세대·지속 가동의 사건 집계를 검증한 뒤 복합 숨은 업적을 활성화한다.
5. 탐사 기능과 D24를 연결하고 실제 플레이에서 메달별 소요 시간·알림 밀도를 조정한다.

## 10. 구현 완료 확인 기준

- 모든 기준값의 직전·정확한 도달·여러 단계 동시 도달을 확인한다.
- 시작 재고·철거·복사·창고 이동·빈 트럭·유휴 발전으로 생산/공급 업적을 얻지 못한다.
- 조건 충족 누적 180초는 179초에서 멈추면 179초를 보존하고, 재개 후 충족 1초로 완료한다. 일시정지·배속·저장·중간 참가에서도 같은 게임 시간 규칙을 따른다.
- 날씨 전환 중·전환 완료 후·날씨 끝 경계의 판정이 일치한다. 눈·모래 바람은 건물의 현지 지형을 사용한다.
- 전봇대 고리·망 병합/분리·축전기의 혼합 발전원에서 최종 소비를 중복 집계하지 않는다.
- 같은 원료·트럭·나무·자원지를 다시 읽어 동일 사건을 여러 번 세지 않는다.
- 기존 메달은 유지되고 활성 기능이 없는 미래 업적은 완료율에서 빠진다.
- 미달성 숨은 이름·수치·진행도가 검색·툴팁·정렬·알림·공유 화면에 유출되지 않는다.
- 새 지도마다 모든 활성 지형·자원지와 업적에 필요한 최소 공간을 보장한다. 자원지 25곳 미만인 특수 지도에서는 D24의 불가능한 단계를 활성화하지 않거나 별도 목표를 정한다.
- 두 참여자가 같은 명령을 실행하고 한 명이 도중에 들어와도 같은 시각·메달·최초·숨은 완료 결과를 얻는다.
