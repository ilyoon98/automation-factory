# 입력·운송 UI 개선 기록

2026-10-31. 기반: 0.6.1 통합 브랜치. 새 콘텐츠 없이 기존 조작과 입력 보존 문제를 수정했다.

## 재현과 수정

1. 드래그 건설 중 모달을 열었다 닫으면 마우스 이동으로 건설이 이어졌다. 영역 철거는 Esc·pointercancel·lostpointercapture 뒤에도 마우스를 떼면 실행됐고, 복사도 취소 후 청사진이 만들어졌다. 제스처 취소를 공통 처리하며 이미 실행된 편집만 끝낸다. 수정 전 코드로 같은 테스트를 실행하면 6개가 실패했고 수정 후 통과했다.
2. 모달의 마지막 입력칸에서 Tab을 누르면 포커스 순환이 적용되지 않았다. 입력 중 단축키 보호를 유지하면서 Tab만 모달 처리에 전달하고 summary도 이동 대상에 포함했다.
3. 운송 계획에 값을 입력하고 + 품목을 누르면 정적 정보창 재작성으로 기존 입력이 사라졌다. UI 검사에서 실패를 확인했다. 동일 차량·동일 확정 계획이면 작성 중 값·초점·정보창 스크롤을 보존한다. 명령 적용·외부 계획 변경·다른 세계·다른 차량에서는 새 확정값을 사용한다.
4. 선택한 품목의 상한이 0·빈값이면 그 행이 조용히 생략되어 기존 계획이 꺼질 수 있었다. 화면에서 실패를 재현했다. 양의 정수·중복·총 적재량을 명령 전 확인하고 실패 시 입력 행을 유지한다.
5. 업적 창과 운영 창은 주기 갱신으로 스크롤이 초기화됐다. 배포 화면 검사에서 업적 읽기 위치 보존 검사가 실패했다. 읽기 위치를 복구하고 업적의 필터 선택 중에는 주기 재작성을 미룬다. 실제 필터 변경은 즉시 적용한다.
6. 320×700 화면에서 상·하단 UI가 정보창을 거의 다 가렸다. 숨김 Electron 캡처로 확인했다. 좁은 화면의 하단 탭을 가로 한 줄로 바꿔 정보창 높이를 확보하고, 단축키로 고른 탭은 보이도록 넘긴다.
7. Space·표시 토글 키의 keydown 자동 반복이 상태를 여러 번 뒤집었다. 토글 키의 반복 입력은 무시하고 이동·다른 편집 키는 유지한다.

## 검증

- 프로덕션 빌드 통과, 전체 테스트 397개 통과·성능 관련 1개 생략.
- 입력 회귀 테스트: 취소 후 지연된 pointerup, 모달의 프레임·이동·해제 경로, 부분 건설 한 번 되돌리기, Space 반복.
- 배포 화면 검사 16개 통과: 창 5종, Tab, 스크롤, 필터 초점, 표시 키 반복 등.
- 운송 화면 검사 17개 통과: 작성 보존·계획 실제 적용·외부 갱신·다른 저장 전환·잘못된 상한·320px 세로 공간 등.
- 공장 연출 검사 27개 통과: 기존 작업·운송·연구·완료·효과 줄이기 회귀 확인.
- 검증 스크립트는 창을 먼저 닫아 실패 코드가 유실될 수 있어 서버 종료 후 명시적 종료 코드로 끝내도록 바꿨다.
- 개인 저장은 사용하지 않았다. 컴퓨터 유즈는 앱 접근 승인 시간 초과로 조작하지 못했으며, 위 화면 결과는 별도 임시 프로필의 자동 검사와 캡처다.

설치 파일 배포·main 병합·원격 푸시는 하지 않았다. 이전 개발판 저장의 이관은 이번 범위가 아니다.
