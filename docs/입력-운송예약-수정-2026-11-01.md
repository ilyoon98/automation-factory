# 입력 전환·운송 예약 후속 수정

2026-11-01 · 0.6.2 이후 미배포 변경.

## 재현한 문제

- Input.setTool은 건설 드래그만 종료했다. 철거·영역 철거·복사 중 도구를 바꾸면 이전 동작이 이어지거나 pointerup에서 확정됐다.
- truck-plan 명령은 잘못된 행을 필터링해 나머지만 적용했다. 상한 0·음수·소수·알 수 없는 품목이 섞인 명령이 기존 계획과 예약을 바꿀 수 있었고, 중복 품목도 허용했다.
- 계획 수정은 출고 예약만 풀어 미적재 화물의 입고 예약이 남았다. 다음 재예약에서는 이미 실은 화물의 예약까지 풀고 새로 실을 수량만 예약해 실제 화물을 입고 예정에서 누락했다.

수정 전 새 회귀 검사 9개가 실패하는 것을 확인했다.

## 수정

- 도구 전환은 공통 제스처 취소로 모든 드래그를 중단한다. 이미 실행한 편집은 보존하고 한 번의 되돌리기로 남긴다.
- 계획 전체 검증을 World.setPlan에서 수행하고 명령도 같은 경로를 사용한다. 유효하지 않은 명령은 예약·화물·계획을 변경하지 않는다.
- 계획 수정 시 미적재 예약을 해제하고 입고 예약은 실제 화물만큼 줄인다. 재예약은 이미 실은 화물의 도착지 공간부터 확보한다. 계획을 끄면 기존 예약을 모두 해제하되 화물은 유지한다.

## 검증

- 빌드·타입 검사 통과.
- 전체 테스트 408개 통과·성능 관련 1개 생략.
- 운송 화면 검사 17개 통과 (개인 저장과 분리된 임시 프로필).
- 두 트럭의 중복 예약 방지, 재예약 후 목표 수량 40개 배송, 중간 스냅샷의 화물·예약 유지, 계획 해제 시 즉시 예약 정리도 확인했다.

이번 변경은 커밋만 하며 0.6.2 공개 릴리스는 바꾸지 않는다.
