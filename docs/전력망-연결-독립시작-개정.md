# 전봇대 연결 전력망과 독립 거점 시작

2026-10-27 · 사용자 채택 · [인프라](지형-운송-전력-상세기획.md) · [경제](진행시간-경제-상세기획.md) · [업적](업적-확장기획서.md)

**송전 터미널을 삭제한다. 전봇대로 이어진 발전기·변전소는 하나의 전력망에서 전력을 공유한다.** 이 문서가 이전의 독립 전력 구역·방향 지정 송전 계약보다 우선한다. 새 확장 세계의 기획 개정이며 게임 코드를 구현하거나 기존 저장을 변환한 결과가 아니다.

## 1. 없애는 규칙과 유지하는 규칙

| 대상 | 개정 |
| --- | --- |
| 송전 터미널·전용 송전 연구 해금 | 삭제. T05는 황·케이블·지열 산업으로 유지 |
| 터미널 양 끝 건설비·거리/8 케이블 차감 | 삭제. 전봇대 건설비에 전선 포함, 자동 연결 비용 추가 없음 |
| 구역별 3/6MW 한도·변전소 용량 승격 | 삭제. 변전소는 넓은 공급 범위를 제공 |
| 중심에서 28/36/40칸 확장 한계·지역 간 128칸 한도 | 삭제. 한 연결의 길이 12칸을 지키며 연속 확장 가능 |
| 선로당 2MW·송수신 각 3개·방향/우선순위/중계 요청 | 삭제. 연결 그래프의 양방향 공유, 고리 연결 허용 |
| 선로당 95% 전달 효율 | 삭제. 첫 버전의 전선 손실은 0, 길이별 출력 감소 없음 |
| 발전기 정격·연료값·현지 날씨/지형 배율 | 유지 |
| 축전기 10MJ·200kW·충전 효율 95%·기본 하한 10% | 유지. 전선 손실 삭제와 혼동하지 않음 |
| 차량의 배터리·충전 속도·대기열 | 유지. 충전 예산은 아래 거점별 규칙 적용 |
| 같은 망의 창고 재고 | 전력 연결만으로 공유하지 않음. 기존 현지 화물 규칙 유지 |

새 전력 설비는 기존 6종에서 터미널을 뺀 **5종**, 새 생산 6종과 합해 **신규 설비 11종**이다. 2026-10-30 개정으로 하단은 발전 C(풍력·석탄·태양광·수력·연료·지열)와 전력 U(전봇대·변전소·축전기)로 분리한다. 목록의 상세 순서는 [운영 UI §2.3](지역-운영-UI-상세기획.md)을 따른다. 케이블은 모듈·연구 재료로 계속 사용하며 전봇대 연결 비용으로 쓰지 않는다.

## 2. 공급 범위와 전선 연결

| 연결 노드 | 몸체 | 직접 공급 반경 | 노드 간 전선 연결 |
| --- | --- | --- | --- |
| 시작 허브 | 기존 3×3 | 24칸 | 최대 12칸 |
| 모든 발전기 | 기존 또는 확정 몸체 | 10칸 | 최대 12칸 |
| 기본 전봇대 | 1×1 | 6칸 | 최대 12칸 |
| 변전소 | 2×2 | 18칸 | 최대 12칸 |

반경과 한 연결 거리는 노드 기준 칸 사이 체비쇼프 거리다. 기준 칸은 몸체 왼쪽 위에서 `(floor(size/2),floor(size/2))`다. 배치 가능한 두 노드가 12칸 이내이면 자동으로 무방향 간선을 연결한다. 선의 개수 제한이나 수동 송수신 설정을 추가하지 않는다. 기본 전봇대는 기존 차량 운송 연구, 변전소는 T02 산업 전동기에서 해금한다. 전선 공유를 T05·고용량 케이블까지 잠그지 않는다.

새 단계 공개 세계에서는 양 끝 노드와 기준 칸 사이 직선의 supercover 셀이 공개돼 있어야 자동 연결한다. [지도 공개](지도-목표별-공개-상세기획.md) §5의 접근 조건이며 공개 전 땅을 건너뛰어 공급하지 않는다. 공개 묶음은 필요한 전봇대 경로도 함께 보장한다.

전선은 도로·벨트·물 위를 지나갈 수 있고 지상 칸을 점유하지 않는다. 노드 몸체는 기존 건설 가능 칸 규칙을 지킨다. 선이 교차하거나 서로 다른 공급 면이 겹친 것만으로는 연결되지 않는다. 실제 노드 사이 거리 조건을 만족하는 간선으로만 연결한다. 물을 건너려면 양쪽에 12칸 이내의 설치 가능한 노드가 있어야 한다.

각 연결 성분이 하나의 **전력망**이다. 발전기·허브가 없는 전봇대/변전소 연결도 망은 존재하지만 공급 0이다. 발전기를 끄거나 연료가 바닥나도 전선 연결은 유지한다. 철거·되돌리기로 실제 간선이 끊어지면 그때 망이 나뉜다. 고리가 있으면 대체 경로가 남으므로 망은 분리되지 않는다.

작업 기계·정류장·축전기는 자신의 기준 칸이 노드의 직접 공급 범위 안에 있으면 그 노드에 접속한다. 이 설비들은 서로 다른 망을 이어 주는 중계 노드가 아니다. 후보 노드가 여러 개면 기존 접속 노드가 유효한 동안 유지하고, 최초/재선택 시 가장 가까운 노드·동률은 가장 작은 노드 ID를 택한다. 미가동/정전을 이유로 매 틱 다른 망으로 자동 이동하지 않는다. 배치 미리보기와 상세에서 접속 노드·망을 표시하고 범위 안 후보로 직접 바꿀 수 있다.

변전소 반경 18칸 안은 전봇대 없이 공급된다. 밖으로 길게 뻗은 설비는 전봇대로 이어 간다. 변전소·전봇대가 발전량을 추가하거나 특정 거점에 전력을 우선 예약하지 않는다.

## 3. 거점과 전력망을 구분

**거점은 생산·물류·업적의 위치 단위, 전력망은 실제 전선 연결 성분이다.** 여러 거점이 한 망을 공유할 수 있다. 연결/분리가 거점 수·이름·과거 생산/배송 실적을 바꾸지 않는다.

거점은 최초 허브·현지 발전기·변전소로 위치 기준과 안정적인 siteId를 만든다. 새 기준 설비가 기존 거점 기준에서 맨해튼 20칸 미만이면 기존 거점으로 묶고, 후보가 여럿이면 가까운 기준·동률 최소 siteId를 사용한다. 전봇대·전선·축전기만으로 새 거점을 만들지 않는다. 거점 기준 설비를 철거해도 기록용 기준 칸·ID는 보존한다. 다른 설비의 거점 귀속은 생성 시 정한 기준을 유지하며 편집으로 기록을 복제하지 않는다. 메인 목표의 생산 거점은 여전히 실제 자동 생산 10개·작업 소비 1MJ 조건과 20칸 거리 묶음을 별도로 만족해야 한다.

새 전력망의 계산용 대표 ID는 연결 성분의 최소 노드 ID로 재계산할 수 있다. 이 ID를 영구 업적 ID나 누적 기록 키로 쓰지 않는다. 전력망 병합/분리는 틱 경계에서 반영하며 소비·충전·실적은 재계산한 동일 토폴로지로 한 번 처리한다.

접속 그래프는 노드 설치·철거·이동 때만 갱신하고 격자 색인으로 12칸 이웃을 조회한다. 같은 연결을 매 틱 전체 노드 쌍으로 다시 검색하지 않는다. 날씨·출력·정지는 간선 구조를 바꾸지 않는다.

차량 충전 예산은 **거점별 기본 400kW·설정 0~800kW**로 유지한다. 같은 거점의 모든 정류장/충전기가 공유한다. 대기열은 기존 도착 순·차량 ID 순이다. 망을 합쳤다고 8거점 충전 예산이 합계 400kW로 줄지 않으며, 전봇대만 쪼개거나 새 정류장을 놓아 같은 거점의 예산을 중복 생성하지 않는다. 배정된 충전 수요는 해당 정류장이 접속한 망에서만 받는다.

## 4. 전력 배분과 연료·축전

연결된 망 전체의 실제 수요와 공급을 합산한다. 같은 망의 공급이 부족하면 그 망의 작업과 배정된 차량 충전을 같은 충족률로 낮춘다. 별도 망은 영향을 받지 않는다. 같은 망을 쓰는 먼 공장도 영향을 받는다는 점을 UI에 표시한다.

1. 허브·태양광·풍력·수력·지열의 실제 가용 출력으로 작업+배정 충전 수요를 충당한다. 출력에는 현지 지형·날씨·일조·실물 자원 조건을 적용한다.
2. 부족하면 연결된 축전기가 잔량 하한·방전 출력 안에서 공급한다.
3. 그래도 부족하면 연결된 석탄/숯·정유 연료 발전기가 필요한 만큼 실제 발전한다. 발전 위치나 거점 경계로 사용처를 제한하지 않는다.
4. 여전히 부족하면 작업+배정 충전에 공통 충족률을 적용한다. 빈 노선·미배정 차량을 임의 충전 수요로 만들지 않는다.
5. 비연료 공급이 수요보다 남으면 연결된 축전기를 충전하고 나머지 출력은 줄인다. 축전 충전만을 위해 연료를 태우지 않는다. 망 전체의 여유로 다른 거점 축전기를 충전할 수 있다.

같은 우선순위 발전기는 가용 출력 비율로 실제 사용량을 나눈다. 축전기는 충방전 한도 내 사용 가능량/수용량 비율로 배분한다. 반올림 잔여는 안정적인 설비 ID 순으로 처리한다. 같은 망의 축전기는 해당 틱에 충전 또는 방전 한 방향만 수행해 전기를 순환시키지 않는다. 연료는 실제 발전 에너지만 차감하며 남은 연소 에너지를 저장한다. 발전량이 출력 감소로 줄면 수력의 물 소비도 실제 발생 에너지를 따른다.

전선에는 용량·손실·우선 경로가 없으므로 선별 전류 방향이나 선별 전달량을 시뮬레이션하지 않는다. 고리에서도 전기를 중복 생산하지 않는다. `실제 발전+실제 방전 = 작업+차량충전+축전기입력`의 에너지 수지를 만족하고, 축전 손실은 입력의 5%로 별도 집계한다.

## 5. 외부 전력 없는 최초 시동

발전 설비는 설치·초기 가동에 전기를 요구하지 않는다. 건설용 부품은 기존 허브 건설 계정을 쓰고 운전용 연료·물은 실제 현지 반입품을 사용한다. 태양광을 선행으로 강제하지 않는다.

| 발전 방식 | 독립 시동 조건 | 주의 |
| --- | --- | --- |
| 석탄/숯 | 현지 발전기에 실물 석탄/숯 반입 | 첫 전기로 채굴기를 돌리고 이후 석탄을 자동 공급 가능 |
| 풍력 | 건설 후 현지 바람 출력 | 밤에도 가능. 초원 맑음 기본 60kW는 채굴기 90kW 정격보다 작아 한 대로 정격 운전을 보장하지 않음 |
| 태양광 | 건설 후 일조가 있을 때 | 밤 0, 화산 상시 0. 모든 새 거점의 보편 시동 수단으로 안내하지 않음 |
| 정유 연료 | 현지 발전기에 정유 연료 반입 | 현지 정유소를 먼저 돌릴 필요 없음 |
| 수력 | 반입한 물을 발전기에 먼저 공급하거나 다른 발전기로 양수기 가동 | 물 0·전력 0의 순환 의존 방지 |
| 지열 | 해금·부품 확보 후 분출구 위에 건설 | 운전 전력·물·연료 요구 없음. 부품은 기존 공장에서 만들어 운반/건설 |

첫 연료/물은 충전해 출발한 기본 트럭으로 현지 정류장·직접 연결 창고에 내려 발전기까지 기존 무전력 하역기·벨트로 공급한다. 기본 하역·벨트·연료 투입은 전력 없이 동작하도록 유지한다. 충전할 전력이 없다는 이유로 실제 화물 하역을 막지 않는다. 현지 발전 후 차량을 충전한다. **먼 허브 재고를 발전기 연료로 순간 차감하거나 빈 발전기에 무료 연료를 주지 않는다.** 새 차량 주행거리·귀환/충전 계획은 기존 물류 규칙을 따른다.

권장 첫 현지 시동은 ‘발전기 1대+초기 실물 연료 → 현지 채굴/생산 → 자동 보급’이다. 이후 태양광·풍력·지열로 연료를 줄이거나 본진 전봇대를 연결할 수 있다. 독립 상태를 유지하는 것도 선택이다.

## 6. 업적·전력 출처

서로 다른 거점 간 전력 기여는 터미널 통과량 대신 **같은 망에서 한 거점의 발전원이 다른 생산 거점의 최종 작업에 기여한 에너지**로 정의한다. 두 기준 칸은 맨해튼 20칸 이상 떨어져야 하며 수신 거점은 실제 생산 10개·작업 소비 1MJ 기록을 만족한다. 발전기와 빈 노드를 멀리 놓는 것만으로 다른 생산 거점을 만들지 않는다.

망의 실제 공급원 구성은 발전기별 실제 출력과 축전기 방전의 저장 출처로 구한다. 각 최종 소비에 그 구성 비율을 곱해 발전원 종류·생산 거점의 기여를 나눈다. 허브·축전기 기여도 분모에 포함한 뒤 업적별 비대상 출처를 제외한다. 선마다 흐름을 상상해 합산하지 않는다. 발전원→최종 소비의 계수만 한 번 기록한다. 공급 중단·망 병합/분리는 누적을 깎지 않는다.

축전 출처는 발전원 종류+원래 생산 거점 단위의 한정된 잔량으로 저장한다. 충전 손실을 적용한 양만 남기고 방전 시 같은 비율로 차감한다. 재충전·중계·고리로 출처가 다른 발전 실적이 되지 않는다. 허브 에너지가 친환경/원거리 기여로 바뀌지도 않는다. 과거 발전기 개체가 철거돼도 출처의 종류·siteId는 보존한다.

- F30·D08·CG03은 거점 간 최종 작업 기여로 바꾼다. 허브 직접/저장 전력과 같은 거점 자체 소비는 제외한다. 시간 유지 조건은 추가하지 않는다.
- D07은 서로 **전선으로 연결되지 않은 독립 망**의 가동 거점을 센다. 전기만 독립시킬 뿐 재료 수입을 금지하지 않는다.
- D09는 한 생산 거점의 한밤 중 실제 작업에 공급한 축전 에너지를 센다. 망을 합쳐도 거점의 밤 기록이 사라지지 않는다.
- D12 등 지역 날씨·가동 조건은 거점 기준과 그 거점이 접속한 망의 실제 충족률을 사용한다. 같은 망을 쓴다고 지역 날씨를 통합하지 않는다.
- H09는 화산 지열 출처가 숲 작업에 기여한 양, H14는 풍력 출처의 실제 충전/배송을 사용한다. 방향 있는 송전선은 요구하지 않는다.
- REC24~26은 기존 직접 발전→작업 기여 조건과 수치를 유지한다. 축전 방전은 이 세 기록의 대상에서 제외한다.

## 7. UI·저장·검증

전력 보기에서 노드·공급 면·실제 전선과 연결 망을 보여 준다. 선에 송신/수신 화살표·2MW 제한·95% 선로 효율을 표시하지 않는다. 망 전체 실제 공급/요청·발전 여유·축전 잔량, 거점별 작업·충전 기여를 구분한다. 망 이름과 거점 이름도 구분한다. 전봇대 배치 중 합쳐질 망, 철거 전 끊길 연결과 분리 후 공급 0인 설비를 확인할 수 있게 한다. 자동 최적 배선/발전기 대수 추천은 추가하지 않는다.

표현 밀도는 [연출 상세](공장-가동-운송-완료-연출-상세기획.md) §6을 따른다. 기본 보기에서 연결 성분을 보존하는 대표 전선을 그리고 선택 시 모든 실제 연결을 보여 준다. 전력 보기에서는 나머지 간선을 옅게 표시한다. 같은 망의 공급 면은 중첩해서 진해지지 않게 합친다. 표현 개선은 실제 간선·철거 판정·현재 공급 반경을 바꾸지 않으며 허브/발전기/변전소 반경 축소는 별도 배치 시험 후 결정한다.

옛 legacy-v042 세계는 기존 공통 전력망을 유지한다. 새 세계에는 연결 방식 버전 `pole-grid-v1`을 저장한다. 구현 중 이전 터미널 시제품 저장을 만났다면 조용히 자동 변환하지 않고 명시적인 호환/미지원 처리를 한다. 노드·실제 접속·거점 기준·충전 예산·축전 출처·누적 기록은 저장/중간 참가/체크섬에 포함한다.

구현 후 확인: 12칸/13칸 연결 경계, 공급 면만 겹친 독립 망, 전봇대 고리의 1개 간선 철거, 발전/소비 없는 망, 부족 전파의 망 경계, 망 병합/분리 후 실적 보존, 정전 중 연료 하역·시동, 밤/화산 태양광 0, 수력 최초 물, 연료·에너지 보존, 같은 틱 공동 편집·저장/재접속. 문서의 계산 검산을 실제 게임 통과로 보고하지 않는다.
