# 정류장 사이 도로 자동 건설과 주석 배송 안내

2026-10-30 · regional-d09 작업본 · 배포 전

최종 검증: 빌드 성공, 전체 테스트 388개 통과·기존 성능 테스트 1개 제외, `git diff --check` 통과. JS 번들의 500kB 안내는 남아 있으나 빌드는 성공했다.

정류장 정보에서 `도로로 연결`을 누르면 A가 지정되고, 공개된 다른 정류장을 B로 고를 수 있다. 아직 도로가 없는 정류장도 선택 가능하다. 지도 미리보기와 함께 도로 구간 칸 수(양 끝 정차 칸 포함), 꺾임 횟수, 신규/기존 도로 수, 실제 자원 아이콘 비용을 표시한다. `경로 보기`는 카메라를 이동·축소하고 `건설`만 실제 명령을 보낸다.

경로는 정류장 몸체가 아닌 테두리의 도로 정차 칸들을 연결한다. BFS로 최단거리를 구한 뒤 그 거리의 경로만 방향별 상태로 비교해 꺾임을 최소화한다. 같은 거리·꺾임이면 기존 도로를 더 활용한다. 후보 정차 칸은 실제 정차 규칙과 같은 상하좌우 테두리이며 건물·벨트·호수·고무나무·미공개 칸은 통과하지 않는다. 재료가 부족해도 경로와 전체 비용은 계산한다.

미리보기는 개인 UI 상태이며 저장·체크섬·재고·목표에 영향을 주지 않는다. 새 구간은 초록 칸, 경로는 파란 선, 양 끝은 A/B다. 출발 정류장·세계·도구가 바뀌거나 Esc/미리보기 닫기로 종료한다. 지도 건설/철거·공개 변경 시 계획을 갱신하고 재고만 바뀌면 부족 여부만 다시 표시한다. 원본 마크업을 비교해 갱신 중 열린 정류장 목록을 재작성하지 않는다.

`road-build` 명령은 미리 본 경로와 신규 칸을 받아 같은 월드에서 최적 계획과 다시 비교한다. 비용·경로가 달라지거나 정류장이 삭제되면 새 경로를 임의로 짓지 않고 재확인을 요구한다. 총재료가 부족해도 일부 설치나 소비를 하지 않는다. 검증 후 신규 칸만 기존 건설 API로 설치하며 단일 편집 단계로 묶는다. 중복 요청은 변경된 신규 칸 검사로 추가 소비를 막는다. 처리 중 선택/건설 버튼을 막고, 응답 지연은 연결 상태 확인으로 안내한다. 기존 트럭 노선은 바꾸지 않는다.

주석 문구는 코드 MG10 `눈밭에서 온 주석`의 조건이다. 주석판 생산 20개와 거점 번호가 서로 다른 정류장 사이의 트럭 배송(주석광석+주석판 합계 20개)을 각각 요구한다. 같은 거점의 다른 정류장 배송, 직접 허브 입고, 초기 재고는 이 배송/생산 조건을 대신하지 않는다. 기존 `recordDelivery` 판정과 목표 ID·완료 기록은 유지하고 문구 및 정류장의 거점 번호 표시만 보완했다.

핵심 파일: `src/sim/road-plan.ts`, `src/sim/commands.ts`, `src/ui/road-builder.ts`, `src/ui/ui.ts`, `src/input/input.ts`, `src/render/renderer.ts`, `src/main.ts`, `src/sim/goals.ts`, `src/style.css`, `index.html`.

검증 범위: 22개 새 코드 검증. 독립 탐색과의 거리/꺾임/신규 칸 비교(장애물 지도 6종), 실제 정차 칸과 트럭 경로, 기존 도로 비용, 장애물·지도 마스크·연구 잠김, 재료 부족·변경된 경로·삭제·변조·중복 실패의 무변경, 플레이어별 undo/redo, 참가자 명령 재현·스냅샷 동일성, 기존 세계, UI 목록·비용·처리 상태·마크업 보존·화면 이동을 확인했다. 실제 자동 건설 도로에서 트럭이 주석광석 12개+주석판 8개를 배송하는 두 상황도 실행했으며, 다른 거점만 MG10 배송 20개로 인정됐다. 컴퓨터 유즈·실제 화면 재생·배포는 실행하지 않았다.
