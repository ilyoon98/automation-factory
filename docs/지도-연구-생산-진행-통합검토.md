# 지도·목표·연구·생산의 통합 진행 검토

2026-10-27 · [지도 공개](지도-목표별-공개-상세기획.md) · [메인 목표](목표-진행-상세기획.md) · [연구/레시피](생산체인-상세기획.md) · [경제](진행시간-경제-상세기획.md)

**현재 기획의 선행 관계와 기준 자원 예산에서 최종 납품을 막는 순환 조건은 발견하지 못했다.** 다만 이를 실제 지도 생성·플레이 검증 통과로 해석하지 않는다. 목표 공개 시점과 첫 조립 판정의 모호한 부분을 보완했고, 별도 구현 작업 폴더의 이전 지도 규칙과 최신 기획의 차이도 확인했다.

## 1. 검토 범위와 방법

- 메인 MG01~36, 공개 RV00~07, 기존 연구 20개+산업 연구 8개, 기존 레시피 20개+신규 23개를 함께 검사했다.
- 연구는 선행 연구와 비용 재료, 생산은 연구 해금·설비 해금·건설 재료·투입 재료, 채취는 지도 공개·자원 연구·채취 설비를 모두 먼저 확보할 수 있어야 한다.
- 실제 산출 가능한 품목과 시작 재고로 잠시 보유한 품목을 구분했다. 시작 재고를 목표의 새 생산으로 세지 않았다.
- 종류별 확보 가능성 모델과 실제 수량 예산을 나눠 확인했다. 모델은 무한 재료를 보장하거나 모든 연구비를 한 번에 지불한 플레이를 재현한 것이 아니다. 구체적 물류·전력·건설 공간은 문서의 보장 조건을 전제로 한다.
- 검토 기준은 현재 main의 기본 데이터와 최신 기획이다. 별도 `.claude/worktrees/regional-d09`의 검토 시점 HEAD `988730a`도 읽어 구현 차이를 기록했다. 이 작업에서 해당 구현 폴더를 수정하거나 그 테스트 통과를 주장하지 않았다.

T03/T04와 T05/T06의 연구 선행은 그대로다. 연구를 먼저 했더라도 미공개 자원은 채취하지 못하고, 지역을 먼저 공개했더라도 미연구 자원은 채취하지 못한다. UI에서 두 원인을 구분한다.

모든 메인 목표는 MG36 선행 그래프에 연결되고 신규 연구·레시피에서 생산 종류의 순환을 발견하지 못했다. 일반적인 최초 대형 조립은 P22이며, T08을 먼저 연구했다면 P23 선행도 허용한다. 목표 MG32와 연구 T08의 선행을 혼동하지 않는다. 신규 레시피의 입력 종류도 설비의 입력 수용 범위 안이었다.

## 5. 수량과 첫 자원지 검사

경제의 4.5시간 건설/연구/51모듈/5트럭 조립품/완충 재고/운영 석탄 사례를 다시 계산했다. 비용 교차 확인 58행·건설 수량 35행이 일치했다. 첫 자동화 세트는 철판 95·기어 10·돌 20으로 시작 120·40·40 안이다. 첫 트럭의 신규 철광석 예산 1,144도 시작 8,000개 안이다.

## 6. 별도 확장 구현과 최신 기획의 차이

검토 시점의 `regional-d09` HEAD `988730a`는 확장 생산·전력·목표·지도 공개 구현을 포함한다. main에 그 기능이 없다는 이전 상태 설명을 모든 작업 폴더에 일반화하면 안 된다. 다음은 읽은 코드의 차이이며 이 문서 작업에서 해당 구현을 수정한 결과가 아니다.

| 항목 | 작업 폴더에서 확인한 규칙 | 최신 기획에서 필요한 규칙 |
| --- | --- | --- |
| 초기 공개 | `regional-map.ts`의 START_REVEAL=40, 초기부터 추가 광맥 주변 포함 | RV00 시작 약 24칸, MG03에서 RV01 외곽 공개 |
| 숲 공개 | `world.ts`의 REVEAL_ON_GOAL은 MG11에서 C 공개 | MG08에서 RV03 숲 공개 |
| 시작 반경과 숲 위치 | C 중심의 A와의 거리는 약 38.63칸. 원형 40칸 초기 공개 안에 들어감 | 단계별 셀 집합으로 미래 자원 공개를 제한. 처음부터 숲 중심을 보이지 않게 생성 검사 |
| 후반 공개 | MG28은 두 번째 자원지, MG32가 전체 공개 | MG28에서 RV07의 남은 전체 공개 |
| 건설 탐사 | `place()`에서 주변 약 6칸을 추가 공개. fog.test.ts도 이 동작을 기대 | 건설 반복으로 공개 범위를 늘리지 않음. RV 목표 공개로만 확대 |

MG14 두 사막·MG19 화산·MG20 염호의 큰 분기 방향은 기획과 맞는다. H를 MG07에 공개하는 구현도 ‘늦어도 RV04’ 조건보다 이르므로 그 자체는 진행 막힘이 아니다. 표의 지도 차이를 수정할 때 기존 전체 공개 저장을 다시 가리지 않으며 테스트도 새 목표 공개 계약에 맞춰 갱신해야 한다.

실제 지도 공개 수정의 연결 지점은 `regional-map.ts` 초기 마스크, `world.ts`의 공개 묶음/건설 공개, 목표 평가와 스냅샷, `fog.test.ts`다. 같은 폴더의 기존 기능을 처음부터 중복 구현하지 말고 현재 브랜치/미커밋 상태부터 재확인한다.

## 7. 남는 검증과 별도 기획 항목

- 여러 시드에서 RV 단계마다 진입로·담수·연료 하역·공장 부지·전봇대 경유 셀이 모두 열리는지 실제 지도 생성 검증이 필요하다. 문서의 보장 조건만으로 통과했다고 할 수 없다.
- 초반 5~8분 자동화·25~35분 배송·4~5시간 납품은 실제 제작/경로/충전 대기/입력 조작을 포함한 플레이 검증이 필요하다. 종류별 확보 모델은 시간을 증명하지 않는다.
- 목재는 현재 전체 기준 사례에서 438개(통나무 219개)의 건설·연구 소비가 중심이다. 절연기판의 지속 소비 경로는 없다. 목재의 후반 지속 수요가 적다는 문제는 진행 막힘과 별개의 밸런스/사용처 보완 항목으로 남긴다. 새 레시피를 임의 추가하지 않았다.
- 선택 업적 출시 목록·자원 완전 고갈 이후 보충/반복 연구 상한은 별도 결정이다. 완료 화면은 이후 2026-10-30의 [연출 상세](공장-가동-운송-완료-연출-상세기획.md)에서 8초 카드·즉시 계속 건설·완료 시점 요약으로 구체화했다. 이번 검토로 이미 정해진 지역 공개/연구/가격을 다시 미정으로 돌리지 않는다.

이번 결과는 **기획 의존 관계·재료 수량 검토 및 구현 차이 확인**이다. 게임 코드 구현·실제 지도 통과·플레이 완주 확인과 구분한다.
