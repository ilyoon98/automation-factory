# 지역 생산망을 확인하는 UI

2026-10-27 · [메인 목표](목표-진행-상세기획.md)·[생산 체인](생산체인-상세기획.md)·[지역 인프라](지형-운송-전력-상세기획.md)의 화면 설계

**어느 거점이 무엇을 만들고, 어느 노선으로 보내고, 어떤 전력으로 돌아가는지 한 화면에서 확인한다.** 후반의 핵심 동선은 ‘조립이 느림 → 부족 재료 → 공급 거점 → 생산·운송·전력의 관측 원인’이다. 화면을 열었을 때 맵과 숫자를 보여 주는 데서 끝내지 않고, 다음에 확인할 공정으로 이동시킨다.

기존 크림색 종이·갈색 잉크·픽셀 테두리·갈무리 글꼴을 유지한다. 현재 `index.html`의 상단 버튼·왼쪽 안내·오른쪽 정보창·하단 건설 탭·미니맵을 바탕으로 확장하는 기획이다. 게임 코드는 변경하지 않는다. 화면 예시는 고정된 설계용 상태이며 실제 공장·실시간 측정 결과가 아니다.

### 정보 표시와 플레이어의 계획

플레이어가 생산 규모·공장 배치·재료 배분·차량 수를 직접 정한다. UI는 레시피의 한 회분 재료·산출·시간, 기계 자체의 명목 속도, 실제 생산·소비·배송·전력·재고와 관측된 정지 이유를 정확하게 보여 준다. 직접 입력한 계획값은 유지하되 자동으로 채우거나 최적값으로 바꾸지 않는다.

목표 생산량에서 전체 레시피 트리의 기계/차량 대수를 역산하는 계산기, 최적 공장 배치·차량 수 추천, 소비량에 따른 목표 재고 자동 추천, 연구용 물량 자동 확보는 첫 범위에 넣지 않는다. 직접 정한 노선의 운행·출고/입고 예약·충전 대기열·분산 출발·반송은 기존 운영 규칙대로 자동 처리한다. 사람의 설계와 공장의 자동 운전을 구분한다.

## 1. 화면 구성과 진입

| 화면 | 용도 | 여는 방법 |
| --- | --- | --- |
| 건설 화면 | 현재 공장을 보며 배치·편집 | 기본 화면 |
| 지도 오버레이 | 같은 지도에 전력·운송·자원·날씨를 선택해 표시 | 상단 지도 보기 버튼 |
| 운영 개요 | 지역·물류·전력을 함께 비교하고 원인을 추적 | 기존 통계 P를 운영 P로 확장 |
| 목표판 | 메인 36개와 선택형 도전의 가지·진행 확인 | O, 상단 목표 버튼 |
| 업적 | 최초·기록·심화·숨은 발견 기록 | J, 상단 업적 버튼 |
| 미니맵 | 건설 중 화면 이동·가까운 경고 확인 | 기존 M 유지 |
| 도감·연구 | 레시피·소비처·해금·재료 확인 | 기존 G·T 유지 |

P 화면은 `지역 / 생산 / 운송 / 전력` 보기를 제공하며 같은 선택 거점·품목·노선을 유지한다. 초기에는 기존 생산 통계를 우선 보여 주고, 첫 차량 운송 이후 지역 운영을 기본으로 한다. 지역 화면의 표는 생산·배송·전력을 동시에 보여 주며 보기 전환은 상세 정보와 강조 선을 바꾼다. 한 종류만 볼 때 다른 두 종류의 문제가 숨지는 않게 한다.

O·J는 목표·업적 키로 사용한다. 건설 탭 키는 Z·X·C·U·V·B·N·L·K이며, 2026-10-30 개정으로 C는 발전, U는 전력이다. 기존 건설·회전·복사 키는 유지한다. 입력 중에는 단축키와 WASD를 실행하지 않는다. Esc는 가장 위 창 → 상세 패널 → 건설 도구 순으로 닫고 포커스를 원래 위치로 돌린다.

## 2. 건설 화면의 기본 배치

상단은 게임 시각·속도·함께 하기·저장과 운영·목표·업적·도감·연구의 진입점이다. 모든 버튼을 같은 크기로 늘리지 않고, 새 게임·도움말·소리 설정은 이름이 보이는 ‘메뉴’로 묶는다. 기존 단축키 표시는 유지한다. 실제 줄 배치·좌우 정렬·팝업 앵커는 [상단 UI 상세](상단-UI-배치-앵커-상세기획.md)를 우선한다.

되돌리기·다시 실행은 기능을 발견할 수 있도록 상단에 보이는 버튼으로 유지한다. `↶ 되돌리기`·`↷ 다시 실행` 이름을 표시하고, 단축키 Ctrl+Z/Ctrl+Y는 보조 표시나 툴팁으로 제공한다. 수행 가능한 이력이 없으면 같은 위치에서 비활성 상태를 표시하며 버튼을 숨기지 않는다. 상단은 기능별 묶음·간격·선택 강조를 정리하고, 이 두 기능을 단축키나 메뉴 안에서만 찾도록 바꾸지 않는다. 실제 되돌리기 가능 범위는 기존 규칙과 완제품 사용 계약을 따른다.

왼쪽은 메인 목표 카드, 선택 과제 1개, 선택 구역의 전력·필수 재고 순이다. 경고는 관련 목표·거점 옆에 표시하고 별도 긴 목록으로 화면을 계속 밀어내지 않는다. 오른쪽은 선택한 건물·거점·노선 중 하나의 상세 정보를 보여 준다. 하단은 기존 건설 툴바다.

```text
시각·속도·되돌리기·다시 실행                     저장·함께 하기·채팅·메뉴
운영 P  목표 O  업적 J  도감 G  연구 T              지도·정보 레이어·생산량
현재 메인 목표           게임 맵과 배치 영역                   선택 대상
선택 추적 1개            거점·노선·전력의 얇은 표시             상세 정보
선택 구역 요약           필요한 원인 연결만 강조               원인으로 가기
                       기존 하단 건설 탭·건물 목록
```

처음부터 거점 8곳·물류 노선 15개를 상시 띄우지 않는다. 건설 중에는 선택 대상과 추적 목표에 관련된 선만 강조한다. 보이지 않는 공급지는 화면 가장자리의 이름·방향으로 안내한다.

설비 크기·포트 좌표·회전은 [설비 배치 상세](설비-입출구-배치-상세기획.md)를 따른다. 새 대형 조립소 미리보기는 3×3 몸체와 입력 6곳·출력 1곳을 구분한다. 연결된 벨트의 방향과 품목을 표시하고 잘못된 접점만 사유를 알린다. 빈 입구를 이유로 건물 배치를 금지하지 않는다. 선택 상세는 재료별 2회분 버퍼 6행을 보이며 ‘I1 프레임’ 같은 표준 배치는 권장 안내로 표시한다. 기존 설비의 앞면 전체 출력과 새 설비의 지정 소켓 표시를 혼동하지 않게 한다.

모듈과 고급 차량의 실제 버튼·상태는 [사용 계약](모듈-장착-트럭생성-상세기획.md) §11을 따른다. 기계에는 공급 창고·실물/예약/사용 가능 수량·현재 배치 효과와 설치/분리를, 정류장에는 기본 구매와 별개로 현지 조립품을 쓰는 고급 조립을 표시한다. 사용 중 모듈의 완료 후 분리와 작업 취소 후 즉시 분리를 구분한다. 고급 조립 성공 후 새 차량을 선택해 노선 미지정·실제 충전 상태를 보여 준다. 처리 중 중복 클릭을 막되 별도 승인창은 추가하지 않는다.

### 2.1 하단 건설 도구의 비용과 차단 상태

하단은 사용자 선호에 따라 **카드마다 비용을 항상 표시하는 방식**을 기본으로 한다. 기존 종이색·픽셀 테두리·카테고리 이름·단축키를 유지한다. 비용은 기존 자원 아이콘과 개수를 함께 표시하고, 이름은 툴팁·키보드 접근·선택 상세에서 확인한다. 게임의 `itemIcon`/`itemIconUrl`과 `buildingIconUrl`을 사용한다. 비용과 부족 판정은 해당 세계의 실제 건설 비용·허브 건설 재고를 기준으로 하며 기계 내부·먼 창고의 실물을 합치지 않는다.

| 상태 | 카드 표현 | 클릭·숫자키 동작 |
| --- | --- | --- |
| 건설 가능 | 종이 배경·체크와 ‘건설 가능’. 실제 선택한 경우에만 금빛 테두리·선택 체크 | 해당 건설 도구 선택 |
| 연구 잠김 | 회색 사선 배경·자물쇠와 ‘연구 잠김’ 띠. 이름은 읽히게 유지 | 건설 도구를 해제하고 필요한 연구·연구 보기 표시 |
| 재료 부족 | 옅은 주황 배경·경고 아이콘과 ‘재료 부족’ 띠. 부족한 자원 수량 강조 | 건설 도구를 해제하고 아이콘·이름·보유/필요·부족량 표시 |

잠금이 재료 부족보다 우선하며 잠긴 항목에 건설 가능/금빛 선택 표시를 쓰지 않는다. 두 차단 상태도 목록에서 숨기지 않는다. 정보 확인 중인 카드와 실제 건설 도구 선택을 구분한다. 색만으로 판정하지 않고 상태 이름·아이콘을 항상 함께 둔다. 선택했던 도구가 자원 변화로 건설 불가가 되면 차단 표시를 선택 강조보다 우선하며 실제 배치 시 조건을 다시 검사한다.

하단의 상시 상세 줄에서는 ‘드래그로 연속 배치’, 회전/취소 같은 반복 조작 안내를 빼고 설비 이름·크기·전력·건설 상태·막힌 이유만 표시한다. 조작법은 기존 도움말·초기 안내에서 유지한다. 카드 폭이 부족하면 좌우 버튼과 현재 항목 범위/전체 개수를 보여 주고 이름을 줄여 읽기 어렵게 만들지 않는다. 숫자키는 원래 목록 순서를 유지하며 화면을 넘길 때 다시 1부터 매기지 않는다.

### 2.2 상단 줄 배치와 앵커

[상단 UI 상세](상단-UI-배치-앵커-상세기획.md)에 논리 폭 900px 이상 2줄, 640~899px 3줄, 그 미만 6개 묶음 줄을 정했다. 되돌리기·다시 실행은 모든 폭에서 이름이 보이는 버튼으로 유지한다. 각 줄은 좌우 8px에 맞추며 줄 사이 1px 선을 둔다.

상단바의 실제 논리 높이를 `H_top`으로 측정한다. 메뉴는 버튼 오른쪽에 맞추되 전체 상단바 아래 `H_top+8px`에서 열고, 연구 완료 카드는 같은 높이의 화면 중앙에 둔다. 좌우 판·큰 창의 top과 최대 높이도 실제 상단/하단 높이에 연동한다. UI 배율 변환·겹침 순서·작은 화면 배치는 링크한 상세 계약을 따른다. 시안의 좌표 안내선은 검토용이다.

### 2.3 발전·전력 건설 탭과 진행 순서 (2026-10-30 개정)

최신 사용자 요청에 따라 기존 전력 통합 탭을 **발전 C**와 **전력 U**로 나눈다. 발전 C는 풍력·석탄·태양광·수력·연료·지열 순서이며 풍력은 C1이다. 전력 U는 전봇대·변전소·축전기 순서다. 연료·지열 발전기는 발전에만 등록한다. 별도의 배전 탭이나 중복 카드는 만들지 않는다. 이전의 ‘기존 발전 4종 번호 유지’ 규칙은 이 개정으로 대체한다.

모든 건설 목록은 초기 사용 가능 설비 → 목표·연구 단계 순으로 고정한다. 같은 단계에서는 생산 흐름에 맞춘다. 연구 가지를 어떤 순서로 진행해도 번호가 갑자기 이동하지 않으며, 잠긴 카드·재료 부족 표시는 유지한다. 탭의 카드·숫자키·도감 분류는 같은 데이터를 사용한다.

| 탭 | 1번부터의 고정 순서 |
| --- | --- |
| 물류 Z | 컨베이어 → 지하 컨베이어 → 분배기 → 합류기 → 우선 분배기 → 스마트 분류기 → 고속 컨베이어 |
| 생산 X | 채굴기 → 제련로 → 조립기 → 고급 채굴기 → 양수기 → 분쇄기 → 세척기 → 분리기 → 전기로 |
| 발전 C | 풍력 발전기 → 석탄 발전기 → 태양광 패널 → 수력 발전기 → 연료 발전기 → 지열 발전소 |
| 전력 U | 전봇대 → 변전소 → 축전기 |
| 보관 V | 창고 → 하역기 |
| 운송 B | 도로 → 정류장 → 충전기 |
| 숲 N | 벌목기 → 제재소 → 식목기 |
| 산업 L | 수액 채취기 → 화학 반응기 → 시추기 → 정유소 → 전해로 → 대형 조립소 |

청사진 K는 마지막에 유지한다. 전력 U·산업 L은 해당 설비가 없는 기존 세계에서 숨기고 Tab 순회에서도 제외한다. 기존 세계의 발전 C는 풍력·석탄·태양광·수력만 표시한다. 좁은 화면의 탭은 줄바꿈하고 실제 하단 높이를 기준으로 안내와 패널 위치를 갱신한다.

전력 보기 레이어·운영 창의 전력 보기와 건설 탭은 같은 이름을 쓰더라도 각각 지도 상태 확인·운영 비교·설비 건설이라는 역할을 유지한다. 탭 분리는 실제 공급 범위·발전량·건설비 변경이 아니다.

### 2.4 목표별 지도 공개 표시

[RV00~07 지도 공개](지도-목표별-공개-상세기획.md)를 기본 맵·미니맵·5개 레이어·자원 검색·위치 이동·툴팁에 공통 적용한다. 미공개 위치/잔량/현지 날씨를 다른 화면에서 먼저 노출하지 않는다. 목표 완료 시 새 공개 영역만 짧게 강조하고 선택형 위치 보기로 이동한다. 강제 카메라 이동·정지·추가 조사 확인 버튼은 없다. 기상 안개는 공개 범위를 되돌리지 않는다. 앞선 전체 공개 독립 시안은 배치 참고이며 현재 공개 마스크 동작의 검증 결과가 아니다.

### 2.4 지도 커서와 겹친 회수 더미 (2026-10-30 구현)

바닥의 회수 더미는 컨베이어·설비와 같은 칸에 있을 수 있다. 빈손으로 해당 칸을 클릭하면 더미를 설비보다 먼저 회수한다. 회수 뒤에는 같은 칸의 설비를 다시 선택할 수 있다. 화면 이동 드래그·복사·단체 선택·핑·건설·철거는 현재 조작을 유지하고 우연한 회수를 실행하지 않는다.

커서는 건설 망치, 철거 빨간 표시, 회수 손, 설비 선택 포인터, 화면 이동 중 쥔 손, 불가 상태 금지 표시로 구분한다. 회수 대상 상자에는 초록 테두리와 품목 아이콘·수량·클릭 안내를 표시하며 밑에 있는 설비 이름으로 회수 안내를 덮지 않는다. 건설 가능 여부는 실제 공간·연구·재료·벨트 교체 환급을 기준으로 하고, 줌/화면 이동 뒤에도 실제 화면의 마우스 위치와 강조 칸을 맞춘다.

### 2.5 연구 해금 아이콘 (2026-10-30 구현)

연구 카드의 해금 목록은 설비 그림+설비 이름, 레시피 결과 아이템 그림+레시피 이름으로 표시한다. 결과가 여러 종류인 레시피는 모든 결과 아이콘을 표시한다. 아이콘은 기존 게임 그림을 16px로 사용하고, 항목 단위로 줄바꿈해 좁은 카드에서도 그림과 이름의 관계를 유지한다. 설명·선행 연구·연구비·완료/잠금 상태는 기존 동작을 따른다.

### 2.6 설비 생산·재료 숫자 정렬 (2026-10-30 구현)

선택 설비의 생산 현황과 재료 사용량은 모두 왼쪽 현재 → 오른쪽 최대 순서로 표시한다. 재료는 `재료 사용 /분` 아래 `아이콘 이름 · 지금 29.8 · 최대 40`처럼 표시한다. 측정 중인 현재 값은 `—`로 두고 최대값은 표시한다. 가동률·멈춘 이유와 비율은 유지하고, ‘분당 몇 개를 공급하면 100%’·‘지금 몇 개만 들어옴’ 및 기계/발전기 증설 권유 문장은 제거한다. 수치 계산과 최근 15초 집계는 유지한다.

### 2.7 기존 UI의 중복·혼동 정리 (2026-10-30 구현)

regional-d09 작업본의 최신 표시 규칙이며 이전 화면 예시보다 우선한다. 일반 설비의 설명은 선택창 아래 `설비 사용법`으로 접고, 연결 선택·충전 예산도 필요할 때 펼친다. 동일 설비를 보는 동안 펼친 상태는 유지한다. 미해금 모듈 설정은 숨기고 연구 이후에 표시한다. 연결 실패·설치 조건·비용·분리 시 반환/되돌리기 제한 등 조작 판단에 필요한 안내는 유지한다.

- 통계는 생산·사용 각각 현재 / 최대, 현재 증감·최대 증감으로 표기한다. 증감은 생산−사용의 분당 값이며 허브 재고와 분리한다. 기계 몇 대를 더 지으라는 자동 추천과 긴 공급 설명은 제거한다.
- 전력 막대와 옆 퍼센트는 모두 전력 충족률이다. 수요/용량·충전 수요·거점 충전 배정/예산·실제 수신 충전을 구분한다. 발전 출력은 한 번만 표시하며 태양광·풍력에 기본 정격을 현지 최대값처럼 붙이지 않는다. 기계의 고정 소비값은 `기본 작업 전력`으로 표시한다.
- 정류장 설정은 `벨트 입출력`, 차량 노선 작업은 `트럭에 싣기 / 트럭에서 내리기`로 구분한다. 목표 재고는 현재/목표, 입고 예정은 별도 줄이다. 차량 상태와 같은 내용을 아래에 반복하지 않는다. 주행거리가 긴 노선은 정류장 간 거리 초과라고 알리고 중간 충전기를 무시한 실패 판정을 쓰지 않는다.
- 충전기는 실제 충전원과 `receivedCharge`를 기준으로 표시한다. 인접 충전기가 여럿이어도 차량·전력을 중복 집계하지 않는다. 하역기는 설비와 겹친 회수 더미를 출처로 인식하고 최대 하역량을 명시한다.
- 창고 철거의 반환 설명은 세계 규칙을 따른다. 확장 세계의 건설비는 허브, 내용물은 현지 더미다. 컨베이어 목록의 실물 개수는 품목이 같아도 갱신한다. `빼기`가 줄 전체에 적용된다는 범위 안내는 유지한다.

도움말·도감의 상세 정보, 목표·업적 조건, 연구 선행과 비용은 상세 확인용으로 유지한다. 툴팁에서는 선택창의 긴 필요 재료 목록과 반복 조작 설명을 줄인다. 컴퓨터 유즈 없이 빌드·355개 테스트를 통과했으며 실제 화면의 밀도·줄바꿈 확인은 남아 있다.

### 2.8 Shift 직선 설치 (2026-10-30 구현)

건설 도구를 들고 Shift+좌클릭 드래그하면 처음 이동한 방향의 가로/세로 축으로 고정한다. 대각선이면 이동량이 큰 축, 같으면 가로를 선택하고 Shift를 유지하는 동안 바꾸지 않는다. 미리보기·설치 좌표·가로/세로 점선 안내가 같은 좌표를 사용한다. Shift를 놓으면 자유 설치, 드래그 도중 다시 누르면 마지막 배치 칸부터 새 직선을 시작한다.

빈손의 Shift 드래그는 기존 단체 선택이며 Ctrl 복사·청사진 배치는 기존 조작을 유지한다. 장애물을 우회하지 않고 기존 건설 불가 판정을 적용한다. 자원 소비와 드래그 전체의 한 단계 되돌리기를 유지한다. 지하 컨베이어의 클릭 배치 제한도 유지한다. 마우스를 떼거나 Esc·포커스 상실·도구 변경 시 축 고정을 끝낸다.

### 2.9 정류장 사이 도로 자동 건설 (2026-10-30 구현)

정류장 A 정보의 `도로로 연결` → 공개된 정류장 B 선택 → 지도 경로·길이·꺾임·신규/기존 칸 수·자원 아이콘 비용 확인 → `건설` 순서다. 연결 전의 정류장도 목록에 나오며 목록에 거점 번호를 함께 표시한다. `경로 보기`는 도로 쪽으로 카메라를 맞추고 기존 줌 범위에서 축소한다.

경로는 양 정류장 테두리의 정차 가능한 칸을 연결한다. 거리 우선, 같은 거리의 최소 꺾임, 둘 다 같으면 신규 도로 최소 순서다. 건물·호수·고무나무·미공개 지역을 피하고 기존 도로는 재사용한다. 미리보기는 개인 화면에만 있고 자원·건물을 변경하지 않는다. 지도에는 새 도로를 초록색 칸, 연결 경로를 파란 선과 A/B로 표시한다.

건설 시 확인한 경로와 신규 칸을 다시 검증하고, 변경되었거나 재료가 부족하면 일부 설치 없이 재확인한다. 비용은 신규 구간만 소비하며 한 단계 되돌리기를 지원한다. 이미 최적 경로가 전부 도로이면 추가 비용 없음·설치됨으로 표시한다. 다른 설비 선택·Esc·창 닫기로 미리보기를 끝낸다. 트럭 노선·거점 배치는 자동으로 변경하지 않는다.

주석 배송 안내도 구체화했다. 코드 MG10은 주석판 20개 생산과 별도로, 주석광석·주석판 합계 20개를 거점 번호가 다른 정류장에 트럭으로 내리는 조건이다. 같은 거점 배송과 직접 허브 입고는 이 배송 실적에 포함하지 않는다. 정류장 기본 정보에 거점 번호를 표시한다. 판정·목표 ID·완료 이력은 유지한다.

## 3. 운영 개요의 중심 화면

상단 줄 배치는 §2.2를 따른다. 이 절의 운영 화면 내부 보기와 상단바 줄을 혼동하지 않는다.

운영 화면은 상단의 보기 선택, 지역 비교 표 또는 생산망 개략도, 선택 대상 상세로 구성한다. 기본 ‘지역’ 보기는 8거점의 세 상태를 한눈에 읽는 표를 우선하고, 생산·운송·전력 보기에서 관계도를 펼친다. 표와 큰 지도를 항상 위아래로 쌓아 중요한 행이 화면 밖으로 밀리지 않게 한다. 개략도는 실제 지형 맵과 구분해 ‘공급 관계’라고 표시한다. 물류 보기에서는 실제 정류장 노선과 거리, 전력 보기에서는 실제 전봇대 연결과 같은 망의 범위를 표시한다. P에서 위치 버튼을 누르면 운영 화면을 접고 게임 맵의 실제 위치로 이동한다. 미니맵 M의 이전 켜짐 상태는 유지한다.

| 지역 표의 열 | 내용 |
| --- | --- |
| 거점 | 이름·지형·운영 상태. A~H 대신 플레이어 이름 사용 가능 |
| 대표 생산 | 실제 생산/설정한 계획량, 부족 품목 한 개와 추가 개수 |
| 운송 | 실제 배송/요청량, 지연 편·적재 대기·충전 대기 구분 |
| 전력 | 현재 작업 충족률, 부족 kW 또는 정상 표시 |
| 재고 | 가장 먼저 모자랄 핵심 품목과 예상 버티는 시간 |

행을 누르면 개략도·표·상세의 선택이 함께 바뀐다. 평상시에는 안정적인 이름순을 유지하고 ‘문제 먼저’는 사용자가 선택한다. 갱신할 때 행이 계속 재정렬되어 클릭 대상이 움직이지 않게 한다. 같은 지형의 다른 거점은 별도 행이며, 전력 전용 거점은 생산 0으로 오류 표시하지 않고 ‘발전 거점’으로 분류한다.

전체 생산·전력의 합계만으로 정상 상태를 판단하지 않는다. 공장 평균이 99%여도 한 거점이 80%라면 그 거점이 표시된다. 색에는 항상 ‘재료 부족·배송 지연·전력 부족·측정 중’ 같은 글자를 붙인다.

## 4. 수치의 시간 범위와 단위

| 수치 | 표시와 측정 |
| --- | --- |
| 운영 생산·소비·배송 | 최근 120초 실제 수량을 분당 환산. 처음에는 ‘측정 중’과 경과 시간 표시 |
| 메인 목표 | 실제 생산·유효 배송·목적지 사용의 누적 수량. 중단돼도 보존 |
| 선택 심화 속도 조건 | 완전한 최근 60초 실제 완료량 Q60과 조건 충족 누적 시간. 미달에는 누적 일시 중지 |
| 구역 현재 전력 | 현재 요청·공급을 1초 값으로 표시, kW 또는 MW 단위 통일 |
| 선택 심화의 전력 충족 | 최근 60초 작업 공급/요청 에너지, 충전 제외 |
| 축전 | 저장 MJ, 충·방전 kW, 하한, 현재 부족량으로 버틸 시간 |
| 배송 신뢰도 | 완성된 운행 주기의 요청 대비 하역량, 정시 편/대상 편. 측정 전에는 0% 대신 ‘주기 측정 중’ |
| 재고 시간 | 사용 가능한 현지 재고/계획 소비량. 소비 계획이 없으면 시간 대신 개수 |

운영 화면의 ‘1.5개/분’은 최근 120초에 실제 3개 생산했다는 뜻이다. Q60 완료 개수를 1.5개라고 표시하지 않는다. 순간 수치·이동 평균·명목 최대치를 섞어 같은 ‘생산량’으로 쓰지 않는다. 계획값은 ‘계획’, 설치 용량은 ‘최대’, 실제값은 ‘실제’라고 표시한다.

지역별 실제 생산은 완성 사건, 입출고는 이동 사건으로 나눈다. 중계 거점의 입고를 그 거점의 생산으로 더하지 않는다. 생산망 개략도의 계획량은 사용자가 설정한 제품·노선 계획이며, 지금 있는 기계가 자동으로 그만큼 만들 수 있다는 뜻이 아니다.

## 5. 거점 상세와 부족 재료 추적

거점 상세 첫 줄은 대표 제품·생산 상태, 그 아래는 `실제 / 계획`, 현지 재고·입고·소비·출고다. `생산 / 입출고 / 전력` 하위 보기로 세부를 확장한다. 일반 상태에서는 핵심 품목 5~7개와 하나의 주된 문제만 보여 준다.

예를 들어 H의 설비 모듈 생산이 부족하면 다음 순서로 따라간다.

1. H 상세에 ‘절연 모터 재고 4개, 계획 소비 8.4개/분, 약 29초분’을 표시한다.
2. 품목을 누르면 공급하는 C 거점과 R07을 함께 강조한다. 실제 배송·예정 도착·목표 재고를 비교한다.
3. 배송은 정상인데 C 생산이 계획보다 낮으면 ‘공급 거점 생산 부족’을 원인 후보로 표시한다.
4. C로 이동하면 해당 모터 기계의 재료 대기·출력 막힘·전력 부족 기록을 보여 준다.
5. 전력 부족이 실제 관측됐다면 C 전력 상세에서 요청·공급·수전 제한과 발전 지형을 확인한다.

운송이 느리다는 이유만으로 트럭 추가를 권하지 않는다. 공급지 생산 부족, 적재 설정, 목적지 포화, 도로 단절, 충전·전력 부족을 나누어 보여 준다. 여러 원인이 겹치면 관측된 사실을 먼저 표시하고 확정하지 못한 것은 ‘확인 필요’로 둔다. 인접해 보이는 거점을 임의로 공급자로 추정하지 않고 실제 배송·설정 관계를 사용한다.

지역 상세의 ‘공급 거점 보기·노선 보기·전력 보기’는 선택 대상을 바꾼다. 뒤로 가기 경로는 `조립 거점 > 모터 > 공급 거점 > 전력`처럼 보존한다. 선택한 건물·노선이 사라졌으면 삭제된 대상을 표시하고 대체 대상을 고르게 한다.

## 6. 운송 상세

노선은 이름, 출발·도착·중계, 실제 도로 거리, 차량 수·종류, 계획·실제 물량을 보여 준다. 정류장별 품목 표에서 `요청/편 · 적재 상한 · 실제 적재 · 실제 하역 · 목적지 재고`를 비교한다. 상세에서는 출발지 가용·출고 예약·이번 편 예정·목적지 현재·입고 예정·목표를 구분한다. 예약은 자동 처리하고 조작은 품목·상한·목표·주기로 한정한다. 기본 대수만 늘려도 출발지 물건이 부족한 상태는 해결되지 않는다는 것을 수치로 드러낸다.

운행 시간은 주행·하역·충전·대기 막대로 나누고 다음 출발·도착 시각을 표시한다. 날씨 전환·새 도로·대기열 때문에 예측이 불안정하면 예상 범위 또는 ‘지연 중’으로 표시한다. 배터리는 다음 충전까지의 실제 거리·필요 에너지·여유를 보여 준다. 빈 귀환은 정상 회송으로, 목적지 목표 재고가 차서 쉬는 것은 수요 충족으로 표시한다.

같은 노선의 차량은 분산 출발 간격을 미리 볼 수 있다. 주기·품목·요청량을 바꿀 때 단기 통계는 다시 측정하지만 메인 누적 실적·선택 심화의 충족 누적 시간·성공 배송 횟수는 남는다고 해당 설정 옆에 표시한다. ‘계획 적용’은 바뀔 노선·수량을 보여 준 뒤 사용자 조작으로 적용하며 게임 상태 변경은 공용 명령으로 전달한다.

### 6.1 차량의 작은 조작 개선

차량 운영을 위한 별도 자동 계획 시스템은 추가하지 않는다. 기존 차량 선택·노선 복제·위치 이동 기능을 다음 표시와 연결한다.

| 항목 | 첫 개선 범위 |
| --- | --- |
| 목록 한 줄 | 차량 이름/번호·기본/고급 종류, 현재 출발→도착, 실은 화물/적재 용량, 배터리, 실제 상태 |
| 화물 상세 | 한 품목으로 축약하지 않고 품목 아이콘·개수, 현재 적재/배송/반송 단계 구분 |
| 대기 사유 | 재료 부족·충전 중·적재 차례·수요 충족·경로 단절을 분리. 빈 귀환은 정상 회송으로 표시 |
| 지도 이동 | 현재 ‘트럭으로 가기’ 유지. 차량 선택 시 그 차량의 실제 노선만 강조하고 출발/도착 정류장으로도 이동 |
| 같은 노선 차량 추가 | 기존 기본 차량 노선 복제 버튼을 쉽게 접근하도록 배치. 고급 차량은 사용 계약에 따라 실제 현지 조립품을 별도 지불 |
| 같은 경로 묶어 보기 | 목록의 접기/펼치기용 묶음. 경로가 같아도 품목·주기 설정이 다르면 차이를 표시. 차량 계획을 자동 병합·일괄 변경하지 않음 |

목록의 묶음은 저장된 실제 정류장 순서와 싣기/내리기 동작을 기준으로 하고 설정 차이를 숨기지 않는다. 필요한 대수나 출고 우선순위를 UI가 정하지 않는다. 실제 노선·품목·상한·주기 변경은 선택한 대상에 플레이어가 적용한다. 첫 범위에 자동 배차·최적 경로 설계·별도 차고·도로 충돌을 추가하지 않는다.

### 6.2 도로로 갈 수 있는 정류장과 간결한 운송 화면

2026-10-30 사용자 피드백에 따라 정류장 선택은 현재 트럭 위치에서 실제 도로로 도달 가능한 곳만 제공한다. 단순 접도 여부로 다른 도로망의 정류장까지 포함하지 않는다. 기존 목적지가 끊기거나 철거됐으면 해당 선택과 이유를 남겨 수리/재설정할 수 있게 하고 노선을 자동 변경하지 않는다.

트럭 기본 화면은 상태·실물 화물·배터리·정류장 순서와 싣기/내리기를 우선한다. 품목별 운송 설정·운행 통계·도움말·차량 관리는 이름이 보이는 접기 항목으로 옮기고 계획 사용 중이면 품목 수를 제목에 표시한다. 정류장은 화물·차량을 우선하고 충전/전력 상세·고급 조립·목표 재고·긴 설명을 접는다. 도로 단절·배터리 거리 부족·충전 전력 없음/부족은 접힌 항목에 숨기지 않는다. 펼친 상태는 같은 대상의 편집/갱신 중 유지한다.

후속 사용자 결정으로 각 노선 정류장에 이름이 보이는 `지도에서 보기`를 제공한다. 정류장 중심으로 개인 카메라만 옮기고 선택한 트럭·노선·보기 설정은 유지한다. 도로가 끊겨도 존재하는 공개 정류장은 볼 수 있으며 미지정/철거/미공개 대상은 이동하지 않는다.

품목 선택은 `출발지에 있음` → `다른 품목`으로 나눈다. 일반 노선은 해당 싣는 정류장의 적재함, 품목별 계획은 연결 창고까지 포함한 실제 공급 풀의 품목을 우선한다. 재고가 없거나 아직 공급하기 전이어도 전체 55품목을 선택할 수 있고 물도 포함한다. 목록을 고를 때 그 목록만 갱신해 현재 선택·미적용 계획의 상한/주기·다른 입력을 보존한다. 재고 수량 변화마다 전체 설정 창을 다시 만들지 않는다.

정류장 배치 시 접도 면·실제 정차 칸을 테두리/연결선과 `P`로 표시한다. 대각선이나 한 칸 떨어진 도로는 연결로 표시하지 않는다. 도로 미연결은 설치 전에도 알리되 정류장 선건설을 막지 않는다. 상차/하차와 벨트 입고/출고는 실제 성공 사건에 한해 읽기 쉬운 아이콘 이동과 정류장 표지로 보여 준다. [정류장 배치·입출고 구현](정류장-배치-입출고-연출-구현-2026-10-30.md)의 실제 시간 0.55초·미공개 마스크·효과 줄이기·묶기 상한을 따른다.

실제 regional-d09 작업본에 반영했고 [구현·검증 기록](운송-선택-정보정리-구현-2026-10-30.md)에 도로 판정·기존 동작 보존·빌드/319테스트/10화면 검증을 적었다. 루트 main의 옛 src에 구현됐다는 뜻은 아니며 배포는 별도다. 이 절이 앞의 정보 목록을 모두 상시 펼쳐 표시한다는 해석보다 우선한다.

## 7. 전력 오버레이와 상세

전력의 기본 진입은 운영 창보다 **현재 지도 위의 전력 보기**다. 카메라·건물 위치를 유지하며 지형을 옅게 하고 공급 범위·연결 망 경계·실제 전선을 강조한다. 정상은 실선, 부족은 주황 사선과 부족 kW, 미연결은 끊긴 선과 문구, 수요 없음은 회색 점선이다. 거점 정체성·연결 망·상태 색은 분리한다. 구역을 누르면 기존 우측 상세에 수치가 나타난다. 목표 추적과 독립적으로 언제든 켜고 끌 수 있다.

지도 보기 목록은 기본·전력·운송·자원·날씨이며 한 번에 한 주제만 강조한다. 온도·세균처럼 아직 없는 시뮬레이션의 레이어는 만들지 않는다. 현재 날씨·지역별 영향·입력·좁은 화면 규칙은 [지도 레이어 상세](날씨-지도레이어-상세기획.md)를 따른다.

전력 요약은 연결 망 전체의 `작업 요청+배정 차량 충전`, `실제 발전+방전`, `축전 입력/저장/충전 손실`을 구분한다. 거점별 발생·소비 기여를 별도로 표시하고 같은 발전을 수전으로 다시 더하지 않는다. 수요 0은 대기다.

발전원별 실제 공급, 날씨·낮밤 배율, 거점별 충전 예산과 대기 차량을 보여 준다. 전선은 실제 연결과 양 끝 노드·같은 망을 강조한다. 선별 방향/전류·손실·상한은 표시하지 않는다. [전력망 개정](전력망-연결-독립시작-개정.md)에 따라 같은 망 부족은 함께 영향을 받고 독립 망은 보호된다. 저장 전력의 버틸 시간은 현재 수요·공급을 유지한다는 가정으로 표시한다. 미래 기상을 읽거나 축전 잔량만으로 다음 날까지 버틴다고 보장하지 않는다.

전봇대·변전소·발전기 배치 시 소속 구역·공급 범위·예상 여유를 맵에 보여 준다. 화산 태양광 0, 숲 풍력 0.75배처럼 현지 입지 차이는 설치 전에 확인한다. 켜진 구역 경계는 도로·벨트·아이템을 가리지 않는 얇은 표시로 그린다.

## 8. 목표와 업적 화면

O 목표판은 장별 메인 가지와 선택 도전을 나누고 완료·진행 중·준비 가능·선행 필요 상태를 보여 준다. 선행이 필요한 목표를 누르면 연구 또는 부족한 생산 경로로 이동한다. 복합 목표의 진행도를 평균 퍼센트 하나로 줄이지 않고 누적 생산·배송·실제 사용을 각각 표시한다. MG36은 ‘설비 모듈 허브 납품 12/50개’이며 현지 재고·운송 중·프로젝트 납품 완료를 구분한다. 목표판에는 ‘허브 위치’와 ‘부품·레시피’를 제공하고 ‘전력 부족 확인’은 넣지 않는다. 전력 비율과 분당 생산량은 운영 진단에 표시하며 메인 달성 조건으로 쓰지 않는다.

J 업적은 `최초 / 기록 / 심화 / 숨은` 탭이다. 공개 업적의 검색·분류·미달성 필터·추적 1개를 제공한다. 기록과 심화는 네 메달·다음 조건을 표시한다. 선택 시간 조건은 ‘충족 누적 92/180초 · 잠시 멈춤’처럼 쌓인 시간을 보존해 보여 준다. 숨은 업적은 달성 전 이름·정확한 수치·진행도를 검색·정렬·툴팁에도 내보내지 않고 힌트만 보여 준다. 과거 30종을 복구하지 못했거나 탐사를 아직 만들지 않았다면 그 기록을 완료율 분모에 넣지 않는다.

진행 시간·경제 기획의 목표 분 수치는 개발용 밸런스 기준이다. 플레이 화면에 실패 카운트다운으로 표시하지 않는다. 연구 화면은 연구비와 해금 설비 건설비를 구분하고 현지에 공급할 제작 재료까지 허브에서 자동 결제하지 않는다.

메인 36개 완료율과 업적의 활성 공개 기록 완료율은 별도다. 숨은 업적은 별도 발견 수로 표시한다. 총 후보 116종·290기록은 설계 문서의 수이며 플레이 화면에 그 숫자를 고정해 넣지 않는다. 실제 활성 목록으로 계산한다.

같은 원인으로 C 전력·C 모터·H 재료 경고가 생기면 ‘C 전력 부족, H 포함 2곳 영향’으로 묶고 세부에서 펼친다. 인과를 확인할 수 없으면 관련 경고로 묶을 뿐 확정 원인이라고 부르지 않는다. 수치가 잠깐 흔들릴 때마다 팝업·소리를 반복하지 않는다. 악화·회복·새 원인은 구분한다.

목표와 최초 업적이 동시에 완료되면 하나의 알림에 함께 표시한다. 여러 메달 달성은 묶고, 저장 로드·중간 참가의 과거 기록은 소리 없이 반영한다. 경고는 설정에서 접어도 지역 표의 문제 상태는 확인할 수 있다.

### 9.1 연구 완료 축하 카드

현재 코드에는 연구 성공 토스트(`src/ui/ui.ts`)·연구 효과음(`src/main.ts`)·허브의 별 반짝임(`src/render/renderer.ts`)이 있다. 이를 바탕으로 화면에서 해금 결과를 확인할 수 있는 축하 카드를 더한다. 기존 효과를 없는 기능으로 보고 중복 구현하지 않는다.

- 처음 완료하는 일반 연구와 T01~T08은 화면 상단 중앙에 `연구 완료`·아이콘·연구 이름·새로 열린 설비/레시피 아이콘 최대 3개와 나머지 개수를 담은 카드를 표시한다. `해금 보기`는 해당 연구 상세를 연다.
- 첫 연출안은 카드 등장 때 약 0.8초의 작은 픽셀 폭죽, 연구 아이콘 뒤 빛이 약 1.5초 동안 한 바퀴 돌고 정지, 카드 약 4초 후 자동 닫기다. 종이·갈색 잉크·금빛 픽셀 표현을 사용한다. 연출 시간은 시제품에서 조정한다.
- 카드는 게임을 멈추거나 연구 시간을 추가하지 않는다. 지도 전체를 가리는 배경을 깔지 않고 카드를 제외한 화면 조작을 유지한다. X·Esc로 즉시 닫을 수 있고, 키보드 포커스를 강제로 빼앗지 않는다. 실제로 조작한 경우에만 카드에 포커스를 둔다.
- 반복 연구는 단계 이름과 결과를 작은 완료 알림으로 묶어 표시한다. 짧은 시간에 여러 연구가 완료되면 카드 한 장을 유지하고 나머지는 순서대로 모아 보여 준다. 게임의 연구 적용은 연출 순서를 기다리지 않는다.
- 실제 연구 성공 사건 하나에 소리와 카드/허브 효과를 한 번만 연결한다. 연구 버튼 콜백과 상태 증가 감지 양쪽에서 같은 소리를 중복 재생하지 않는다. 함께 하는 사람에게도 그 세션에서 새로 완료된 연구를 한 번 표시한다.
- 저장 불러오기·중간 참가·명령 재수신으로 과거 연구의 폭죽을 다시 터뜨리지 않는다. 애니메이션 시간은 개인 화면 표현으로만 사용하고 생산·날씨·목표 판정 시간을 바꾸지 않는다.
- 효과 줄이기에서는 폭죽·회전·확대 동작을 생략하고 정적인 완료 카드로 같은 이름·해금 정보를 제공한다. 기존 효과음 설정을 유지한다.

공장·운송·건설·날씨와 최종 완료는 [연출 상세](공장-가동-운송-완료-연출-상세기획.md)를 따른다. 연구의 기존 4초 카드·폭죽·빛 회전은 유지한다. 최종 완료는 작은 폭죽과 8초 카드·즉시 계속 건설, 완료 시점의 경과 시간/생산 거점 수/납품량 요약으로 구체화했다. 효과를 줄여도 상태와 완료 정보는 동일하다.

## 10. 시각 방향과 접근성

기준 팔레트는 종이 `#fbf3df`, 잉크 `#3b2716`, 구리 `#b35c12`, 정상 `#3f8a3a`, 주의 `#b7791f`, 중단 `#c0392b`다. 기존 종이 음영·베벨을 활용하고 모서리와 그림자는 픽셀 방식으로 유지한다. 운영 표 전체를 빨강·초록 면적으로 채우지 않고 상태 글자·작은 표시와 선택 선에 색을 쓴다.

제목은 갈무리의 큰 정수 배율, 본문은 Galmuri11 기본 12px 배수, 숫자는 자릿수가 고정된 정렬을 사용한다. 기존 ‘글자 또렷하게’ 설정을 모든 새 창에도 적용한다. 작은 화면에서 글자를 더 줄이기보다 열을 접거나 상세를 아래로 옮긴다.

1280px 이상은 개략도와 상세를 나란히, 900~1279px은 표의 부가 열을 접고 선택 상세를 넓힌다. 그 아래는 거점 목록 → 선택 상세의 단일 열로 바꾼다. 화면 예시는 320px에서도 내용이 겹치지 않도록 구성하지만 실제 게임의 최소 지원 해상도는 별도 성능·입력 검증으로 정한다. 키보드 포커스·색 외 상태 문구·감소된 동작 설정을 지원한다.

생산 탭 X와 별도 산업 탭 L의 목록은 §2.3을 따른다. 숫자키는 현재 목록에 대응하고 활성 탭을 항상 표시한다. 한 탭은 최대 9개로 두어 모든 설비를 숫자키로 고를 수 있게 한다.

현지 회수 대상은 허브 재고와 분리해 건물 위치·품목·수량으로 표시해야 한다. 레시피·정류장 모드 변경과 철거 전에 남는 화물과 진행 중 투입물을 알려 주고, 회수로 새 생산·배송·납품 수량이 생기지 않게 한다. 구체적인 회수 더미·하역기 입력 대상·예약량·반송과 설정 변경 표시는 [물류 운영 규칙](물류-회수-운영규칙.md)을 따른다.

## 11. 정보와 구현 순서

계측은 시뮬레이션의 실제 생산·입출고·작업 에너지·차량 상태·노선 개정에 기반한다. UI는 그 집계를 읽는다. 화면이 닫혀 있어도 목표·업적과 계측은 같은 틱에 진행한다. 개인의 선택·필터·추적·창 크기는 공장 상태와 분리한다.

단기 집계는 거점·품목·노선별 제한된 시간 창으로 유지하고 모든 아이템의 전체 이동 경로를 무한히 보관하지 않는다. 긴 기간이 필요한 소비처 실수요·송전 출처 업적은 필요한 누적 집계를 별도로 정의한다. 거점 집계는 매초, UI 수치 갱신은 최대 250ms 간격으로 묶고 전체 DOM을 매 프레임 재작성하지 않는다.

1. 먼저 생산·운송·전력의 공통 계측과 명칭·단위·거점 ID를 연결한다.
2. 목표 고정 ID·선행 가지·기존 저장 보존과 알림을 만든다. 연구·건설 비용은 세계의 경제 프로필을 사용하며 기존 저장의 가격을 전역으로 덮어쓰지 않는다.
3. 지역 표와 선택 상세를 만들고 부족 재료 → 공급 거점 이동을 연결한다.
4. 실제 도로·송전·충전 대기의 보기와 노선 계획 설정을 연결한다.
5. 업적·도전·숨김·공개 완료율을 연결하고 정보 밀도·배율·성능을 다듬는다.

화면 기획을 마지막에 붙이는 방식 대신 각 산업의 계측·목표·상세를 함께 만든다. 실제 수정 대상은 `src/ui/ui.ts`, `src/ui/guide.ts`, `src/ui/minimap.ts`, `src/style.css`, `index.html`과 신규 운영·업적 UI 모듈이지만 이번 작업에서는 해당 게임 파일을 수정하지 않는다.

## 12. 화면 검증 시나리오

H의 모터 부족 → R07의 공급량 → C의 생산·전력으로 세 번 이내 이동할 수 있는지 확인한다. C에 문제가 있어도 다른 거점의 정상 상태를 잃지 않아야 한다. 배송·발전 용량만 보고 실제 공급이 정상이라고 표시하지 않는다.

빈 공장·첫 측정·지연 배송·목표 재고 충족·망 분리/발전 부족·야간 방전·삭제된 공급지·예전 저장을 각각 확인한다. 목표·업적·설정 창을 연 상태의 입력 충돌과 키보드 복귀, 125%·150% 배율·좁은 창에서 겹침·가려짐을 확인한다. 설계 예시의 클릭 동작을 확인한 것과 실제 시뮬레이션 연동 검증을 구분한다.

연구 완료 시 연구당 소리·카드가 한 번인지, 화면 밖 허브에서도 완료를 알 수 있는지, X·Esc·자동 닫기·해금 보기가 동작하는지 확인한다. 로드·중간 참가·중복 명령에서 과거 카드가 다시 뜨지 않고 효과 줄이기에서도 내용은 읽을 수 있어야 한다. 차량 묶음 표시를 바꿔도 실제 노선·설정·화물이 바뀌지 않으며, 차량 추가에 필요한 기존 비용/현지 조립품은 정상 차감돼야 한다.

앞선 독립 운영 화면 예시에서는 H의 부족 재료 → C 생산 → C 전력 이동, 다른 거점의 운송 노선 선택, 목표 장 전환, 업적 탭과 숨은 힌트 표시를 브라우저에서 확인했다. 320px에서 가로 넘침이 없었고 1024px의 관계도에서 8거점 표시가 겹치지 않았다. 예시는 약 700KB이며 게임 계측·저장·멀티플레이에는 연결하지 않았다. 실제 게임의 키보드·배율·성능 검증은 남아 있다.

앞선 독립 예시는 같은 공장 지도를 기본·전력·운송·자원·날씨 보기로 바꾸고 선택 거점의 상세를 갱신한다. 전력·날씨·자원·운송 전환, 눈밭 예보, 허브 위치 이동, 레시피 펼침을 브라우저에서 확인했다. 320px에서 가로 넘침이 없었고 목표 영역에 전력 확인 버튼이 없음을 확인했다. 납품 완료 12개·조립 재고 6개·운송 중 4개는 고정된 설명용 상태다. 이번 확인은 화면 예시에 한하며 실제 게임 오버레이·허브 납품은 아직 구현하지 않았다. 당시 예시의 미래 날씨·카운트다운은 현재 기획에서 폐기됐으며 화면의 현재 날씨 표시와 혼동하지 않는다.
