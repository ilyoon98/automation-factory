# 코드로 진행한 초반 생산과 운송 검토

2026-10-30 · 사용자가 컴퓨터 유즈를 제외하도록 요청한 뒤 게임 명령과 시뮬레이션 틱만 사용했다.

후속 사용자 요청으로 아래에서 발견한 첫 목표·정류장 지도 보기·출발지 품목 우선 표시를 구현했다. MG01은 철판 실제 반입도 인정하며, 검토 스크립트는 원광 반입 없는 제련 직행에서 첫 목표 완료를 요구하도록 바꿨다. 최신 전체 단위 테스트는 325개 통과다. 아래 최초 관찰의 MG01 미완료와 세 가지 개선 후보는 이전 상태의 기록이며 현재 남은 과제로 해석하지 않는다. 세부는 [후속 운송 구현](운송-선택-정보정리-구현-2026-10-30.md)을 따른다.

## 확인 방법과 범위

`node scripts/playtest-simulation.mjs`로 다시 실행할 수 있다. 실제 `World`, 지도 생성, 건설/설정/연구/노선 명령과 틱을 사용한다. 브라우저·Electron 조작이나 컴퓨터 유즈를 사용하지 않는다. 결과는 무시되는 `artifacts/playtest-simulation/results.json`에 기록한다.

초반은 회전·반전 8종을 대표하는 새 지도 8개에서 기본 시작 재료만 사용한다. 재고·연구·목표 완료·전력은 무료 지급하지 않는다. 운송 6상황은 별도의 준비된 공장에서 연구와 초기 건설 재료·화물을 제공한 뒤 실행한다. 전체 후반 완주·첫 트럭 연구까지의 실제 경제·조작 난도·화면 가독성·음향을 검증한 결과는 아니다.

## 결과

| 경우 | 결과 |
| --- | --- |
| 시드 1/1010/3028/4037/5046/6055/7064/8073 | 철광석 반입 → 철판 → 유료 조립 자동화 연구 → 기어 20개 → 유료 풍력 연구/건설 → MG04와 첫 지역 공개까지 모두 진행 |
| 일반 배송 | 철판 50개 실제 배송 |
| 도로 단절/복구 | 단절 중 배송 0·길 없음, 선택 목록에서 목적지 제외. 연결 복구 뒤 배송 재개 |
| 목적지 가득 참/공간 회복 | 실제 용량 200개를 채우면 하역 대기·화물 보존. 준비 시나리오에서 공간을 비운 뒤 하역 재개 |
| 소량 다품목 계획 | 철판 7개+구리판 5개를 모두 실제 배송 |
| 정류장 종류와 노선 행동 다름 | 정류장은 싣기여도 노선에서 내리기를 설정하면 배송 가능. 두 설정의 의미를 사용자가 구분해야 함 |
| 물만 지정 운송 | 물 12개 배송, 출발지에 섞여 있던 철광석 5개는 그대로 유지 |

새 지도 8개에서 기어 20개까지 게임 시간 약 5분 40~44초, 첫 지역 공개까지 약 6분 21~25초였다. 설계·배치·입력의 사람 시간을 제외한 자동 구성 사례이므로 권장 플레이 시간이나 초보자 소요 시간으로 사용하지 않는다. 첫 지역 공개는 철판 공장·자체 발전 두 과제로 달성했다.

## 발견하여 바로 수정한 표시 문제

- 일반 노선의 품목 선택에서 물만 제외되어 있었다. 실제 물 운송을 지원하므로 전체 품목에 포함했다. 준비된 운송 시뮬레이션으로 물 지정 배송과 다른 화물 비혼입을 확인했다.
- 미공개 셀 건설 실패 안내가 메인 목표를 달성하라고 알려 주었다. 최신 지도 규칙인 지역 과제 셋 중 둘로 수정했다. 실제 공개 판정과 저장 규칙은 유지했다.

## 다음 개선 우선순위

1. **첫 목표와 제련 자동화가 어긋나는 경우.** 별도 새 지도에서 채굴기 → 제련로 → 허브로 바로 연결해 철판 120개를 실제 반입했지만 MG01은 완료되지 않았다. MG01은 철광석 원광을 따로 허브에 10개 넣어야 하기 때문이다. 공장은 정상 작동해도 메인 목표는 처음에 남는다. 첫 목표를 '첫 생산물 반입'으로 넓히거나, 원광 직접 반입을 먼저 요구하는 이유와 순서를 더 명확히 안내하는 선택이 필요하다. 목표 판정은 이번에 변경하지 않았다.
2. **정류장 번호만 보고 위치를 찾기 어렵다.** 각 노선 행에 기존 카메라 이동을 연결한 '지도에서 보기'를 제공하면 목적지를 확인하기 쉽다. 노선을 자동 변경하지 않는다.
3. **품목 선택이 길다.** 55품목을 한 목록에서 찾는 대신 출발지에 있는 품목을 먼저 보여 주고 전체 목록을 별도로 펼치는 표현을 검토한다. 빈 재고 때문에 미리 설정한 품목을 숨기거나 자동으로 다른 품목을 고르면 안 된다.
4. **같은 싣기/내리기 용어가 두 곳에 있다.** 정류장의 벨트 입출력 역할과 트럭이 그곳에서 할 일을 화면에서 구분하고 기본 왕복 노선은 출발/도착 중심으로 표현한다. 기존 다중 정류장·혼합 운송은 상세 설정에서 유지한다.

이 항목은 구현할 후보이며 첫 목표 변경·정류장 위치 버튼·품목 목록 재구성·운송 방식 변경을 이번 검사로 완료했다고 보고하지 않는다.

## 회귀 검증

위 자동 진행과 별도로 타입 검사를 포함한 `npm run build`와 단위 테스트 319개가 통과했다. 기존 성능 시험 1개는 기본 실행에서 건너뛴다. 기존 UI 검증 스크립트는 이번 사용자 요청 이후 실행하지 않았다. 컴퓨터 유즈 중단 전에 본 초기 도움말은 내용이 길었으며, 도움말과 최종 목표의 옛 표현 점검도 후속 후보로 남긴다. 배포는 실행하지 않았다.
