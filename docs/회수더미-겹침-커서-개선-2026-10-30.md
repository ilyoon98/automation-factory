# 겹친 바닥 회수 더미와 커서 개선

2026-10-30 · regional-d09 작업본 · 배포 전

사용자가 지적한 대상은 컨베이어 화물이 아니라 컨베이어와 같은 칸에 놓인 바닥 회수 더미다. 기존 Input은 건물·차량이 없는 칸에서만 더미 클릭을 처리해 겹친 더미를 누르면 컨베이어가 선택됐다.

빈손으로 해당 칸을 클릭하면 더미를 먼저 회수한다. 기존 `pile-collect` 명령과 명령 중복 방지·가까운 창고/정류장 우선·남은 물량 허브 보관을 사용한다. 컨베이어·운반 화물·새 생산/배송 실적은 보존한다. 회수 후에는 같은 칸의 설비를 선택한다. 더미가 이미 회수됐다면 실패 안내를 내고 밑의 설비를 대신 누르지 않는다.

마우스를 누를 때 회수 칸을 기억하고, 이동 거리가 드래그 기준을 넘으면 화면 이동으로 처리해 수거하지 않는다. Ctrl/Shift/Alt 및 건설·청사진·철거 등 기존 조작이 우선한다. 별도 컨베이어 화물 회수 명령이나 E 단축키는 추가하지 않았다.

입력 판정·커서·대상 테두리·툴팁이 `pointerFeedback`을 공유한다. 건설은 망치, 철거는 빨간 표시, 회수는 손, 선택은 포인터, 이동 중은 쥔 손, 불가는 금지 커서다. 더미 상자의 그림 위치와 초록 테두리는 `PILE_MARKER`를 공유한다. 실제 품목 아이콘·수량·바닥 물건 클릭 안내를 표시하고 회수 중에는 밑의 설비/광맥 안내를 생략한다. 공개되지 않은 지도 정보는 노출하지 않는다.

건설 미리보기는 연구·재료·벨트 교체 환급과 드래그 제한을 반영한다. 줌·카메라 이동 후에도 화면의 마우스 위치로 칸을 다시 계산한다. 포커스 상실 시 편집 조작을 마감하고 영역 표시를 지운다. 이전 탭 순서 변경에 맞춰 지하 컨베이어 안내 번호도 물류 2로 수정했다.

변경 파일: `src/input/input.ts`, `src/input/pointer.ts`, `src/render/renderer.ts`, `src/render/pile-marker.ts`, `src/ui/ui.ts`, `src/ui/cursors/*.svg`, `src/style.css`, `index.html`. 루트 운영 UI·물류 회수·계획서도 동기화했다.

검증: `npm run build` 성공, 전체 테스트 350개 통과·기존 성능 테스트 1개 제외. 추가 9개는 겹친 벨트/큰 설비/0번 칸, 더미·운반 화물 분리, 수량·실적 보존, 드래그/조합키, 이미 회수된 대상, 실제 배치 가능 여부, 커서 상태·포커스 상실·줌을 확인한다. 브라우저 없이 이벤트 리스너와 실제 Input/World/명령 경로를 실행했다. 컴퓨터 유즈·실제 화면 재생 확인은 하지 않았다. 빌드의 JS 500kB 크기 안내가 남아 있으며 빌드 실패는 없다.
